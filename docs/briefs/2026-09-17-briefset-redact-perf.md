# Brief Set: Reduce redaction overhead with shared analysis, caching, and parallel preparation

## Purpose
- Plan executable performance work for `codemap-search` after commit `e5fc44172faaa87a8e0fd358d160bfe881d5e47b`, keeping the existing redaction coverage and public contracts intact.
- Combine the recommended removal of duplicate scans/parses and completed-result caching with the user's requested overlap between redaction and symbol preparation. These are runtime performance changes, not parallel client requests or parallel agent assignments.
- Decision recorded on 2026-09-17: no fixed millisecond SLO. Compare the same three conditions, demonstrate repeated-request improvement, and disclose first-request, post-edit, initial-index, and resource regressions separately.
- Historical evidence is preserved at `docs/briefs/evidence/redact-perf/baseline-e5fc441.json`. The executable benchmark was temporary, so Child 01 creates a durable reproduction route before optimization.
- Authoring produces this parent and five child briefs only; unchecked boxes represent future implementation work. The accompanying JSON is captured historical evidence, not new execution proof.
- BDR-1: Benchmark fixture/harness work has a distinct test-only outcome. Keep its generator, assertions, and timing contract together because an independently changing fixture invalidates the performance handoff.
- BDR-2: Shared analysis spans many consumers (B1/B3). Keep the policy/API and all affected consumer migrations atomic (K1); splitting them would permit a detached masking path or incompatible source identity.
- BDR-3: Cache identity, publication, failure cleanup, and eviction span positive/negative paths (B1/B2). Keep them together as one correctness boundary (K2); an incomplete cache can publish a false clean result.
- BDR-4: Scheduling, fork/join, budgets, failure, and shutdown span execution paths (B1/B2). Keep them together as one lifecycle boundary (K2); scheduling alone is not safe parallel behavior.
- BDR-5: Final integration owns cross-child proof and maintenance documentation. Production fixes return to their owning performance child; this remains a test work type rather than a second implementation stream.

## Shared Constraints
- Preserve MCP-only masking: ordinary `parse` CLI output, source files, persisted indexes, matching, ranking, counts, and public JSON-RPC schemas retain their current contracts.
- Preserve `[tool_output].is_redact_enabled`, the three `[redact]` lists, repo/global/default precedence, exact rule/value exceptions, and request-pinned configuration. Add no user-facing configuration keys or schema migration for this work.
- Add no redaction byte, candidate-count, or time scan limits. Retain `parser::parse_source`'s existing 5000ms deadline, existing tool input/output limits, and complete text fallback. Cache eviction or worker saturation must never mean skipped inspection.
- Detect against the complete original presentation source before clipping, escaping, or truncation. Preserve UTF-8 byte coordinates, BOM/CRLF handling, multiline values, PEM interiors, and conservative changed/unavailable-source behavior.
- Keep the final JSON-RPC response guard, contextual named-string handling, and existing treatment of parent objects, arrays, numeric values, and booleans. Never release an uninspected response while work is pending.
- Use only synthetic credentials in fixtures and measurement output. Do not log source text, secret values, exception values, or credential-bearing query strings in profiling records.
- Repository instructions, the stable CLI/MCP tool contract, and existing caller selections apply to every child. Use `codemap-search` for suitable code exploration and run commands from the repository root unless a handoff explicitly states otherwise.
- Use release binaries, identical fixtures, independent config homes, serial JSON-RPC requests, two warm-ups, and 21 measured calls per primary cell. The baseline is redaction off with secrets, compared with on with secrets and on without secrets.
- Preserve captured raw evidence. Give each revision/phase/cache-state/serial-or-parallel comparison a distinct result path, including repeated original-revision runs; never reuse `baseline-current.json` as an optimization output. Record both absolute latency and the enabled-minus-off delta for each revision.
- Do not claim source-only repeated-request gains prove symbol parallelism. Distinguish shared-work reduction, positive/negative cache reuse, and same-state CPU overlap using the separate rich/cold/phase populations.
- Runtime CPU parallelism is required for eligible symbol/callable preparation, with bounded admission and safe inline fallback. The children themselves execute in serial waves to preserve shared interfaces and comparable measurements.
- SourceResolver/request guards remain on their owner thread. Workers receive explicit immutable policy and compatible original source identity; filtered/composite/native-expanded sources remain distinct. Output-budget allocation uses actual joined results.
- Index-time prewarming is a bounded adopt-or-defer decision inside Child 04. It is optional only if provenance is incompatible or measured cold-start/resource cost is unhelpful; record the evidence. It never replaces live misses or the requested request-path overlap.
- No additional user decision is needed before the planned work. Bounded private API, retention, executor, and dispatch choices belong to workers and must be documented in handoffs. Material public behavior changes or unresolved measured regressions return to the parent before being accepted.
- User-authorized test additions are in scope. Unrelated failures/features, new scan limits, broad object propagation, new token catalogs, public tuning flags, and arbitrary refactors remain out of scope.
- Keep commits cohesive and consistent with recent Conventional Commits history; use `test(codemap-search): ...` for test-only work and `perf(codemap-search): ...` for runtime optimization, with Korean subject text. Do not split the atomic shared-analysis consumer migration into a temporarily unsafe state. This authoring task does not create implementation commits.
