# 05. 코드베이스 근거와 관련어 맞춤

## 현재 상태

2026-10-17 기준으로 기능 구현, 호스트 자동 검증, Docker의 12개 저장소·36개 근거 범위·3개 적용 모드 평가와 브랜치 전환 검증을 마쳤다. 최종 Docker 실행은 종료 코드 0이었다. 제품은 심볼 근거로 순서를 조정하며, 뜻 제거는 끈 상태다. 기대 분야의 추가 손실은 없었지만, 교차 저장소 대조에서 기대 분야 적중 차이는 확인하지 못했다. 독립 제거 판정은 보류 상태이므로 제거 품질까지 통과한 것은 아니다.

사용자는 기능 구현을 모두 마친 뒤 Docker 안에서 문서의 12개 저장소를 새로 clone·index하고 평가하도록 정했다. 하위 에이전트는 사용하지 않는다. 릴리스 게시, 모델 도구 평가, 제거 표본의 독립 판정은 보류한다.

## 구현과 동작 경계

- `src/related_terms/evidence.rs`는 사전의 단어 키와 분야 대응을 읽고, 인덱스가 공개한 파일에서 근거를 계산한다. 원본과 준비된 데이터셋에는 근거를 쓰지 않는다.
- 심볼 이름을 기존 `split_identifier()`로 나누고 연속 1~4개 토큰을 조합한다. 사전에 있는 키만 파일 수와 출현 수로 센다. 평가용 범위는 심볼, 심볼+문서 주석, 심볼+문서 주석+문자열의 세 가지다.
- 파일별 근거 입력의 지문을 보관한다. 새 스냅샷에서는 바뀐 파일의 기여만 빼고 더하며, 사라진 파일의 기여도 뺀다. 메모리 저장소를 사용한다. 초기 근거 계산의 관찰 예산은 1,000ms로 두며, 이는 MCP 응답 제한이나 사용자가 승인한 제거 기준이 아니다. 제품 범위가 이를 넘으면 최종 완료 전에 관련 경로를 보완하고 다시 측정한다.
- `src/index/indexer.rs`의 `SnapshotSource`는 최신 공개 스냅샷 하나를 전달한다. 데이터셋 준비가 첫 인덱스 공개보다 늦어도 최신 스냅샷부터 계산한다. 계산 중 더 새 세대가 공개되면 오래된 결과를 적용하지 않는다.
- `src/related_terms/runtime.rs`는 내려받기·준비·첫 조회·사전 근거 로딩을 MCP 요청 루프 밖에서 수행한다. 근거 계산도 별도 OS 스레드에서 수행한다. 준비 중에는 사전 결과를 그대로 반환하고 근거 준비 상태를 표시한다.
- `synonyms`는 기존 `ensure_alive()`와 `trigger_refresh()`를 사용한다. 감시기가 꺼졌거나 실패한 경우에도 요청 기반 갱신을 따른다. 인덱서가 교체되면 새 스냅샷 공급원을 사용한다.
- `src/related_terms/lookup.rs`는 뜻별 전체 단어와 표시용 중복 제거 결과를 따로 보존한다. `overlay.rs`가 전체 단어로 판단한 뒤 표시 그룹을 다시 구성한다.
- 입력이 코드에 없거나 지원되는 뜻이 하나도 없으면 거르지 않는다. 기본 동작은 지원되는 뜻과 실제 코드의 단어를 앞세우는 것이다. 뜻·분야 제거는 평가 빌드의 제거 모드에서만 측정한다. 기존 6개 뜻·그룹별 단어 상한과 생략 개수 표시는 유지한다.
- 기능이 꺼지면 사전·근거 준비와 근거 스레드를 시작하지 않는다. `search` 순위와 Tantivy 스키마는 바꾸지 않았다.

## 평가 전용 경로

일반 빌드에서는 `SHOULD_REMOVE_UNSUPPORTED_SENSES = false`다. `related-terms-eval`은 기본 Cargo 기능이 아니며, 평가 이미지에서만 켠다.

| 항목 | 계약 |
| --- | --- |
| 비공개 JSON-RPC 메서드 | `related_terms/evaluate` |
| `scope` | `symbols`, `docstrings`, `literals` |
| `mode` | `off`, `demote`, `remove` |
| 응답 측정값 | `_meta.related_terms_eval`에 인덱스·근거 세대, 상한 전 결과, 적용 판단을 담는다 |
| 근거 원자료 | `CODEMAP_RELATED_TERMS_EVAL_REPORT`의 파일에 원자적으로 저장한다 |
| 공개 도구 계약 | `synonyms`의 입력은 그대로 `terms` 하나다. 새 설정 키나 공개 도구 인자는 추가하지 않았다 |

`overlay_eval.py`는 모델을 실행하지 않는다. 240개 입력 중 기대 분야가 있는 224개를 적중 계산에 사용한다. 상한 전후 적중, 코드에서 찾히는 단어 비율, 출력 크기, 교차 저장소 대조를 기록한다. 제거 표본은 분야와 입력 그룹으로 층화해 저장소·근거 범위마다 최대 20개를 뽑는다. 표본이 적으면 전부 뽑는다. 판정이 없으므로 오제거율과 상한은 미평가로 남긴다.

평가기는 초기 인덱스와 최신 근거가 준비되기 전 결과를 측정값으로 받아들이지 않는다. 시간 초과는 실패로 기록한다. MCP 종료가 지연되면 자신이 시작한 서버만 종료하여 다음 저장소에 영향을 남기지 않는다. 브랜치 검증은 별도 Express 클론과 독립적인 새 인덱스를 사용하고, 감시 갱신이 새 계산 결과와 완전히 같아질 때까지 확인한다.

패키지 목록 검사는 미커밋 변경 때문에 기본 명령이 중단되어 `--allow-dirty`로 현재 작업 트리를 확인했다. 패키지를 게시하거나 커밋한 것은 아니다. 마지막 무결성 검사에서 원본 해시, 보호된 네 PoC 파일과 추적 데이터셋, 호스트의 기존 12개 체크아웃에 변경이 없었다. Docker에 사용한 코드·쿼리·평가 입력의 지문도 그대로였다. 결과는 `/Users/buyong/tmp/rterms-05-docker-pSpnS6/final-integrity.json`에 있다.

평가 시작 전 확인한 환경은 Docker Desktop 29.2.1, Linux ARM64, 데몬 CPU 14개, 메모리 8,216,498,176바이트다. 실행 컨테이너에는 CPU 4개와 메모리 6GiB를 할당한다. 기본 이벤트 탐색은 켜 둔다. 준비 대기는 저장소마다 최대 3,600초로 제한한다. 이미지 식별값·컴파일러·바이너리 해시·데이터셋 해시·실제 컨테이너 설정은 실행 원자료에 기록한다.

### 자동 측정 요약

전체 입력은 범위마다 240개이며, 적중 계산은 기대 분야가 있는 224개에 한정한다. 표의 세 값은 모두 **끔 / 순서 조정 / 제거** 순서다. 찾힘 비율은 실제 응답에 나온 단어 중 해당 범위의 코드 근거에 있는 단어 비율이다. 범위마다 찾힘의 정의가 다르므로 행 사이 비율만으로 품질 우위를 판단하지 않는다.

### 교차 저장소 대조

입력이 두 저장소에 모두 있고 예외 없이 맞춤이 적용된 경우만 비교했다. 저장소 이름 정렬에서 다음 저장소를 대조군으로 사용했다.

### 브랜치 전환

별도 Express 클론에서 `v5.2.1`(`dbac741a49a5a64336b70c06e85c2e2706e36336`)과 `4.21.2`(`1faf228935aa0a13111f92c28ee795be64ce3f0f`)를 비교했다. 근거 키는 474개에서 502개로 달라졌고, 바뀐 파일 53개와 삭제된 파일 3개의 기여가 반영됐다. 전환 뒤 증분 결과는 새 인덱스의 단어별 파일 수·출현 수·분야 집계·파일 수와 완전히 같았다.

초기 실행에서는 존재하지 않는 `v4.21.2`를 요청해 이 단계만 실패했다. 실제 태그와 커밋을 확인해 수정한 뒤 전체 측정을 재실행했고 종료 코드 0을 확인했다. 처음과 마지막 실행의 Rust 바이너리는 같았으며, 36개 조합의 단어 근거·분야 집계·파일 수에도 차이가 없었다. 최초 결과를 삭제하거나 최초 실행을 성공으로 바꾸지 않았다.

## 호스트 예비 실행과 한계

Express 예비 실행은 161개 파일에서 세 근거 범위 모두 상한 후 적중이 끔·뒤로 보내기·제거 각각 18/18/18이었다. 기대 분야가 있는 입력은 19개였다. 근거 계산 시간은 심볼 4.8ms, 문서 주석 포함 4.3ms, 문자열 포함 23.5ms였고, 인덱스 작업은 209.8ms였다. 이후 표본 추출과 실행기가 바뀌었으므로 본 평가 보고서로 재사용하지 않는다.

호스트의 첫 다중 저장소 실행은 Bitwarden에서 900초 안에 끝나지 않았다. stderr의 84바이트 준비 응답은 17회였고, 이후 1,315바이트 응답 15,581회는 사전 조회 결과와 근거 준비 상태였다. 데이터셋 준비가 900초 계속된 것은 아니다. 저장된 인덱스로 짧게 재현했을 때 사전 응답은 약 1초에 나왔으며, 스레드 표본에서는 기존 `Source routes` 타입 분석이 인덱스 스냅샷 공개 전에 실행 중이었다. 근거 스레드는 공개를 기다리고 있었다. 이 기존 분석 코드는 수정하지 않았고, 이벤트 탐색을 꺼서 평가 조건을 바꾸지도 않았다.

## 보류된 승인과 제품 기본값

모델 도구 평가와 독립 제거 판정은 사용자 요청으로 보류한다. 따라서 잘못 제거한 비율과 최종 제거 기준은 확정하지 않았다. 제품 기본값은 심볼 근거와 순서 조정이며, 뜻 제거는 계속 `false`다. 릴리스·태그는 게시하지 않았다.
