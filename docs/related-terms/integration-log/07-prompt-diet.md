# 07 — synonyms 프롬프트 축약과 입력 선별 재검증

`o200k_base` 기준 관련 안내문 합계를 **476 → 333토큰(-30.04%)**으로 줄인 수정안을 채택했다. Luna의 고정된 6개 과제에서 실제 `terms`가 기대 배열과 모두 일치했다. 이는 이 과제들의 입력 선별 결과이며, 전체 검색·추천 품질이나 모든 새 식별자에 대한 보장은 아니다.

최종 재검증 로그 날짜는 2026-10-18(UTC)이다. 메인 에이전트가 구현·기록 대조·채택 판정을 맡았고, `openai-codex/gpt-6-luna`의 `medium` 설정으로 독립 세션을 실행했다.

## 승인 범위와 진행 순서

1. 사용자는 관련어 작업만 먼저 커밋하고, 검증된 축약안을 별도 커밋하도록 승인했다. 선행 사용자 변경인 루트 `AGENTS.md`, `package.json`, `bun.lock`, `docs/related-terms/README.md`와 데이터셋·캐시는 제외했다.
2. 체크포인트 `b96bb5b`에 관련 작업 60개 파일을 반영했다. 첫 시도는 기존 서식·Clippy 훅에서 실패했다. 경고 억제 없이 발행 조건을 호출자에서 결합하고 준비 완료 메시지의 큰 값을 `Box`로 전달하도록 정리했다. 서식 변경도 커밋 대상 안에 한정했다.
3. 최초 축약안을 안내문 248토큰까지 줄였다. 승인된 Luna 8세션은 새 2과제의 축약 전 실행과 6과제의 축약 후 실행으로 구성했다. 기존 4과제의 축약 전 결과는 앞선 기록을 재사용했다.
4. 최초 축약안은 입력 선별 기준을 충족하지 못했다. 실패 기록을 보존하고 원문과 일반 바이너리를 복원했으며, 축약안을 커밋하지 않았다.
5. 사용자가 추가 6세션을 승인했다. 필수 입력 목록과 역할어 제외·대상 단어 한정·단어 형태 보존·복합 연산어 구분을 명시한 수정안으로 같은 과제를 재실행했다. 기대값과 과제 문구는 바꾸지 않았다.

## 버전별 관측 결과

정확 일치는 최종 답변이 아니라 실행된 `synonyms`의 `terms` 배열로 판정했다.

| 버전 | 안내문 합계(토큰) | 고정 6과제의 정확 일치 | 처리 |
| --- | ---: | ---: | --- |
| 축약 전 | 476 | 5/6 | 기존 4건 재사용 + 새 2건 관측 |
| 최초 축약안 | 248 | 1/6 | 불합격으로 보존하고 복원 |
| 수정안 | 333 | 6/6 | 이번 입력 선별 범위에서 채택 |

축약 전부터 새 테스트 이름의 `orders`를 `order`로 바꾸는 문제가 있었다. 이를 축약 때문에 생긴 변화로 계산하지 않았다. 최초 축약안에서는 여기에 `get` 누락이 추가됐고, 결제 예시에 `method`·`source`를 다시 넣거나 요청문의 `distinguish`, `side`, `grep`을 입력하는 퇴행도 관측했다.

수정안은 필수 예시를 정확한 입력 목록으로 명시했다. 대상 이름 밖의 지시문·참조 코드 단어를 추가하지 않게 했고, 단수화와 서로 다른 연산 단위의 병합을 금지했다. 역할어는 문맥에 따라 제외하도록 유지했다. 이번 축약에서 정규화·분리·사전 조회·응답 표시 로직은 변경하지 않았다.

## 채택한 안내문의 토큰 측정

실제 MCP에서 받은 문자열을 `tiktoken 0.12.0`의 `o200k_base`로 측정했다. 아래 합계는 각 안내문을 한 번씩 센 값이다. Luna의 정확한 토크나이저, 세션 전체 입력 토큰, 도구 응답 토큰 또는 과금액을 측정한 값은 아니다.

| 안내문 | 축약 전(토큰) | 수정안(토큰) |
| --- | ---: | ---: |
| 도구 설명 본문 | 361 | 274 |
| `terms` 인자 설명 | 49 | 34 |
| 공통 초기 안내 | 66 | 25 |
| 합계 | 476 | 333 |

공개 MCP 도구 정의를 간결한 JSON으로 직렬화한 참고 측정은 518 → 418토큰이다. 이는 제공자별 도구 직렬화 형식과 같다고 보장하지 않는다. 도구 응답 본문을 압축한 작업도 아니다.

변경한 안내문은 다음 세 곳이다.

## 검증과 해석의 경계

- 체크포인트의 기본 관련어 20건, 평가 기능 관련어 20건, 새로고침 10건이 통과했다. 기존 커밋 훅의 서식·Clippy 검사도 통과했다.
- 수정안은 `cargo check`와 일반 바이너리 빌드가 통과했다. 실제 MCP 및 Pi 연결에서 새 설명의 노출을 확인했다. 안내문 이외의 공개 도구 계약은 같았으며, 입력은 계속 `terms`만 허용하는 1–16개 문자열이다. 새 길이 제한은 추가하지 않았다.
- 과제에는 정답 배열이나 분해 지시를 넣지 않았지만, 도구 설명에는 첫 세 가지 필수 예시가 들어 있다. 수정안은 앞선 실패를 보고 조정했으므로 동일 과제 재검증을 독립적인 일반화 점수로 해석하지 않는다.
- 도구 사용을 과제에서 명시적으로 요청했다. 자발적인 도구 선택률, 최종 추천어의 정확도, 실제 저장소 검색 성과는 평가하지 않았다. 저장소 체크아웃 없이 제공한 이름·발췌문만 문맥으로 사용했다.
- 수정안의 6회 호출은 모두 사전 준비가 끝난 응답을 받았다. 준비 중 재시도 동작을 이번 6회에서 검증한 것은 아니다.
- 검증한 소스·바이너리와 커밋할 소스의 일치를 확인했다. 보호한 사용자 파일·PoC 파일과 원본 데이터셋은 유지했다. 기존 실행 중인 MCP가 갱신된 것은 아니며, 적용하려면 새 바이너리로 다시 시작해야 한다.
- 이전 `luna-replay.html`은 과거 관측 기록으로 남겼다. 이번 실행 결과로 덮어쓰지 않았다. 푸시·릴리스 게시는 이 작업에 포함하지 않는다.
