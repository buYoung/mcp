# 실사용 후속 개선과 Pi 리플레이

## 범위와 결정

Astra 검토에서 확인한 도구 설명·표시 품질·테스트 서버 종료 문제를 개선하고, 기존 Luna 관측을 오프라인 HTML로 재구성했다. 구현은 직접 수행했다.

- 입력 길이 제한은 사용자의 결정에 따라 추가하지 않았다. 기존 `terms` 1–16개 계약을 유지했다.
- 필요한 회귀 사례만 기존 e2e에 추가했다. 새 테스트 환경이나 외부 의존성은 추가하지 않았다.
- 추가 Luna 관측은 실행하지 않았다. 뜻 제거의 제품 기본값은 비활성 상태로 유지했다.
- 조회 원본·정규화·데이터셋과 보호된 PoC 파일은 변경하지 않았다.

## 제품 변경

`src/tools/instructions/tools/synonyms.md`에 입력은 `terms`만 받는다고 명시하고 최소 JSON 예시를 추가했다. `field`, `fields`, `topic`은 입력 필터가 아니라 응답에서 선택하는 분류임을 구분했다.

새 `src/tools/synonyms/presentation.rs`는 MCP 표시만 담당한다.

1. 같은 근거 우선순위 안에서 분야·주제 ID가 같은 뜻을 묶는다. 입력 부분의 출처를 유지한다.
2. 입력 부분별로 표시 순서를 나누되, 코드 근거가 있는 뜻의 우선순위를 보존한다. 표시 상한은 6개 그룹이다.
3. 선택된 그룹의 전체 membership에서 표시 단어를 다시 만들므로 숨겨진 그룹이 단어를 먼저 차지하지 않는다. 직접·가까운 말·같은 주제의 기존 우선순위와 20/10/10 상한은 유지한다.
4. 빈 비지원 그룹은 표시 예산에서 제외한다. 근거가 있는 그룹의 단어가 다른 그룹과 겹치면 근거 분류를 버리지 않고 공유 안내를 붙인다.
5. 조회 시도 진단 목록은 8개까지 표시하고 생략 수를 알린다. 실제 해석 결과는 유지한다.

사전 준비와 코드베이스 근거 준비 상태는 입력 헤더 바로 뒤, 단어 목록 앞에 표시한다. 기존 소비자가 사용하는 첫 `##` 헤더는 유지한다. 조회 캐시의 전체 뜻·단어 membership과 평가 JSON 계약은 바꾸지 않았다.

`tests/e2e/related_terms_fetch.rs`의 공통 fixture는 nonblocking accept/read/write에 취소 신호와 전체 30초 기한을 적용한다. 클라이언트가 접속 전에 실패해도 fixture를 취소하고 join한다. fixture 오류에는 먼저 확보한 클라이언트 결과를 함께 표시한다. 최초 관측 당시 클라이언트가 접속하지 못한 원인 자체를 규명한 것은 아니다.

## HTML 리플레이

결과물은 [luna-replay.html](../luna-replay.html)이다. 파일 하나에 CSS·JavaScript·가시 로그 데이터가 들어 있어 외부 서버 없이 열 수 있다.

사용자가 제공한 [CineScript 예시](https://arnehilmann.github.io/cinescript/cinescript-template.html)의 기록 간격 재생·일시정지·처음부터·빠르게 넘기기 개념을 참고했다. 해당 라이브러리 코드를 복사하거나 jQuery·term.js를 추가하지 않고 직접 구현했다. 원본 페이지의 HTML·스크립트로 기능을 확인했으며 브라우저 화면을 직접 관찰한 것은 아니다.

### 재생 기능

- 과제 선택, 재생/일시정지, 이전/다음 단계, 처음/끝, 탐색 막대와 배속을 제공한다.
- 2초를 넘는 기록 공백을 축약할 수 있다. 끄면 원래 이벤트 간격을 사용한다.
- Pi 스타일의 요청·공개 답변·도구 인자·실제 실행·모델에 전달된 결과를 시간 순서대로 표시한다.
- 호출 제안, 실제 실행, 클라이언트 거절, 감독자 답신, 미완성 제안과 시간 초과를 구분한다.
- 모델에게 전달된 결과가 이미 잘렸다면 그 사실을 표시한다. 없던 출력을 복원하지 않는다.
- 상세 결과를 펼칠 수 있으며 키보드와 작은 화면용 레이아웃을 제공한다.

리플레이는 **개선 전 관측**이다. 이번 구현의 효과를 새로 측정한 Luna 실행이나 원래 Pi 화면 녹화가 아니다. 토큰 스트림·추론·미관측 동작을 생성하지 않는다. 비정상 추가 속성에 섞인 내부 서술과 제어 토큰은 인자 장면과 오류 장면에서 숨기고 표시를 붙였다. 원본 로그는 수정하지 않았다.

### 검증 중 발견해 바로잡은 사항

- 첫 e2e는 19개 통과·1개 실패였다. 새 근거 우선순위 fixture에 전체 입력 키가 없어 근거 적용 조건에 도달하지 못했다. 분류되지 않은 키를 테스트 사전에 추가했으며 제품의 입력 존재 조건은 완화하지 않았다.
- 첫 출력 비교는 성공 응답 앞에 붙인 상태 헤더 때문에 기존 클라이언트의 준비 완료 인식에서 시간 초과됐다. 클라이언트를 바꾸지 않고 첫 `##` 헤더를 유지하도록 수정했다. 실패 자료는 `cap-eval-attempt-1/`에 보존했다.
- 첫 DOM 모형 검사에서는 일시정지 처리 중 탐색 막대 값이 덮어써지는 문제가 드러났다. 사용자 요청 위치를 먼저 확보하도록 고친 뒤 관련 HTML 검사를 다시 통과했다.

### 미확인 범위

Chrome 연결을 사용할 수 없어 실제 브라우저 렌더링·스크린샷·화면 크기별 시각 검증은 수행하지 못했다. DOM 모형 검사를 실제 브라우저 검증으로 표현하지 않는다. 새 Luna 관측, 전체 e2e, 공개 데이터 릴리스 검증은 실행하지 않았다.

## HTML 재생성

다음 명령은 기존 로그를 읽어 HTML만 만든다. 모델·MCP·컨테이너를 실행하지 않는다.

```bash
python3 apps/codemap-search/experiments/related-terms-poc/sense-eval/build_luna_replay.py \
  --input-dir /Users/buyong/tmp/rterms-luna-astra-6d4KwD \
  --output docs/related-terms/luna-replay.html
```

템플릿은 같은 디렉터리의 `luna_replay.template.html`이다. 이미 생성된 HTML을 보는 데 원자료 디렉터리나 Python은 필요하지 않다.
