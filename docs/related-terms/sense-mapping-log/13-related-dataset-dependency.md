# 13단계: 관련어 데이터셋 의존 조사

작업일: 2026-10-17. 조사만 했고 코드와 데이터셋은 바꾸지 않았다.

사용자가 고른 N5(관련어 데이터셋 의존 줄이기)는 "조사 후 보고"로 정했다. 뜻 조회(`sense_lookup.py`)는 저장소 밖의 관련어 데이터셋 `rtr1-930791c83bea6132`(430MiB, `.codemap/` 아래라 git이 추적하지 않음)가 없으면 동작하지 않는다. 이 단계에서는 무엇을 얼마나 읽는지 확인하고, 줄인 판으로 같은 결과가 나오는지 쟀다.

## 1. 조회가 rtr1에서 읽는 것

| 쓰는 곳 | 읽는 것 | 코드 |
| --- | --- | --- |
| 입력 해석 | `rtpoc3 related`를 실행해 입력과 입력 부분이 맞는 단어(`matches`)만 받는다. `rtpoc3`가 함께 계산하는 관련어 목록은 쓰지 않는다 | `category_lookup.run_rtpoc3` |
| 굴절형 근거 | `-ing`·`-ed`·`-s`로 끝나는 입력 단어로 들어오는 관계와 `form` 관계 | `category_lookup.InflectionEvidence` |
| 뜻 정렬 | 입력 단어와 주제 단어의 int8 768차원 벡터 | `sense_lookup.TermVectors` |

`rtpoc3`는 저장소의 Rust 소스(`lookup-v3/`)를 빌드한 바이너리다. 바이너리 자체는 저장소에 없으므로, 새로 받은 저장소에서는 `cargo build --release`가 필요하다.

## 2. 줄인 판 시험

뜻 데이터셋에 있는 단어(표제어, 관련어, 입력 단어 17만 6천 개)와, 굴절형 근거가 읽는 영어 굴절형만 남긴 rtr1 부분집합을 만들었다. 관계는 그 굴절형으로 들어오는 관계와 `form` 관계만 남겼다. 시험 스크립트와 판은 저장소 밖 작업 폴더에 있다.

| 판 | 단어 | 벡터 | 관계 | 크기 |
| --- | ---: | ---: | ---: | ---: |
| rtr1 원본 | 364,074 | 전부 | 916,718 | 430MiB |
| 줄인 판(벡터 포함) | 263,163 | 244,138 | 120,853 | 259MiB |
| 줄인 판(벡터 없음) | 263,163 | 0 | 120,853 | 41MiB |

평가 세트 224단어, 무작위 표본 3,000단어, 사전에 없는 입력 16개를 원본과 줄인 판으로 각각 조회했다. 사전에 없는 입력은 `blocked`, `retried` 같은 굴절형과 `appVersion`, `getUserName` 같은 식별자다.

| 비교 | 결과 |
| --- | --- |
| 줄인 판(벡터 포함)으로 입력 해석, 굴절형 근거, 뜻 정렬을 모두 대신함 | 3,253단어 응답이 원본과 모두 같다 |
| 줄인 판(벡터 없음)으로 입력 해석과 굴절형 근거만 대신함. 벡터는 원본 | 3,253단어 응답이 원본과 모두 같다 |
| 줄인 판(벡터 없음)에서 유사도 정렬을 끔(`--no-similarity-order`, 8단계 순서) | 표본 3,000단어 중 285단어의 첫 뜻이 달라진다. 평가 세트 첫 뜻 적중은 70.5%에서 68.8%로 내려간다([10단계](10-sense-order-rule.md)) |

입력 해석과 굴절형 근거에 필요한 자료는 41MiB에 들어간다. 나머지 218MiB는 뜻 정렬에 쓰는 벡터다.

## 3. 선택지

| 선택지 | 크기 | 결과 | 남는 일 |
| --- | --- | --- | --- |
| A. 줄인 판(벡터 포함)을 배포 | 259MiB | 원본과 같음 | GitHub 파일 한도(100MB)를 넘어 git에 바로 넣을 수 없다. Git LFS나 릴리스 파일로 배포해야 한다. `rtpoc3` 빌드도 필요하다 |
| B. 줄인 판(벡터 없음)을 저장소에 넣음 | 41MiB | 벡터가 없으면 8단계 순서로 정렬한다(첫 뜻 적중 68.8%). 벡터가 있으면 원본과 같다 | 벡터가 없을 때 유사도 정렬을 끄는 분기를 `sense_lookup.py`에 더해야 한다. `rtpoc3` 빌드는 여전히 필요하다 |
| C. 입력 해석을 Python으로 옮김 | B와 같음 | 시험하지 않음 | `rtpoc3`의 키 규칙(정확, 정규화, 붙여 쓰기, 기본형, 부분 일치)을 옮기고 같은지 검증해야 한다. 바이너리 빌드가 필요 없어진다 |
| D. 벡터를 줄임(차원 축소, 더 낮은 양자화) | 미측정 | 유사도가 조금 바뀐다 | 이 작업 환경에는 numpy가 없어 시험하지 않았다 |

## 4. 확인하지 못한 것

- 줄인 판에서 `rtpoc3`의 실행 시간은 재지 않았다.
- 비교는 2절의 3,253단어로만 했다. 사전에 없는 입력의 종류를 더 넓히면 다른 결과가 나올 수 있다.
- 줄인 판은 현재 뜻 데이터셋의 단어로 만든다. 뜻 데이터셋에 단어를 더하면 줄인 판도 다시 만들어야 한다.
