# 10단계: 뜻 순서 규칙 A 채택

작업일: 2026-10-17. 데이터셋: `rts4-e5083ab344e1336d`(기본값, 바꾸지 않음).

[9단계](09-similarity-order.md)의 질의 유사도 정렬(이하 D)은 생성 횟수를 무시하고, 검토로만 연결한 뜻을 첫 뜻으로 올리는 결함이 있었다. 생성 횟수와 유사도를 함께 쓰는 규칙 셋을 더해 네 가지를 비교했고, 독립 분석 두 번과 블라인드 판정을 거쳐 사용자가 A를 골랐다. 데이터셋은 바꾸지 않고 뜻 순서만 바뀐다.

## 1. 후보 규칙

모든 규칙에서 마지막 동점은 8단계 순서(`sense_order`)의 위치로 정한다.

| 규칙 | 순서 |
| --- | --- |
| 8단계 | 검토 전용 뒤 → 자기 뜻 먼저 → 생성 횟수 → 주제 단어 수 |
| **A** | 검토 전용 뒤 → 자기 뜻 먼저 → 생성 횟수 → 질의 유사도 |
| B | 검토 전용 뒤 → 질의 유사도 |
| C | 질의 유사도. 이웃한 뜻의 유사도 차이가 0.02 미만으로 이어지면 한 묶음으로 보고, 묶음 안은 8단계 순서 |
| D | 질의 유사도(9단계 기본값) |

검토 전용은 검토로만 연결한 뜻(생성 횟수 0), 자기 뜻은 다른 단어의 persona를 거쳐 읽지 않는 단어 자신의 뜻이다. 질의 유사도는 9단계와 같다.

## 2. 비교

평가 세트 224단어와 4단계부터 쓴 무작위 표본 3,000단어(뜻이 둘 이상인 823단어)로 쟀다. 각 단어의 뜻을 한 번 모은 뒤 규칙마다 다시 정렬했다. 그렇게 재구성한 D와 8단계 순서는 실제 조회 결과와 모든 단어에서 같았다.

| 지표 | 8단계 | A | B | C | D |
| --- | ---: | ---: | ---: | ---: | ---: |
| 첫 뜻 적중 | 68.8% | **70.5%** | 69.2% | 69.2% | 69.6% |
| `target` / `multi` / `input` | 87.6 / 52.3 / 45.7 | 87.6 / 55.4 / 50.0 | 87.6 / 50.8 / 50.0 | 88.5 / 50.8 / 47.8 | 88.5 / 50.8 / 50.0 |
| 맞는 뜻의 평균 순위(191단어) | 1.48 | **1.36** | 1.57 | 1.46 | 1.56 |
| 표본: 생성 횟수 1위 뜻이 첫 뜻이 아님 | 125 | 125 | 221 | 212 | 226 |
| 표본: 검토 전용 뜻이 첫 뜻 | 0 | 0 | 0 | 6 | 7 |
| 표본: 8단계와 첫 뜻이 다름 | 0 | 286 | 434 | 388 | 438 |

8단계와 A에서도 생성 횟수 1위 뜻이 첫 뜻이 아닌 단어(125)가 있다. 다른 단어를 거쳐 읽은 뜻의 생성 횟수가 자기 뜻보다 클 때도 자기 뜻을 앞에 두기 때문이다.

네 규칙의 단어별 순서를 나란히 보는 비교 페이지를 만들어 사용자에게 보였다(Claude 아티팩트, 저장소 밖).

## 3. 블라인드 분석 두 번

같은 의뢰서로 독립 분석을 두 번 돌렸다. 하나는 Claude Opus 5.5 하위 에이전트, 다른 하나는 `codex exec`(`gpt-6-astra`, 추론 `max`)다. 의뢰서에는 규칙 정의, 평가 자료, 사용자 요구만 적었다. 9단계 문서, 알려진 결함 문서, 평가 결과 폴더, 앞선 분석의 작업 폴더는 읽지 않게 했다. 두 분석 모두 저장소 파일을 고치지 않았다.

두 분석이 같게 본 것:

- A~D의 수치가 2절과 같다.
- A~D 사이의 차이는 2~3단어라 통계적으로 구별되지 않는다. A와 D를 짝지으면 A만 맞힌 단어 9개, D만 맞힌 단어 7개다(McNemar p=0.80).
- A~D보다 나은 변형으로 둘 다 같은 것을 찾았다. A의 우선순위를 두고, 같은 순위 안의 유사도를 주제 단어 각각과의 코사인 평균으로 바꾼 것이다(이하 Aμ). 첫 뜻 적중은 163단어(72.8%)로 A보다 5단어 많다(6개 얻고 1개 잃음, p=0.125).
- 생성 횟수와 유사도를 섞은 점수, 로그 가중, 여백 규칙, 주제 크기 보정, 순위 합치기, 질의 확장은 교차 검증에서 A를 넘지 못했다.
- 정렬만으로 닿을 수 있는 첫 뜻 적중 상한은 191단어(85.3%)다. A의 우선순위를 지키는 상한은 175단어(78.1%)다. 33단어는 기대 분야의 뜻이 데이터에 없어 어떤 정렬로도 고칠 수 없다. `input` 집단은 상한부터 63.0%다.

두 분석이 다르게 본 것은 Aμ의 채택 여부다.

| | codex | 하위 에이전트 |
| --- | --- | --- |
| 권장 | Aμ | A(Aμ는 보류) |
| 근거 | 5분할 반복 검증 20회와 저장소 하나씩 빼는 검증에서 매번 Aμ가 선택됨 | 시험한 설정 1,654개 전체에서 고르게 하는 중첩 교차 검증의 추정치는 159(+1) |
| 지적한 위험 | `on update`는 채점상 적중이지만 Flask 코드에 React 상태 주제가 첫 뜻으로 옴. `mobile` 퇴행 | 이득 6개 중 4개가 단어 3~8개짜리 `general-wording` 주제. 평가 라벨이 `general-wording`을 자주 고른 경향과 겹침. 단어 1~2개짜리 주제로 쏠림 |

하위 에이전트는 A가 순서 때문에 놓친 33단어를 코드 줄과 함께 다시 읽었다. 정렬 규칙으로 고칠 만한 명백한 정렬 오류는 약 7단어(`role`, `operators`, `compile` 등)였다. 약 17단어는 그 코드에서만 맞는 뜻이고(`public`이 공개 키를 뜻하는 경우 등), 약 9단어는 첫 뜻과 기대 분야가 이웃 분야였다.

## 4. 결정

사용자가 A로 바꾸고, Aμ는 A와 첫 뜻이 갈리는 표본 단어를 블라인드로 판정해 정하기로 했다. 결정 기준은 Aμ가 확실히 이기면 Aμ, 비슷하거나 A가 이기면 A다.

## 6. Aμ 블라인드 판정

표본 3,000단어 중 A와 Aμ의 첫 뜻이 갈리는 단어는 64개다. 나머지 단어는 두 규칙의 첫 뜻이 같다. 둘째 이하 뜻의 순서만 다른 단어는 105개 더 있다.

- 단어마다 두 첫 뜻을 규칙 이름 없이 무작위 순서로 놓았다. 각 후보에는 분야, 주제 이름, 그 뜻에서 함께 생성된 관련어 6개까지, 같은 주제의 단어 예 6개까지를 적었다.
- 질문은 "이 단어가 코드에 나올 때 더 흔히 뜻하는 것은 어느 쪽인가"다. 표본 단어에는 코드 용례가 없어서 일반적인 코드 전반을 기준으로 했다.
- Claude Opus 5.5와 codex(`gpt-6-astra`, 추론 `max`)가 따로 판정했다. codex는 판정 자료 파일 하나만 읽었다(실행 기록으로 확인). 어느 쪽이 어느 규칙인지 적힌 키는 두 판정이 끝난 뒤 열었다.
- 자료: `sense-eval/order-rule-judgments/`의 `pairs.json`(판정 자료), `key.json`(키), `judgments-claude.json`, `judgments-codex.json`

| 판정자 | A가 더 흔한 뜻 | Aμ가 더 흔한 뜻 | 같음 | 부호 검정 p |
| --- | ---: | ---: | ---: | ---: |
| Claude Opus 5.5 | 34 | 24 | 6 | 0.24 |
| codex | 20 | 9 | 35 | 0.061 |
| 둘이 같은 쪽을 고른 단어 | 19 | 8 | 5 | 0.052 |

두 판정자 모두 A 쪽이 더 많았다. 서로 반대쪽을 고른 단어는 `verification` 하나다.

| 둘 다 A를 고른 예 | A의 첫 뜻 | Aμ의 첫 뜻 |
| --- | --- | --- |
| `withTransaction` | Transactional database operations | Addition wording(`general-wording`) |
| `relative address` | Path construction | DOM element offsets(단어 1개) |
| `WhileNode` | Loop iteration control | Permanence wording(`general-wording`) |
| `probe` | Liveness health checks | Kernel tracing probes |
| `query` | SQL statement execution | Observability queries |

| 둘 다 Aμ를 고른 예 | A의 첫 뜻 | Aμ의 첫 뜻 |
| --- | --- | --- |
| `of` | Observable stream operators | Static factory construction |
| `QoS=1` | Network traffic QoS | MQTT broker delivery |
| `rfc 7230` | HTTP protocol negotiation | HTTP message lines |
| `significance` | Behavior semantics wording | Confidence interval plots |

Aμ가 진 예는 하위 에이전트가 지적한 위험(작은 주제와 `general-wording` 주제로의 쏠림)과 맞는다. 결정 기준에 따라 **Aμ는 채택하지 않는다.**

판정의 한계:

- 두 판정자 모두 LLM이다. Claude 판정자는 Aμ가 작은 주제를 앞세운다는 것을 알고 있었고, 후보의 단어 예 수가 6개보다 적으면 작은 주제라는 것이 드러난다.
- codex는 절반 넘게 `same`으로 답했다.
- 둘 다 p가 0.05보다 크다. Aμ가 A보다 낫다는 근거가 없다는 뜻이지, A가 확실히 낫다는 뜻은 아니다.

## 7. 남은 문제

- 생성 횟수는 코드에서의 빈도가 아니다. `role`은 4번 생성된 Documentation markup이 권한 역할(Role assignments, 1번)보다 앞선다. `operators`도 같은 유형이다.
- 검토로만 연결한 뜻은 맞는 뜻이어도 맨 뒤다(`jsonp`, `text transform`).
- 생성 횟수가 같은 뜻 사이에서는 9단계의 한계가 남는다. 질의 표기만 보므로 문맥을 구분하지 못하고, 같은 글자가 든 주제가 앞서기 쉽다(`tokens`의 Lexical token streams와 Design token tooling이 OAuth access tokens보다 앞선다).
- 정렬로 더 얻을 수 있는 몫은 작다. 첫 뜻 적중을 더 올리려면 기대 분야의 뜻이 없는 33단어(뜻 누락, 분야·연결 오류)를 고치거나 조회에 문맥을 넘겨야 한다. 33단어 중 5개(`organization repository`, `define`, `cookie samesite`, `amt`, `navigation component`)는 기대 분야가 주제의 보조 분야에만 있다.
- "질의와 가장 비슷한 순서"를 글자 그대로 따르는 것은 D다. A는 생성 횟수가 다르면 유사도가 낮은 뜻도 앞에 둔다. 표본에서 A와 D의 첫 뜻이 갈리는 단어는 약 160개다.
