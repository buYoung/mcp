# B-4 멤버 범위 · 둘 다: 추가 패치 25회 실험

상태: 25회 풀이·5개 채점 묶음·직접 재생·집계 완료. 실제 상태와 봉인은 실험 루트 `checkpoint.json`, `final-verification.json`으로 확인한다. 이 문서는 실행 전에 작성한 재개 기준과 완료 기록을 함께 보존한다. **후속 제품 반영:** 사용자 승인으로 멤버·둘 다와 범위+안내를 `ee1774533`·`f27ca5edc`에 반영했다. 아래 제품 변경 금지·환경 변수 지침은 격리 실험 당시의 계약이며 현재 제품 구현 방식이 아니다. [현재 소스 상태](CURRENT-STATE.md)

## 요청과 비교표

공통 기반은 `b4-live-symbols-r2`의 `group-both`다. `grep`, `read`는 `# symbols` 뒤에 `# results`를 출력하며, 같은 파일의 class/struct/impl 멤버와 caller/callee를 함께 제공한다. Smart routing은 적용하지 않는다.

| 후보 ID | 하위 폴더 범위 보존 | grep 정규식 안내 보강 | 언어별 멤버 그룹 정확성 | 새 풀이 |
| --- | --- | --- | --- | --- |
| scope-both | 적용 | 기존 | 기존 | 5 |
| regex-both | 기존 | 적용 | 기존 | 5 |
| language-both | 기존 | 기존 | 적용 | 5 |
| scope_regex-both | 적용 | 적용 | 기존 | 5 |
| all-both | 적용 | 적용 | 적용 | 5 |

총 25회다. 사용자의 ‘안내 보안’은 정규식 사용 안내 보강으로 해석한다. 기존 `group-both` 5회는 역사적 참고값으로 재사용하며, 추가 기준군 풀이를 만들지 않는다.

## 고정 조건

- 문항: 기존 어려움 문항 `complex-go-1`. 조직 사용자 검색과 팀 검색의 권한 필터 SQL 전달 경로를 비교한다.
- 풀이 모델: `gpt-5.6-luna`, 추론 `medium`, 고정 Codex CLI `0.153.4`.
- 실행 한도: 300초, 탐색 호출 80회, 캐시 포함 입력+출력 500,000토큰. 최대 동시 실행 2개. 한도 도달 뒤 기존 30초 사용량 수집 유예를 유지하고 늦은 답변은 제외한다.
- 채점: 기존 사실·근거·인용 기준, `gpt-6-astra high`. 최대 5개 배치, 각 배치 실제 답변 최대 5개와 고정 대조 답변 4개. 빈 답변은 기계적으로 판정한다.
- 원본: `benchmark/v2/artifacts/b4-live-symbols-r2`. 평가 소스·초기 인덱스·문항·프롬프트·채점 기준을 재사용한다.
- 평가 소스 커밋: `c6fad8695a96577eb466d425e6ac4a759ca30f47`; 소스 목록 SHA-256: `607ab21a2294386a9fb2a5199555fe5ecffbe6c8703d9ee2709191e1b39e7638`; 초기 인덱스 목록 SHA-256: `b23c0eae8200a0fffa08a98b59a40eb18967cbcc215036ae84ec8f93491039b5`.
- 활성 제품 코드와 기존 실험은 변경하지 않는다. 새 실험의 격리된 소스와 실행 기록만 작성한다.

## 패치 경계

범위 보존은 하위 폴더 `overview` 뒤의 암묵적 `search`와 명시적 `workspace_scope`가 해당 하위 폴더를 유지하도록 한다. 별칭 해석·`all` 초기화·경로 경계를 유지한다. 파일을 지정하면 그 파일의 부모 폴더를 검색 범위로 사용한다. workspace 자체의 식별 함수는 유지하고 search용 범위 해석을 분리한다.

정규식 안내는 `grep.pattern`의 정규식 의미, 괄호·별표 등 리터럴 문자의 이스케이프, 0건일 때 검색식 점검을 설명한다. 자동 이스케이프·자동 검색 확대·문항별 힌트는 추가하지 않는다.

언어별 그룹은 기존 고정 멤버 범위를 유지하면서 언어별 컨테이너 및 Rust impl 영역을 정확히 연결한다. 함수 범위로 자동 전환하지 않는다. Go receiver 그룹은 기존과 같을 수 있다. 실제 Go 응답이 바뀌지 않았다면 ‘이번 문항에서 패치가 노출되지 않음’으로 기록하며 일반적인 무효과로 해석하지 않는다. 정확한 변경 목록은 실행 전 소스 해시와 함께 고정한다.

## 실행·재개 계약

실험 루트: `benchmark/v2/artifacts/b4-member-patches-r1`.

1. `request.json`, `schedule.json`, `checkpoint.json`을 먼저 저장한다. 반복 번호 1~5 안에서 5개 후보를 고정 난수 순서로 배치한다. 25개 슬롯의 ID는 `<후보 ID>-r<반복 번호>`다.
2. 격리된 소스·하네스를 준비하고 기존 fixture를 통한 직접 도구 계약 확인 및 필요한 컴파일을 실행한다. 모델 풀이 전에 구현·설정·일정·분석·채점 입력 해시를 고정한다.
3. 슬롯 시작 전에 시작 기록을 남긴다. 완료 답변·호출·사용량·실행 봉인을 검증하고 체크포인트를 갱신한다. 완료 슬롯은 재실행하지 않는다.
4. 중단 후에는 체크포인트와 각 슬롯의 원본 로그·프로세스·봉인을 먼저 대조한다. 시작됐지만 미완료인 슬롯은 기존 로그에서 회수할 수 있는지 진단한다. 자동 재풀이·자동 재채점·무근거 반복을 금지한다.
5. 실행 명령과 준비 완료 상태는 이 문서와 실험 루트 README에 실제 생성된 명령으로 추가한다. 아직 없는 명령을 실행 가능하다고 보고하지 않는다.
6. 사용량 누락·빈 답변·한도 도달·채점 미확정은 원형 그대로 남긴다. 누락 토큰을 추정값으로 채우거나 인용을 고쳐 채점하지 않는다.

## 분석과 완료 조건

새 실험 내 단일 변경 비교는 `scope_regex-both` 대 `scope-both`(범위 보존 하에서 안내 추가), `scope_regex-both` 대 `regex-both`(안내 하에서 범위 보존 추가), `all-both` 대 `scope_regex-both`(두 패치 하에서 언어 그룹 추가)다. 다른 후보 간 차이와 이전 `group-both` 비교는 복합 변경 또는 역사적 비교로 표시한다.

후보마다 부분 정답·완전 정답·오답·무응답·미확정, 정답 사실·인용 근거, 평균 전체 토큰과 수집 완전성을 제시한다. 기존 94개 지표와 호출 흐름·패치의 실제 노출 여부를 보존한다. 5회·단일 Go 문항의 결과로 일반적인 인과관계나 동등성을 확정하지 않는다. 특히 패치가 실행 경로에 노출됐는지와 최종 답변 개선은 분리한다.

완료 조건: 요청한 25개 슬롯의 상태와 원본 기록이 남고, 채점·집계·무결성 검증 결과 및 한계가 보고서와 `benchmark/CURRENT-STATE.md`에 연결되어 있어야 한다. 준비나 문서 작성만으로 완료 처리하지 않는다.

## 풀이·채점 완료와 후처리 기록

- 새 풀이 25회 종료: 정상 완료 21회, 토큰 한도 종료 4회. 빈 답변 3회이며 모두 원래 분모에 남겼다. 전체 사용량은 23/25회 확정, 나머지 2회는 관측 하한을 유지한다.
- 답변 22개를 Astra high 5개 묶음으로 채점했고 고정 대조 20개도 검증을 통과했다. `scope_regex-both-r5`는 인용 목적지가 모두 `...`이어서 판정 보류다. 원래 답변을 고치거나 다시 채점하지 않았다.
- 최초 직접 재생 드라이버의 예외 타입 처리를 보완한 `exposure_v2.py`로 재개한다. 원래 드라이버·고정 입력은 그대로 보존했다. 오류 직전까지의 27개 통신 응답을 회수했고 재풀이·재채점 및 완료 탐색 요청 반복은 없었다. 상세 근거는 실험 루트 `postprocessing-revision.json`과 README에 있다.

## 최종 결과와 재사용

[최종 보고서](v2/artifacts/b4-member-patches-r1/report.md)와 [94개 상세 지표](v2/artifacts/b4-member-patches-r1/analysis/metrics-detail.md)에 모든 결과를 남겼다. 범위+안내가 평균 310,625.6토큰으로 이번 후보 중 가장 낮았으나, 정답 2/5회와 보류 1회여서 품질 우위를 확정하지 못했다. 세 가지 전부는 정답 1/5회, 평균 383,640.2토큰이다. 이전 기준은 시점이 다른 3/5회·319,993.4토큰으로 유지한다.

실제 요청 재생에서는 범위 검색 27건 중 3건이 달라졌고, 언어 패치 grep/read 185건은 차이가 없었다. 따라서 범위 수정의 출력 효과와 Go에서 언어 패치가 노출되지 않은 사실을 구분한다. 초기 직접 검증의 Rust impl 복구를 Go 답변 개선 근거로 전용하지 않는다.

완료된 25개 슬롯과 채점을 다시 실행하지 않는다. 같은 결과는 원자료·봉인·보고서와 당시 고정한 소스·바이너리·하네스로 확인한다. `study.py verify`에는 실험 당시 활성 제품의 변경 여부 검사도 있으므로, 후속 제품 반영 이후 현재 작업 트리에서 그대로 실행하면 승인된 변경 때문에 실패할 수 있다. 이를 이유로 과거 봉인이나 검증기를 덮어쓰지 않는다. 새 실험은 별도 이름과 별도 계약으로 시작해야 한다. 범위+안내의 후속 제품 반영과 이 실험의 원래 점수·완료 상태는 구분한다.
