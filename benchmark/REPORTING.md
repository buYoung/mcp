# codemap-search 개선 평가·보고 기준

2026-09-08 사용자 지시에 따라, 앞으로의 제품 개선 평가는 현재 상세 메트릭 형식을 유지한다. 이 문서는 평가·보고 담당자가 따르는 기준이며 사용자의 후속 지시가 우선한다.

작업을 재개할 때 [현재 상태와 비교표 형식](CURRENT-STATE.md)을 먼저 읽는다. 최신 인과 확인 범위·미확인 항목·파일별 심볼 첨부의 기존 시도도 그 문서에서 확인한다. `grafana-four-way-r1`은 네 버전의 준비 질문 재측정 기록이다. 표 형식과 결측 처리 규칙을 유지하되, 그 수치를 새 후보 성능평가의 기준값으로 복사하지 않는다.

## 인과 해석과 같은 실수의 재발 방지 — 2026-09-10

1. **시작 전에 완료 기록부터 확인한다.** 대상 실험의 `checkpoint.json`, `frozen.json`, 일정, 실행 결과와 최종 검증의 존재·상태를 확인한다. 대화 요약에 작업이 없다고 되어 있어도 기존 완료 실험을 자동으로 다시 만들거나 실행하지 않는다. 남아 있는 원자료를 읽어 확인하는 것과 새 실행을 구분한다.
2. **미사용·미제공·효과 없음은 다르다.** `overview/search`의 낮은 호출 빈도만으로 영향이 작다고 결론내리지 않는다. R1-C4처럼 선택 기능 사용이 0회면 그 기능의 효과는 미확인이다. 후보 묶음의 점수를 개별 기능의 성능으로 대체하지 않는다.
3. **개입의 종류를 정확히 적는다.** 안내 문구, 검색 인자, 색인 저장 내용, 순위 계산, 결과 렌더링, 실제 모델 전달, 종료·채점 절차를 구별한다. 같은 색인을 쓴 프롬프트 실험을 색인 변경 실험으로 부르지 않는다. 오사용 호출을 외부에서 직접 고친 실험과 모델이 안내를 보고 스스로 고치는 실험도 분리한다.
4. **실제 행동·반환·전달을 먼저 확인한다.** 도구 호출 성공이나 힌트 생성만으로 모델이 내용을 봤다고 가정하지 않는다. 실제 인자와 네이티브 반환, 모델에 전달된 내용, 후속 행동을 대조한다. 반복되는 첨부는 세션 전체의 동일 문자열 검색으로 호출별 전달을 판정하지 말고 해당 exec/wait 출력에 연결한다. 같은 호스트 호출에서 동일한 첨부가 여러 번 생성됐다면 개별 귀속이 모호함을 남긴다. 빈 영역·생략 안내의 전달과 실제 심볼·호출 관계의 노출도 구분한다. JSON/JavaScript의 표시상 백슬래시 수를 실제 검색식과 혼동하지 않는다. 0건은 경로·필터·검색식·출력 조건을 확인하기 전까지 코드 부재나 엔진 결함의 증거가 아니다.
5. **일차 지표와 보조 관측을 바꾸어 쓰지 않는다.** 오사용 복구가 양쪽 12/12인데 목표 노출이 0/12 → 11/12라면 ‘노출 증가’를 보고하고 ‘오사용률 감소’로 바꾸지 않는다. 명시적 복구 과제, 한 번의 검색, 고정 표시 이력의 후속 풀이를 자연스러운 전체 문제 풀이와 구분한다. 반복 수·문제 수·공유 대조·불확실성을 함께 적는다.
6. **탐색 이후 실패를 별도로 분류한다.** 근거 미도달, 전달 뒤 필수 설명 누락, 잘못된 논리, 내용은 맞지만 인용 부족, 답변 없음은 별도 항목이다. 전달 시각과 실제 행을 확인하고, 전체 근거 묶음과 누락한 세부 내용의 근거를 구별한다. 어떤 코드가 전달됐다는 사실만으로 내부 이해·주의·요약 중 원인을 단정하지 않는다.
7. **답변 안내와 채점 요건의 간격을 점검한다.** ‘파일 경로·행 번호’ 안내와 충분한 근거 범위를 요구하는 채점은 구체성이 다르다. 명시된 Markdown 표시문 범위를 시작 앵커 한 행으로 축소하지 않는다. 불충분한 인용을 고쳐 통과시키거나 기존 점수를 조용히 바꾸지 말고, 필요한 채점 수정은 별도 고정 계약으로 보존한다. `causal-control-r1`의 최종 해석은 `grading-r2`를 따른다.
8. **종료 수집 개선의 비용과 한계를 보존한다.** [선택형 수집 대기](v2/USAGE-COLLECTION.md)를 쓰면 조건·대기 시간·한도 이후 답변 제외·추가 토큰을 실행 전에 고정한다. 정상 종료 인증 조건을 완화하지 않는다. 낮은 한도 진단 2회 성공을 500,000토큰 부하나 모든 장애에서의 성공으로 일반화하지 않으며, 과거 누락 비용은 여전히 미확정으로 남긴다.
9. **유사한 제안을 같은 기능으로 취급하지 않는다.** `overview(...)` 호출 추천, 특정 심볼을 지정한 선택형 read, `grep/find/read` 결과 자체의 파일별 심볼 요약·목록은 서로 다르다. 기존 구현·선택 인자 사용·실제 출력·모델 전달을 구분한 뒤 중복 시도 여부를 판단한다. 심볼 직접 첨부는 목록/현재 위치 심볼의 범위, 자동/선택 노출, 파일 수·바이트 상한과 색인 미준비 시 동작도 구분해 기록한다. 두 정보의 단독/동시 첨부를 비교할 때는 한 정보가 다른 정보를 출력 한도에서 밀어내는지도 확인한다. Go receiver와 class/impl의 대응, 중첩 선언 포함 규칙처럼 후보 의미에 영향을 주는 해석은 실행 전에 확정한다. 실제 구현·실행 범위는 사용자의 후속 요청을 따른다.
10. **자료 부재를 실험 결과로 채우지 않는다.** 정리된 후보는 보존 등록부·집계와 현재 직접 읽을 수 있는 소스를 구별한다. 생성·측정·채점의 완료 기록을 확인하고, 원시 소스나 로그가 없으면 그 재검증 한계를 밝힌다. 과거 제안 객체 안의 오래된 상태와 후속 구현·실행 상태도 혼동하지 않는다.
11. **모델 실행 전에 실행기와 채점 준비 경로도 확인한다.** CLI 자동 업데이트로 버전이 바뀌었다면 실제 사용할 경로·바이너리를 고정하고 확인한다. 익명화에 필요한 경로 메타데이터도 실제 실행 자료와 대조한다. 경고는 정확한 원문 구간을 분류한 기록을 남기며, 식별 정보가 없는 잘못된 인용 경로를 올바르게 고쳐 채점하지 않는다. 준비 실패·보완과 실제 모델 재실행을 구분한다.
12. **범위의 효과를 정보 종류와 분리해서 일반화하지 않는다.** `b4-live-symbols-r1`에서는 같은 타입→함수 축소가 내부 심볼만 있을 때 비용 증가5/5, 호출 관계와 함께 있을 때 비용 감소5/5로 반대로 관측됐다. 다른 요인을 고정한 반복 방향·정답·근거 충족을 함께 보고한다. 이 결과는 해당 문제의5회 관측이며 무첨부 B-4 대비 첨부 자체의 효과나 다른 문제의 확증이 아니다.
13. **사용자가 확인한 실제 출력 구조를 측정 전에 대조한다.** 이번 심볼 실험 계약은 `# symbols`가 먼저, `# results`가 나중이다. class/struct/impl의 필드·메서드를 계층으로 묶고 메서드 지역 변수와 공개 여부를 별개로 다룬다. Go receiver 대응을 확인받았다는 이유로 평면 목록·지역 변수 포함·원문 뒤 배치를 같은 요구로 취급하지 않는다. 사용자 예제를 실제 도구로 출력해 확인한다. r1의 뒤쪽 평면 목록과 r2의 앞쪽 계층 출력은 순서 외의 요소도 달라, 두 차수를 순서 하나의 인과 효과로 비교하지 않는다.

14. **판정 보류를 집계 전 과정에서 유지한다.** 채점 계약 검증 통과와 모든 답안의 판정 확정을 구분한다. `indeterminate` 때문에 사실·근거 수가 미확정이면 합산·반복 비교·보고서에서도 미확정을 전파하고, 정답 확정 건수·보류 건수·유효 분모를 함께 표시한다. 보류 답안의 개별 사실 메모를 확정 집계에 섞지 않는다. r2에서 발생한 보류값 합산 오류처럼 집계를 보완할 때는 원본·실패 자료·새 분석 코드를 보존하고 풀이·채점·비교 기준의 변경 여부를 명시한다.

15. **조건부 결합은 실제 분기 사용을 확인한다.** 두 좋은 후보를 합쳤다는 이유로 점수를 합성하지 않는다. 함수·멤버·혼합·미분류의 생성과 실제 전달을 따로 센다. 언어별 직접 분기 검사 통과와 모델 실행에서 해당 분기가 사용된 것은 다르다. 넓은 조회창의 혼합 처리와 행 단위 판정 한계를 기록하고, 과거 결과를 재사용한 비교를 같은 시점의 짝지은 인과 대조로 바꾸지 않는다.

16. **제품 채택과 과거 실험 봉인을 구분한다.** 현재 제품의 승인된 변경으로 과거 검증기의 활성 작업 트리 해시 검사가 실패할 수 있다. 당시 스냅샷·바이너리·하네스와 현재 소스를 구분하고, 통과시키려고 원래 봉인·점수·검증기를 고치지 않는다. 제품 반영의 완료는 필요한 기반 파일까지 커밋에 포함됐는지 확인하며 단순 서식 잔여와 미커밋 동작 변경을 구별한다.

현재 확인한 인과관계와 아직 밝혀지지 않은 항목의 구체적인 수치·출처는 [현재 상태](CURRENT-STATE.md)에 둔다. 이 규칙은 실행 범위를 늘리거나 별도 승인 단계를 추가하는 지시가 아니며, 사용자의 최신 요청과 제한 안에서 적용한다.

## 평가 단계 정정 — 2026-09-09 사용자 지시

**준비 6문제를 두 버전에 실행하는 12회는 정식 벤치 전 오류 찾기용 사전 검증이다. 후보 성능을 선별하는 벤치마크로 사용하지 않는다.** 이전 문서와 B-5~B-7 작업에서 이 단계를 후보 성능 판정으로 사용한 해석은 철회한다. 기존 원자료·점수는 당시 관측 기록으로 보존하며 새 성능 결과로 재해석하거나 고쳐 쓰지 않는다.

- **후보별 구현·계약 확인:** 요청받은 후보군 전체를 각각 준비한다. 구현 보류·계약 오류·미실행·성능 미측정을 구분하고 일부 후보의 결과를 전체 후보군의 결론으로 발표하지 않는다.
- **후보 성능평가:** 고정 정식 문항에서 선택한 오류 검증 부분집합 안의 더 작은 고정 부분집합을 사용한다. 문항·정답 계약·반복수·실행 제한을 후보 결과를 보기 전에 고정하고 모든 후보의 실제 모델 토큰·최종 답변을 같은 조건으로 비교한다. 진단 단계의 점수나 CPU·직접 도구 시간으로 대신하지 않는다.
- **12회 사전 검증:** 정식 평가 전에 도구·모델 전달·권한·인자·실행 환경·수집·채점 등의 오류를 찾는 진단 단계다. 발견한 오류를 고쳐야 할 근거는 되지만 후보 성능의 우열·채택을 확정하는 자료는 아니다.
- **정식 평가:** 별도로 승인·고정한 범위에서 수행한다. 오류가 있었던 과거 정식 30문제 결과를 새 결과에 사용하지 않는다.

`b4-next-candidates-r1`·`r2`·`r3`의 **15개 전체 재시도는 본평가에서 선택한 10문제·총 180회로 완료**했다. 고정 ID와 상태는 재시도 후보 등록부에 보존한다. 기존에 유리해 보인 후보만 다시 고르거나 미검증 후보를 실패/위반으로 표시하지 않는다. 후속 작업은 아래의 고정 부분집합 정책을 따르며, 매 후보 탐색마다 새 질문집을 구성하지 않는다.

## 질문·정답 계약과 기준 결과 고정 — 2026-09-09 정정

**후보 탐색마다 문항 구성을 바꾸고 A·B-1·B-4·B-6을 재측정하여 고정 점수처럼 제시한 절차·보고 오류를 바로잡는다.** 확인된 최근 네 평가의 문항 수는 6 → 10 → 1 → 3이며 기준 네 버전은 각각 24·40·4·12회 새로 실행했다. 선택한 질문·핵심 사실·근거·대조 답안 객체는 기존 원본과 일치했다. 개별 정답을 매번 새로 썼다는 주장과 문항·정답 묶음을 바꾼 사실을 구분한다. [실행별 근거·보존 결과표](CURRENT-STATE.md)

1. **문항 계층을 고정한다.** 정식 문항 집합을 F, 오류 검증 문항을 E, 후보 탐색 문항을 C로 두고 **C ⊂ E ⊂ F**를 유지한다. 오류 검증과 후보 탐색은 정식 벤치의 규모를 줄인 단계이며 별개의 문제·정답을 만드는 단계가 아니다. 실행 목적·반복수·제한은 단계별로 미리 기록한다. 12회 진단을 후보 우열 판정으로 바꾸지 않는다.
2. **질문과 정답 계약을 함께 유지한다.** 문항 ID와 순서, 질문, 핵심 사실, 원문 근거, 대조 답안, 채점 기준을 후보 결과를 보기 전에 고정한다. 후보마다 유리한 문항을 고르거나 정답을 완화하지 않는다. 필요한 변경은 이유와 함께 새 평가 차수로 등록하고 기존 자료를 보존한다.
3. **기준 결과 재사용이 기본이다.** 같은 평가 계약에 고정된 A·B-1·B-4·B-6 결과를 실행 ID와 함께 재사용하고 새 후보만 승인된 범위에서 실행한다. 후보가 바뀌거나 비교표가 필요하다는 이유로 기준 버전을 자동 재측정하지 않는다. 명시적으로 재측정을 요청받은 경우에만 별도 차수의 결과로 추가하며 과거 값·표를 덮어쓰지 않는다.
4. **비교의 식별 조건을 함께 남긴다.** 제품 버전·소스/바이너리 해시, 문항 부분집합 ID·목록·해시, Grafana 커밋, 모델·추론 강도·CLI, 실행 제한·반복수·일정, 하네스·도구 정의, 채점 계약·방법, 캐시·색인 시작 상태, 실행 ID가 필요하다. 모델 샘플링 미통제와 일정 시드를 구분한다. 버전 이름이나 핵심 하네스 해시만 같다고 같은 평가로 취급하지 않는다.
5. **호환되지 않는 과거 수치는 분리한다.** 현재 계약과 맞지 않는 기록은 별도 과거 표로 보존한다. 기본 네 열은 유지하되 호환되는 측정이 없으면 미측정으로 표시하고 이유를 적는다. 6문제 평균을 3문제 평균과 연결하거나 다른 차수의 유리한 토큰·정답 값만 골라 섞지 않는다. 별도 재채점·재집계도 원본을 보존하고 변경 이유·입력·판정 차수를 구분한다.
6. **규모에 맞게 결론을 제한한다.** 1문제·3문제의 각 1회 관측은 일반적인 성능 개선이나 기능별 인과 효과의 확증이 아니다. 작은 탐색의 결과로 오류 검증·정식 평가를 완료했다고 보고하지 않는다. 결측이 있는 토큰 하한을 확정 평균이나 절감률로 바꾸지 않는다.

기존 `dataset.json`의 준비 6문제와 본평가 30문제는 서로 겹치지 않는 과거 구성이다. 이를 위의 중첩 부분집합 정책이 이미 구현된 것으로 설명하지 않는다. 이번 정정은 문서·등록부에 적용하며 **새 F/E/C 등록이나 실행기 변경은 수행하지 않았다.** 다음 평가 준비 시 기존 검증 문항에서 부분집합과 참조 실행을 고정하고, 정책을 충족하지 않는 기존 명령을 그대로 실행하지 않는다. 오류가 확인된 정식 30문제의 **결과·점수는 계속 제외**한다. 검증된 원본 문항을 사용하는 것과 오류가 있는 과거 점수를 재사용하는 것은 다르다.

## 대상과 제품 버전

**후보 탐색 종료 후 정식 비교의 범위는 Grafana의 A / 현재 승인 제품이다.** 아래 A/B-1/B-4/B-6 열 규칙은 후보 탐색 이력의 보고 형식이며, 후속 A/현재 정식 비교에 불필요한 버전 실행을 추가하는 근거가 아니다. `formal-r1-A` 다중 저장소 고정 표는 과거 기록으로 유지하고 Grafana의 기준값으로 사용하지 않는다. `bench:ready`를 6개 저장소 준비로 확대하지 않는다.

- 저장소 범위는 Grafana다. 정식·오류 검증·후보 탐색의 문항을 위 중첩 부분집합 정책으로 고정한다. 다른 저장소로 임의 확대하지 않는다. 오류가 확인된 정식 30문제 결과와 다른 저장소의 사전 검증 결과를 개선 판정에 사용하지 않는다.
- 현재 소스는 **B-4 + 멤버 범위·둘 다 + 범위 보존·정규식 안내**다. 과거 표의 B-4는 각 실행에서 동결한 무첨부 기준 제품으로 유지한다. B-1은 비교·복원 자료로 보존한다. [현재 기준](current-baseline.json)의 소스 커밋·제품 트리와 과거 측정 바이너리를 구분하며, 로컬 release 파일의 존재만으로 현재 소스의 빌드·배포를 확인했다고 보고하지 않는다.
- **A**는 기본 탐색 도구이며 승인된 경로·행 번호 설명 보완 여부를 표시한다. **B**는 최초 제품, **B-1**은 이전 채택 개선본, **B-2**는 철회한 후속 후보다. B-2 결과를 삭제하거나 이름을 재사용하지 않는다.
- 개선 차수와 기반 버전을 함께 기록하고 과거 B-5·B-6·B-7의 이름을 재사용하지 않는다. 현재 15개 개별 후보는 **R1-C1~R3-C5(각각 B-4 기반)**로 구별하며, 원래 제안 묶음·실제 과거 구현 버전의 대응을 명시한다. B-4는 사용자가 승인한 5개 통합 개선본이며 이후 개선은 B-4를 대조군으로 삼는다.
- 새 비교의 A는 이미 승인된 기본 경로·행 번호 설명 보완을 유지한다. [현재 기준](current-baseline.json)의 A 도구 정의 해시를 대조하고, 원본 하네스의 과거 설명을 그대로 복사해 알려진 오류를 다시 도입하지 않는다.
- 같은 시점의 새 실행과 과거 실행 재사용을 구분한다. 모델·추론 강도·CLI·Grafana 커밋·질의·설정·실행 제한·순서·제품 해시를 실행 전에 고정한다. 모델 샘플링 시드를 통제하지 못하면 일정 시드와 구분한다.

## 상세 메트릭 형식

제품 개선 판정 지표는 **후보 성능평가에서 실제 모델이 사용한 전체 토큰과 최종 답변의 정답·근거 충족**이다. 도구 시간·CPU·작업량 감소는 진단 자료다. 경량 직접 검사나 12회 사전 검증만 수행한 결과를 후보 성능 검증 완료로 대신하지 않는다. 후보군 전체 검증을 요청받으면 모든 후보를 같은 고정 성능평가 조건으로 확인하되 사용자의 실행 수·비용·재실행 제한을 지킨다. 평가가 제한되거나 막혔다면 그 단계를 미완료로 보고한다. 과거 사전 검증 수치를 복사하거나 미측정으로 채우는 것만으로 완료하지 않는다.

후속 사용자 지시에 따라 **후보 탐색·우선순위·채택 판단에는 실제 모델의 전체 토큰 사용량과 최종 정답률만 사용한다.** 시간·CPU·호출 수·내부 작업량은 기존 상세 형식에서 진단 자료로 유지하되, 이 두 지표의 개선을 대신하거나 점수에 합산하지 않는다. 기존 실행 분석으로 발견한 실패 구간과 새 후보의 실제 효과를 구분한다. 정답 감소를 토큰 절감으로 상쇄하지 않으며, 품질과 사용량 중 한쪽이 나빠지면 절충으로 보고하고 자동 채택하지 않는다. 후보 탐색만 요청받은 경우 새 모델 실행 없이 근거 있는 가설을 정리할 수 있지만, 이를 검증된 개선으로 표시하지 않는다.

MCP `tools/list`와 직접 호출의 성공은 실제 Codex에 전달되는 인자 설명의 보존을 보장하지 않는다. 실제 모델 출력의 도구 선언에서 기존·새 인자, 기본값과 권한 안내를 확인한다. 선언이 포괄적인 unknown 타입으로 바뀌거나 새 기능 안내가 사라지면 계약 회귀로 기록하고, 설명 크기 감소나 미사용 기능의 직접 속도를 제품 개선 근거로 세지 않는다.

기준은 상세 보고서와 [94개 지표 정의](metrics-catalog.json)다. 새 지표는 추가할 수 있으나 기존 지표를 설명 없이 삭제하거나 의미를 바꾸지 않는다. 기능이 없는 버전은 미제공, 기록이 없는 항목은 미측정, 자료가 불완전하면 미확정으로 표시한다. 빈 값을 0이나 통과로 바꾸지 않는다.

보고서에는 다음 내용을 모두 포함한다.

2026-09-09 사용자가 지정한 기본 비교 열은 **A / B-1 / B-4 / B-6**이다. 후보 탐색 보고, 검증 보고서 첫 요약과 대화의 최종 결과 답변에도 이 버전들을 한 표로 표시한다. 최신 두 버전만 제시하거나 나머지 버전을 상세 보고서 링크로 대신하지 않는다. 후속 후보가 생기면 이 네 열을 유지하고 오른쪽에 후보 열을 추가한다. 같은 버전에 여러 실행 차수가 있으면 사용한 차수와 과거·새 실행 구분을 표에 밝히고, 다른 차수의 토큰과 정답률을 섞지 않는다.

같은 날의 후속 지시에 따라 요약 표의 필수 행은 **부분 정답 / 정답 / 오답 / 답변 없음 / 핵심 사실 충족 / 평균 토큰 사용량**이다. 평균 토큰은 캐시 포함 입력+출력을 모든 예정 실행 수로 나눈 값이며, 전체 사용량이 불완전하면 정확한 평균은 미확정으로 표시한다. 관측 평균 하한을 함께 제시할 때는 하한임을 명시하고 실패 실행을 제외한 평균으로 대체하지 않는다. 네 버전 재측정을 요청받은 평가의 기본 표에는 네 버전의 새 실행만 사용한다.

새 측정 없이 후보만 탐색할 때도 같은 표 형식을 유지한다. 고정 평가 계약과 호환되는 기준 결과는 **기존 기록 재사용**과 실행 ID를 표시한다. 과거 사전 검증이나 다른 문항 구성의 기록은 별도 표로 분리하며 새 후보의 미측정 칸에 이전 제품 수치를 넣지 않는다. 형식 유지 때문에 기준 버전이나 후보 실행을 자동으로 추가하지 않으며 사용자가 승인한 실행 범위와 횟수를 따른다. 표의 값·정의·후속 적용 예는 [현재 상태 문서](CURRENT-STATE.md)에 보존한다.

1. **버전 비교:** A/B/B-1/후속 후보의 정확한 의미, 기반 버전, 새 실행·재사용 구분, 표본 수와 제품 해시.
2. **품질:** 완전 정답·부분·오답·보류, 핵심 사실·근거 충족률, 주요 오류, 답변 없음. 보류가 있으면 전체 정답률과 정확도 차이는 미확정으로 유지한다.
3. **토큰:** 전체·입력·출력·캐시·비캐시·추론·캐시 쓰기, 모델 응답 수, 응답당 토큰과 최대 단일 응답 입력. 캐시를 이중 합산하지 않는다.
4. **호출·탐색:** MCP 요청과 exec/wait를 구분하고, 도구별 성공·오류·취소, 반복 요청·중복 읽기·빈 검색·읽은 파일·범위 선택을 보고한다.
5. **출력·근거:** 원출력·중계·실제 모델 전달량, 귀속 가능 범위·잘림, 최초 필수 근거 도달 시간·단계와 근거 노출의 분석 한계를 보고한다.
6. **시간:** 전체 실행, 도구 응답 시간 합·구간 합집합·잔여 구간, 기동 이후 첫 요청, 복제·색인·정리·채점 비용을 분리한다. 잔여 구간을 순수 모델 추론 시간이라고 부르지 않는다.
7. **분포·하위 집단:** 평균·중앙값·p95·최소·최대·표본 표준편차·의미 있는 합계·유효 N/예정 N, 도구별·응답별·난도별·언어별·질문별 모든 값을 표시한다.
8. **비교·불확실성:** 절대 차이·상대 변화·사전 방법의 신뢰구간, 기준값 0·결측 처리, 분자·분모 합의 비율과 문제별 비율 평균, 공통 정답 문제의 보조 비용을 구분한다. 부분집합으로 전체 분모를 바꾸지 않는다.
9. **신뢰성·제한:** 사용량 정합성·기록 수집·경계 위반·한도 감지·초과량·종료 상태·늦은 도구 결과·채점 검증 상태를 모두 남긴다.
10. **제품 지표와 공백:** 설명 크기·색인 크기·기능 이용·직접 고정 질의 재생을 별도로 다룬다. CPU/RSS/입출력/갱신 지연/Precision·Recall·MRR·nDCG처럼 계측하지 않은 항목도 목록과 이유를 남긴다.

관측 부분의 평균이나 비율은 유효 표본 수와 함께 표시하며 전체 성능으로 대체하지 않는다. 실제 질의가 달라진 도구 지연을 동일 작업량의 엔진 성능으로 비교하지 않는다. 설명 문자열 길이와 전체 토큰 비용, 구현 검사 통과와 제품 성능 개선을 구분한다.

## 변경·검증·보존

- 하나의 가설을 확인할 수 있게 변경을 분리한다. 관측된 Grafana 문제명·저장소명·정답 심볼을 제품 분기 조건에 넣지 않는다.
- 도구 기능·인자 계약·기본값·출력 상한·권한·범위 선택을 변경한 경우 영향과 적용 버전을 밝힌다. 평가 대상 제품 개선과 하네스 변경을 같은 효과로 합산하지 않는다.
- 실행·채점 횟수와 재실행 규칙을 사전에 고정하고, 실패·한도 종료·불리한 결과를 지우거나 자동으로 재실행해 대체하지 않는다.
- 채점 계약을 위반한 묶음은 점수 집계에서 보류한다. 사후 인용문 수정·조건 완화로 통과시키지 않는다. 채점 절차를 바꾸려면 새 고정 계약으로 구분하고 과거 점수를 보존한다.
- 원자료·답변·질의·실행 설정·스냅샷·해시를 보존한다. 보고서는 Markdown, 전체 값은 JSON, 지표 정의는 별도 등록부로 남긴다. 기존 입력 수치와의 일치 및 보고서 재생성 해시를 확인한다.
- 새 측정 없이 계산 가능한 지표는 기존 기록에서 산출한다. 관측으로 복원할 수 없는 수치는 추정으로 채우지 않는다. 추가 실행은 사용자가 요청한 범위 안에서 진행한다.
