# 범용 MCP 정식 평가 계약

**과거 계약 보존:** `formal-r1`은 완료된 실행의 재현 자료다. 확인된 평가 오류와 판정 보류 때문에 현재 제품 개선 판정에 이 점수를 사용하지 않는다. 아래 명령은 당시 절차이며 새 실행 지시가 아니다. 당시 하네스·소스·봉인을 사용해야 하며, 현재 실행기로 과거 결과를 덮어쓰지 않는다. [현재 평가 기준](../../../REPORTING.md)

이 평가는 고정된 개선 제품과 기본 파일 탐색을 비교하는 120회 평가다. Grafana에서 관측한 준비 실험의 개선이 다른 저장소에서도 유지되는지 확인한다. 제품 변경 전후를 직접 비교하는 실험은 아니며, 제품 이전 버전은 정식 평가 집단에 포함하지 않는다.

## 표본과 고정 조건

- 최종 저장소: Django(Python), Kubernetes API(Go), Axum(Rust), Vite(TypeScript), Gson(Java), fmt(C++).
- 저장소당 5문제, 전체 30문제. 단순·중간·복잡 각 10문제, 필수 사실 총 70개.
- A/B 각 2회: 120회. A는 `rg`, `grep`, `find`, `read`, B는 고정된 codemap-search의 6개 도구를 사용한다.
- 실행: Codex `0.153.4`, Luna medium. 채점: Astra low. 기존 V2의 채점 지시와 구조화 출력 계약을 유지한다.
- 제한: 실행당 300초·탐색 호출 80회·캐시를 포함한 입력+출력 500,000토큰. 최대 동시 실행 2개, 시드 20260907.
- 고정 제품: 저장소 커밋 `9231c2409`에서 `apps/codemap-search`를 추출해 빌드했다. 검색 동작 변경은 `f07296b4a`에 들어 있다. 정확한 커밋·트리·바이너리 해시는 실행 디렉터리의 `product/build.json`에 기록한다.

`dataset.json`은 각 질문의 고정 저장소 커밋, 요청, 필수 사실, 오해 사례, 코드 근거와 행 번호, 정답·대체 표현·부분 답변·오답 대조 사례를 포함한다. `build_dataset.py`는 이 원문 계약을 고정 소스에서 재구성한다. 문제는 PR에서 무작위 추출하지 않고 고정 코드를 읽어 목적 표집했다. 이전 Grafana 문제와 결과는 합산하지 않는다.

최초 Go 후보는 client-go였다. 최종 실행 전 파일 목록을 확인했을 때 최초 6개 저장소 모두 제품의 생성·자원 경로 감점 정규식에 해당하는 파일이 없어 Kubernetes API로 교체했다. 교체 결정은 정식 답변을 보기 전에 이뤄졌고, 생성된 `generated.pb.go`가 정답 근거인 문제 2개를 포함했다. 최초 계약은 `dataset-initial.json`에 보존한다. `resource-primary`는 자원 내용이 정답인 질문이고, `auxiliary-path-primary`는 실제 제품 감점 경로에 해당하는 질문이다. 두 범주는 다르다.

## 실행과 판정

사전 채점에서는 질문당 4개 대조 답안의 사실별 판정과 주요 오류 유무를 검증한다. 최초 후보 집합의 사전 채점 자료를 보존하고, 계약이 동일한 25문제의 기록은 재사용한다. 추가 Go 5문제만 새로 사전 채점하며 실패 기록을 자동 재시도하지 않는다. 런타임 검사 A/B 2회와 사전 채점·정식 채점 비용은 120회 평가 비용과 별도 기록한다.

제품과 소스 색인, 질문·정답 계약, 실행 코드 및 채점 지시를 `frozen.json`으로 동결한다. 매 실행은 동일한 고정 소스·색인의 새 복제본을 사용한다. A/B 시작 순서는 시드로 정하고 2회차에 뒤집는다. 서로 다른 문제 쌍만 겹쳐 실행하며 한 쌍의 A/B는 순차 실행한다. 실패·한도 종료를 분모에서 삭제하거나 자동 재실행하지 않는다.

정식 120회가 모두 종료한 뒤 질문별 실제 답변 4개와 대조 답안 4개를 섞어 채점한다. 채점자는 집단·호출·토큰·시간을 받지 않는다. 실제 답변 경로의 실행 식별자는 익명화하고, 최종 판정의 인용은 원문에 다시 대조한다. 채점 실패가 생겨도 정식 답변을 본 뒤 채점 지시나 정답 계약을 조정하지 않는다.

필수 사실이 모두 정확하고 답변에 근거가 있으며 주요 오류가 없어야 완전 정답이다. 조건 확인 실패나 채점 결측은 오답으로 바꾸지 않고 결측으로 남긴다. 전체 비용은 정상 완료와 기록 완전성을 확인한 실행만 확정하며, 종료 신호만으로 처리 중인 요청의 비용까지 확보됐다고 간주하지 않는다.

## 집계와 해석 범위

문제 내 반복 평균을 먼저 구하고 문제와 저장소에 같은 비중을 둔다. 주요 지표는 완전 정답률, 캐시 포함 전체 토큰, 탐색 호출, 시간이다. 저장소별·언어별·난도별·사례 유형별 결과와 모든 실제 답변을 보존한다. 결측이 있으면 전체 합계를 임의 추정하지 않고 관측 부분합과 결측 사유를 함께 기록한다.

95% 구간은 저장소를 재표집하고 그 안의 문제를 재표집하는 10,000회 계층 부트스트랩으로 계산한다. A/B와 2회 반복은 묶어서 유지한다. 저장소가 6개뿐이고 언어당 저장소가 하나이므로 언어 효과와 저장소 효과를 분리할 수 없다. 이 저장소들은 이번 Grafana 기반 제품 조정에 쓰이지 않았지만, 모델 학습 자료에 포함됐는지는 알 수 없다. 목적 표본의 결과를 모든 저장소에서의 보장으로 해석하지 않는다.

실행 하네스의 완전성과 제품 정확도·효율의 결과는 별도로 결론 낸다. 생성 경로 2문제의 결과도 모든 자동 생성·자원 경로에 대한 포괄적 검증을 뜻하지 않는다.

## 실행 자료

작업 디렉터리는 저장소 루트다. 새 경로는 기존 V2 CLI와 준비 실험 파일을 변경하지 않는다.

```sh
python3 -m benchmark.v2.formal validate --experiment benchmark/v2/artifacts/formal-r1
python3 -m benchmark.v2.formal prepare --experiment benchmark/v2/artifacts/formal-r1
python3 -m benchmark.v2.formal calibrate --experiment benchmark/v2/artifacts/formal-r1
python3 -m benchmark.v2.formal freeze --experiment benchmark/v2/artifacts/formal-r1
python3 -m benchmark.v2.formal run --experiment benchmark/v2/artifacts/formal-r1
python3 -m benchmark.v2.formal grade --experiment benchmark/v2/artifacts/formal-r1
python3 -m benchmark.v2.formal report --experiment benchmark/v2/artifacts/formal-r1
```

원자료와 실행별 해시는 `benchmark/v2/artifacts/formal-r1/`, 자동 집계는 그 아래 `report/summary.json`, 실제 답변과 판정은 `report/report.md`에 저장한다. 비용과 결론을 포함한 해설 보고서는 완료 후 해당 실행 자료와 함께 작성한다.
