# Grafana 기능 경로 3문항 고정 계약

codemap-search 1.0.0 벤치마크에 사용할 문항 내용을 2026-10-03 사용자 요청으로 고정했다. 식별자는 `grafana-routes-v1`, 개정 번호는 `1`, 상태는 `content_frozen`이다. Grafana 기준 소스는 `grafana/grafana`의 `c6fad8695a96577eb466d425e6ac4a759ca30f47`이다.

| 문항 ID | 난도 | 고정 질문 | 필수 핵심 | 확장 진단 |
| --- | --- | --- | ---: | ---: |
| `route-star` | 쉬움 | 대시보드 상단의 즐겨찾기를 추가하거나 해제할 때 화면과 서버가 연결되는 구간 다 확인해줘. | 6 | 2 |
| `route-save-existing` | 보통 | 기존 일반 대시보드를 수정해서 저장할 때 화면과 서버가 연결되는 구간 다 확인해줘. | 7 | 3 |
| `route-live-receive` | 어려움 | TestData의 Grafana Live 스트림을 구독하고 데이터를 받는 구간 다 확인해줘. | 8 | 3 |

세 문항 모두 TypeScript와 Go의 연결을 평가한다. 난도는 정적 경로 구조에 따른 분류이며 실제 LLM 풀이로 검증한 난도는 아니다. 핵심 21개는 필수 정답, 확장 8개는 별도 진단으로 고정한다.

## 고정 파일

| 파일 | 역할 |
| --- | --- |
| [questions.json](questions.json) | 풀이용 문항 ID와 질문 원문. 정답·근거·검색 경로를 포함하지 않는다. |
| [dataset.json](dataset.json) | 순서, 난도, 언어, 범위, 언어 간 연결, 핵심·확장 사실과 오해 사례. |
| [evidence.json](evidence.json) | 고정 소스 파일 81개의 해시와 근거 60개 범위의 원문·행 번호·해시·원본 링크. |
| [grading.json](grading.json) | 핵심 정답과 근거 충족, 확장 진단, 판정 보류, 대체 근거 처리 계약. |
| [manifest.json](manifest.json) | 동결 식별 정보, 파일별 SHA-256, 개수, 검증 범위와 실행기 연결 상태. |
| [SHA256SUMS](SHA256SUMS) | manifest를 포함한 고정 파일의 SHA-256 목록. |

## 문항 범위

- **즐겨찾기:** 저장된 대시보드의 상단 버튼에서 시작해 요청, 서버 변경, 버튼·메뉴 상태 반영까지 확인한다. 폴더 즐겨찾기나 다른 화면의 진입점을 필수 범위로 넓히지 않는다.
- **저장:** 프로비저닝·Git 관리·템플릿이 아닌 기존 일반 대시보드의 저장을 다룬다. 수정 모델, V1/V2 선택, HTTP 요청, 서버 저장 처리, 응답의 최종 적용을 연결한다. 신규 생성·복사·import·복원은 별도 문항으로 확대하지 않는다.
- **Live:** Grafana Live 편집기에서 선택하는 내장 TestData 랜덤 채널의 구독·생산·수신·정리를 다룬다. 브라우저 생성 스트림, simulation 전용 구현, 사용자 지정 pipeline 상세 처리와 외부 SceneQueryRunner의 패널 렌더링은 필수 범위에 넣지 않는다. 관련 우회 분기는 구분한다.

서버 저장소와 Live 처리 규칙에 따른 조건을 그대로 보존한다. 모든 설치가 같은 SQL 저장소를 쓰거나 모든 프레임이 같은 발행 경로를 거친다고 가정하지 않는다. 원문에서 확인한 정적 연결을 실제 서버 실행 관측으로 바꾸어 설명하지 않는다.

## 채점 계약

핵심 사실은 설명의 정확성(`correct`)과 답변에 제시한 원문의 입증 여부(`supported`)를 각각 판정한다. 문항의 모든 핵심 사실이 두 조건을 충족하고 핵심 경로와 모순되는 주장이 없어야 핵심 완전 충족이다. Go와 TypeScript 파일을 각각 찾은 것만으로 연결을 인정하지 않고 URL·식별자·메시지 계약의 대응도 확인한다.

확장 사실의 누락·오답·근거 부족은 별도 진단으로 기록하며 핵심 사실의 분모나 핵심 완전 충족률에 합산하지 않는다. 확장 설명이 핵심 사실 자체와 모순되면 해당 핵심 사실도 독립적으로 판정한다. 원문 검증이 불가능한 항목은 사유와 함께 보류하며 오답이나 0점으로 치환하지 않는다.

풀이 모델에는 `questions.json`의 질문과 동일 조건의 공통 실행 안내만 전달한다. 나머지 파일은 채점·검증용으로 보관하고 풀이 대상 Grafana 작업 공간에 정답 자료를 복사하지 않는다. 대체 인용과 동등한 설명을 허용하며 특정 파일 순서나 탐색 전략을 강제하지 않는다.

## 검증과 보존

다운로드한 81개 파일의 원본 바이트를 해당 Git 커밋의 blob SHA-1과 대조했다. 60개 근거의 행 범위와 원문 SHA-256, 문항별 참조와 핵심·확장 개수를 확인했다. LLM 풀이·채점, 실제 Grafana 서버 시나리오와 난도 실측은 수행하지 않았다.

저장소 루트에서 다음과 같이 무결성을 확인한다.

```sh
cd benchmark/data/grafana-routes-v1
shasum -a 256 -c SHA256SUMS
```

`evidence.json`의 파일 해시는 원본 바이트 기준이다. 근거 해시는 원문의 `splitlines()` 결과에서 지정한 1-based 양끝 포함 범위를 골라 LF로 결합한 UTF-8 텍스트 기준이며 마지막 LF는 붙이지 않는다. 원문과 해시를 함께 보존했으므로 이전 분석의 `/tmp` 파일은 이 계약을 읽는 데 필요하지 않다.

질문·사실·범위·채점 의미를 바꿀 때는 이 고정본을 덮어쓰지 않고 변경 이유를 기록한 새 개정으로 만든다. 과거 30문항의 결과·점수는 이 세 문항의 기준값으로 재사용하지 않는다.

## 실행기 연결 상태

이번 고정 대상은 **문항 내용과 채점 계약**이다. 현재 `benchmark/settings.py`와 `benchmark/data/profiles.json`은 기존 `benchmark/v2/data/dataset.json`의 30문항 계약을 읽는다. `pnpm bench:ready`와 `pnpm bench:start`는 아직 이 고정본을 사용하지 않는다.

새 실행기의 3문항·복수 언어·핵심/확장 구분 지원, 채점 대조 자료, 단계별 프로파일, 모델·반복수·한도·일정·집계 방식과 제품·색인 식별 정보는 실행 계약에서 별도로 고정해야 한다. 기존 3/10/30문항 단계나 반복수를 이 고정본에 자동 적용하지 않는다. 현재 상태는 `manifest.json`의 `execution_contract`에 기록한다.
