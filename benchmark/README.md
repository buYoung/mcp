# Grafana 벤치마크 실행

저장소 루트에서 `pnpm bench:ready`로 준비하고 `pnpm bench:start`에서 평가 유형과 비교 대상을 선택한다. 정식 대상은 **Grafana만**이다. 현재 제품은 **B-4 + grep/read 멤버 범위·둘 다 + 하위 폴더 범위 보존·정규식 안내**이며, 현재 작업 파일의 미커밋 변경도 평가 소스에 포함한다.

## 준비

macOS/Linux, Python 3.12 이상, Node 20.17+ 또는 22.13+ 또는 24+, pnpm, Git, Rust/Cargo, `rg`, `grep`, `find`, Codex와 정상적인 Codex 로그인이 필요하다. 최초 준비에는 Grafana와 Rust 의존성을 받을 네트워크 연결이 필요하다. Codex 버전은 고정하지 않는다.

```sh
pnpm install
pnpm bench:ready
```

준비 명령은 Grafana 커밋 `c6fad8695a96577eb466d425e6ac4a759ca30f47`을 준비하고 고정 문항의 근거 원문을 검증한다. 현재 제품 소스를 별도로 복사해 release 빌드하고 Grafana 색인을 생성한다. 소스·바이너리·색인 해시가 같은 완료 캐시는 재사용한다. 모델 풀이·채점은 실행하지 않는다.

`벤치 준비 완료`가 출력되면 실행할 수 있다. 기존 Grafana 복제본의 커밋이 다르거나 추적 파일이 변경돼 있으면 덮어쓰지 않고 중단한다. 실패한 빌드·색인 캐시는 다음 준비에서 `.incomplete-*`로 보존한 뒤 다시 준비한다.

## 실행

```sh
pnpm bench:start
```

1. 미완료 실행이 있으면 새 실행 또는 이어하기를 선택한다.
2. 평가 유형을 선택한다. 문항은 [고정 프로파일](data/profiles.json)에 등록된 ID로 정해진다.
3. A·현재 버전·등록 후보 중 비교 대상을 복수 선택한다. Space로 선택하고 Enter로 확정한다. 기본 선택은 A와 현재 버전이다.
4. 같은 조건의 A 풀이가 있으면 새 측정 또는 재사용을 선택한다. 재사용한 답변도 이번 비교의 답변들과 함께 익명 채점한다.
5. 준비된 제품 식별 정보, 횟수, 모델, 한도, 저장 위치를 확인하고 실행을 승인한다. **Enter만 누르면 실행하지 않는다.**

| 평가 유형 | 문항 | 문항별 반복 | 대상당 풀이 | A+현재 모두 새 측정 |
|---|---:|---:|---:|---:|
| 후보군 탐색 | 3 | 3 | 9 | 18 |
| 오류 검증 | 10 | 1 | 10 | 20 |
| 정식 벤치 | 30 | 2 | 60 | 120 |

후보 3문항은 `navigation-flow-screen-r2`, 오류 검증 10문항은 `candidate-retry-r1`에서 사용한 기존 문항이다. **후보 ⊂ 오류 검증 ⊂ 정식 30문항**이며 질문·사실·정답·대조 사례 객체를 다시 작성하지 않는다. 과거 준비 6문항은 이 프로파일에 포함하지 않는다. CUI에서는 개별 문항을 선택하지 않는다.

기본 풀이 모델은 `gpt-5.6-luna / medium`, 채점은 `gpt-6-astra / high`다. 실행당 300초·탐색 80회·입력+출력 500,000토큰, 동시 실행 2개를 적용한다. 질문·반복별 대상 실행은 순차로 진행하고, 서로 다른 질문 묶음은 겹칠 수 있다. 순서는 시드와 함께 저장한다.

실행 확인 후 예정 목록을 동결하고 풀이 → 채점 → 결과표를 생성한다. 실제 모델 비용이 발생한다. 파이프 입력·비대화형 터미널·자동 응답 인자를 허용하지 않으며 `CI=true`도 사용자 선택을 대신하지 않는다.

## 모델과 후보 등록

[config.json](config.json)에서 모델·추론 강도·한도·동시 실행 수·시드·후보 목록을 설정한다. 평가 유형의 문항 수와 반복 수는 위 고정 프로파일을 사용한다. 후보가 없으면 A와 현재 버전만 표시된다.

`candidates`에는 아래처럼 등록한다. `path`와 `git_ref`는 하나만 사용한다.

```json
[
  {"id": "local_candidate", "name": "로컬 후보", "path": "../codemap-candidate"},
  {"id": "commit_candidate", "name": "커밋 후보", "git_ref": "candidate-branch"}
]
```

`path`는 저장소 루트 기준 또는 절대 경로이며 `Cargo.toml`과 `Cargo.lock`이 있는 독립 `codemap-search` crate를 가리킨다. `git_ref`는 이 저장소의 참조이며 해당 커밋의 `apps/codemap-search`를 추출한다. 로컬 소스는 추적 파일의 수정·삭제와 무시되지 않은 새 파일을 포함하고 빌드 캐시는 제외한다. 과거 B-6 등은 자동으로 등록하지 않는다.

`bench:ready`는 현재 제품을 준비하며, 후보는 CUI에서 선택할 때 필요한 것만 준비한다. 각 대상은 커밋 ID·미커밋 상태·실제 소스 해시·바이너리 해시를 별도로 기록한다. 기존 `apps/codemap-search/target/release` 바이너리를 평가용 제품으로 대신 사용하지 않는다.

## 취소·재개·결과 해석

Ctrl+C는 새 풀이 예약을 중단하고 실행기가 시작한 Codex·MCP 프로세스를 정리한다. 완료 결과를 보존하고, `pnpm bench:start`에서 **미실행 항목**을 이어갈 수 있다. 시작한 실패·중단 세션은 자동 재실행하지 않는다. 종료 로그가 남은 미완료 후처리는 원자료에서 복구한다.

하네스나 실행 설정이 바뀌면 기존 실행을 보존하고 새 실행을 시작한다. Codex 버전 변경만으로 새 실행이나 재개를 막지 않으며 실제 버전을 세션마다 기록한다. 필요한 CLI 옵션 또는 로그 계약이 지원되지 않으면 오류와 원자료를 남긴다. 버전이 섞인 결과는 같은 조건의 비교로 해석하지 않는다.

A 재사용은 Grafana 소스·문항·반복·모델·한도·프롬프트·도구·하네스·실제 Codex 버전이 같은 완결된 풀이만 제시한다. 실행 조건이나 사용량이 불완전한 A는 자동 재사용하지 않는다. 이전 다중 저장소 [A 고정 결과표](results/formal-r1/A.md)는 영구 보존할 과거 기록이며 Grafana 정식 기준값이 아니다.

원자료는 `benchmark/runs/<실행 ID>/`에 저장한다. 종료 시 출력되는 `report/results.md`에서 결과표를, `report/summary.json`에서 실행별·대상별 지표와 결측 사유를 확인한다. `manifest.json`은 실행 조건, `schedule.json`은 전체 예정 목록, `runs/`는 풀이 기록, `grading/`은 익명 입력·실제 채점·고정 대조 검증을 담는다.

사용량은 응답 ID별 기록과 누적·종료 기록을 대조한다. 제한 감지 후 최대 30초 동안 사용량 회수를 기다리되 신규 탐색은 차단하고, 제한 뒤 답변은 평가에서 제외한다. 사용자 취소는 이 대기를 건너뛴다. 미확정 비용을 0으로 채우거나 실패한 풀이를 분모에서 빼지 않는다. 후보 탐색·오류 검증 결과를 정식 결과나 일반적인 인과관계 증명으로 승격하지 않는다.

## 채점과 검토가 필요한 경우

승인된 [A 도구 안내](data/a-tools.json), Markdown 표시 범위와 이동 앵커의 구분, 원래 답변 줄 ID로 정확한 인용문 복원, 절대 경로 익명화, 대체 인용 원문 수집을 공통 하네스에 포함한다. 채점은 한 문항의 실제 답변 최대 5개와 기존 대조 사례 4개씩 묶는다. 160 KiB를 넘으면 모델 시작 전에 답변 묶음을 나눈다.

채점 보조 원문은 고정 근거 범위와 답변이 실제로 인용한 범위 및 앞뒤 6행을 포함한다. 다른 파일에서 찾은 대체 인용도 포함한다. 파일 전체를 붙일 때 일부 정식 문항이 한도를 넘는 문제를 방지한 방식이며, 주변 문맥을 답변의 인용 범위로 확대하지 않는다. 질문·정답·원답변은 보존한다.

익명화 경고가 발생하면 `grading/review-required.json`을 남기고 채점을 멈춘다. 비용·후보 정보를 누설하는지 원래 답변을 검토한다. 경고가 평가와 무관한 표현임을 확인한 경우에만 같은 폴더의 `review-resolutions.json`에 실행 ID별로 아래 형식의 근거를 기록하고 이어간다.

```json
{
  "경고에 표시된 실행 ID": {
    "answer_sha256": "경고에 표시된 원답변 해시",
    "decision": "allow",
    "reason": "실제 검토한 표현과 집단·비용 정보 누설이 아니라는 근거"
  }
}
```

누설이 확인되면 승인으로 덮지 않는다. 원자료를 보존하고 마스킹 규칙을 수정해 별도 채점 조건으로 다뤄야 한다. 대조 판정 실패·참조 오류·지원하지 않는 로그는 불완전 상태와 사유를 남긴다. 원답변을 고치거나 모델을 자동 재실행하지 않는다.

## 보관과 정리

- `benchmark/.cache/`: 다시 만들 수 있는 소스 복제본·제품 빌드·색인·미확정 실행 준비 정보. 기존 실행을 이어가거나 근거를 재검증할 때는 해당 캐시를 유지한다.
- `benchmark/runs/`: 원자료와 사용량·채점 근거. A 재사용이 참조하는 이전 실행까지 함께 보존한다.
- `benchmark/results/`: 계속 유지할 고정 결과표. 과거 수치를 새 결과로 덮어쓰지 않는다.

새 벤치는 과거 tmp·실험 보관본을 요구하지 않는다. 기존 결과 문서·고정 A 표·원본 문항은 유지한다. 과거 원자료의 재채점·로그 재집계는 지원하지 않는다.

## 구현 검증

저장소 루트에서 다음 명령을 실행한다. 임시 Codex 대역과 실제 Inquirer 터미널을 사용하며 실제 모델 풀이·채점은 실행하지 않는다.

```sh
python3 -m unittest benchmark.v2.checks benchmark.checks benchmark.cui_checks
```

제품의 기능·성능 검증과 하네스의 오프라인 검증은 구분한다. 실제 모델의 새 버전에서 모든 로그·도구 경계가 유지되는지는 사용자가 실행한 벤치의 기록으로 확인한다.

2026-09-10 구현 검증: 자동 사례 54개 통과, 실제 현재 제품 release 빌드·색인 및 캐시 재사용, 직접 MCP 도구 목록·심볼 우선 출력 확인. 과거 실험 경로를 옮긴 뒤에도 준비와 자동 검증이 통과했다. [상세 기록](verification.json).
