# codemap-search 1.0.0 벤치마크

같은 에이전트·문항·예산에서 **코드 검색 도구별 최종 답변 품질과 탐색 비용**을 비교한다. 에이전트는 도구를 사용하는 공통 사용자이며, 답변 작성 능력의 영향은 공통 사용 조건으로 허용한다. 도구 선택과 호출 순서는 LLM에 맡기고 근거 단계별 분리 집계를 필수로 요구하지 않는다.

현재 하네스는 **Grafana 3문항 × 6개 비교군 × 문항별 1회 = 18회 예정**인 `grafana-routes` 하나만 지원한다. 설치·색인·중립 조회·채점 및 측정 계약·풀이 입력을 준비한 뒤 `prepared_not_executed`에서 종료한다. 실제 18회 풀이·채점 실행 흐름 연결은 별도 작업이다.

## 준비 절차

현재 등록된 공식 바이너리 조합은 macOS arm64용이다. Python 3.12 이상, Node 22.13+ 또는 24.x, pnpm, npm, uv, Git, Rust/Cargo, Codex와 정상 로그인 상태가 필요하다. 최초 준비는 고정 소스·패키지·로컬 임베딩 가중치를 내려받는다. 개인 MCP 설정이나 전역 도구 설치는 바꾸지 않는다.

모든 명령은 저장소 루트에서 실행한다. CUI 의존성이 없다면 먼저 `pnpm install`을 실행한다.

```sh
pnpm bench:ready
```

입력 해시 확인 → 도구 설치·빌드 → 전체 Grafana 소스 대조 → 제품별 색인 → 중립 조회·종료·상태 복원 → 채점·측정 계약 확인 → 기존 오프라인 검증 → 18개 풀이 입력과 미실행 계획 생성을 수행한다. 제품 도구의 로컬 임베딩 계산은 포함하며 풀이·채점 LLM은 호출하지 않는다.

완료 후 현재 파일과 준비 기록을 대조한다.

```sh
python3 -m benchmark.route_prepare verify
```

성공 결과는 `prepared_not_executed: <계획 ID>`다. [최종 준비 기록](../docs/briefs/evidence/bench-ready/07-readiness.json)의 `technical_ready`가 true이고 `solver_runs`, `grader_runs`, `calibration_runs`가 모두 0인지 확인한다. 같은 계획의 `benchmark/.cache/route-preparation/plans/<계획 ID>/`에 풀이 입력과 미실행 결과표가 저장된다.

준비 CUI는 다음 명령으로 연다.

```sh
pnpm bench:start
```

유일한 Grafana 프로필을 선택하면 6개 비교군 모두를 준비하고 종료한다. 실제 풀이를 시작하거나 과거 답변을 재사용하는 메뉴는 없다. Ctrl+C로 준비를 취소할 수 있으며, 다시 준비할 때 검증된 설치물과 색인을 재사용한다.

## 도구와 측정 정책

- 제품 응답의 기본값을 유지한다. 하네스의 공통 바이트·행 제한, 자동 페이지 조회·요약·보충, 경쟁 도구의 예산 증가는 없다. codemap-search의 100000 설정도 각 설정의 단위를 따르며 공통 토큰 한도로 바꾸지 않는다.
- 제품 자체 도구를 우선한다. Graphify에는 원문 본문 조회를 위해 `read`만 보조로 제공한다. zvec-grep의 후속 grep/rg 안내는 보조 도구 추가 사유로 쓰지 않는다. 낮은 품질이나 짧은 응답으로 보조 도구를 늘리지 않는다.
- `plain rg`는 추가 검색 제품이 없는 기본 에이전트다. 전용 rg MCP 없이 기본 셸·파일 탐색을 제공하고, 명령 PATH에서 고정 rg가 우선한다. 셸·code mode·출력 기본값을 유지한다. [Codex 권한 프로필](https://learn.chatgpt.com/docs/permissions)로 Grafana와 최소 실행 경로만 읽도록 제한하고 정답·보고서 읽기와 소스 쓰기를 차단한다.
- 검색·색인은 로컬 조건이다. Jev는 비활성, Graphify는 빈 출력 디렉터리에서 코드 전용 추출, zvec는 고정 리비전의 `local/potion-code-16m-v2`를 사용한다. 제품의 제외 규칙과 선택적 파서 누락은 그대로 기록한다.
- 22,898개 추적 파일과 생성된 TypeScript·JSON을 동일하게 제공한다. 문항마다 같은 절대 경로에 조회 전 상태를 복원하도록 준비한다. OS 페이지 캐시는 통제하지 않는다.
- 제품군은 MCP 호출, 기본 에이전트는 `command_execution`의 고유 item ID를 탐색 호출로 센다. 한 셸 명령 안의 여러 명령은 한 호출이며 started/completed를 중복 집계하지 않는다. 관측 시점에 한도를 집행하고 동시 호출의 초과량과 조건 위반을 기록한다.
- 제품 원본 응답·중계 응답·실제 모델 전달 관측을 구분한다. CLI 출력만으로 모델이 모두 읽었다고 간주하지 않는다. 토큰·시간·호출·오류는 관측한 값과 원자료 경로를 남기며 미관측 값을 0으로 채우지 않는다.
- 최종 답변을 고정 rubric으로 채점한다. 인용 파서는 보조 정보이며 특정 형식이나 파싱 성공으로 `supported`를 강제하지 않는다. 확장·비채점 참고 사항을 핵심 필수 항목으로 바꾸지 않는다.
- 도구·모델 식별 노출은 채점 입력 확정 전에 차단하고 원답변과 정확한 구간을 검토 기록에 남긴다. 실행 조건 무효, 실패 사유, 호출 로그 불완전도 결과에서 보존한다. 1회 측정으로 반복 분산이나 통계적 유의성을 주장하지 않는다.

## 기록과 재검증

[준비 브리프셋](../docs/briefs/2026-10-03-briefset-bench-ready.md)과 `docs/briefs/evidence/bench-ready/`에 현재 준비 작업·검증 근거를 보존한다. `benchmark/.cache/route-preparation/`에는 소스, 설치물, 색인, 복원본, 원본 조회 로그가 있다. 준비 기록의 해시를 재검증할 때 이 캐시가 필요하며 바이너리·가중치·색인 캐시는 커밋에 넣지 않는다.

중립 조회는 당시 코드·명령·환경·권한·Codex 버전·노출 도구 구성이 현재와 일치할 때만 재사용한다. 변경 시 조회 전 상태로 복원한 뒤 다시 점검하며, 준비 중 코드가 바뀌어도 완료 처리를 막는다. 제품 소스 바이트가 같으면 고정된 빌드의 출처를 새 Git HEAD로 다시 표시하지 않는다.

해시 불일치나 설치 실패가 생기면 출력된 작업 전용 로그에서 원인을 확인한다. 다른 버전으로 자동 대체하거나 필수 비교군을 제외하지 않는다. 입력이나 색인이 변경된 경우 해당 준비 상태를 새로 만들어야 하며, 개인 데몬을 종료해 충돌을 해결하지 않는다.

현재 데이터셋 manifest와 비교 대상 잠금의 과거 연결 상태·초기 개정 경로는 동결 당시의 출처 기록이다. 현재 실행 의존성이 아니다. 현재 조건은 실행 계약과 최종 준비 기록을 따른다.

## 하네스 검증과 실제 실행 경계

```sh
python3 -m unittest benchmark.checks benchmark.cui_checks
node --check benchmark/start.mjs
```

기존 실행·사용량·취소·응답 처리 검증과 실제 Inquirer 터미널 검증을 사용하며 모델 실행은 로컬 대역으로 대체한다. [CUI 점검 기록](../docs/briefs/evidence/bench-ready/07-operator-inspection.json)에는 실제 준비 기록을 사용한 메뉴 흐름과 실행 호출 0회를 남긴다.

실제 18회 실행에는 준비 검증 이후 슬롯별 상태 복원·풀이·수집·익명 채점·결과 집계를 연결하는 작업이 남아 있다. 현재 CLI는 `catalog`와 `prepare`만 제공하며 실행 설정은 준비 전용이다. 계정의 지정 모델 사용 가능 여부, 실제 모델 전달량, 채점 보정, 난도 실측은 아직 확인하지 않았다.
