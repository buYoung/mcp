이 페이지는 **Grafana**(`24,115`개 추적 파일, TypeScript + Go)에서 `codemap-search 0.14.2`를 기본 도구 기준군(`rg 15.2.0`) 및 공개 MCP 코드 탐색 서버 4종(`Graphify 0.9.95`, `zvec-grep 0.2.2`, `codebase-memory-mcp 0.12.1`, `CodeGraph 1.6.2`)과 비교 측정한 정량 결과를 담고 있습니다. 풀이 모델 `gpt-6.1-sol`(`medium`)과 도구·저장소 접근 없이 채점하는 블라인드 채점 모델 `gpt-6-astra`(`high`)를 사용해, 환경·도구마다 다단계 아키텍처 질문 `3`개를 `3`회씩 평가했습니다(환경·도구당 `9`개 답변·행 인용 필수 사실 `108`개, `pi codemode`의 `zvec-grep 0.2.2`만 서버 중단 2건으로 `7`개 답변·`84`개 사실; 전체 유효 답변 **`160`개·채점 사실 `1,920`개**).

표에서 `·`로 구분된 세 값(예: `5/9 · 6/9 · 6/9`, `3·3·2`)은 항상 **`pi direct` · `pi codemode` · `Codex code mode`** 순서입니다. 세 실행 환경은 기본 보조 도구, 출력 길이 제한, 프롬프트·토큰 집계 방식이 서로 다르므로 나란히 적고 **합산하지 않습니다**(예: Codex는 매 턴 더 큰 개발자·코드 모드 프롬프트가 포함되어 총 캐시 입력 토큰이 더 높게 집계됩니다).

아래 관측은 이번 Grafana 저장소 스냅샷, 3개 문항 과제 세트, 고정된 `gpt-6.1-sol`(`medium`) 및 클라이언트·색인 설정에서 확인한 결과입니다.

- **`rg 15.2.0` (기본 도구 기준군) 대비**: `codemap-search 0.14.2`가 세 환경 모두에서 답변당 `+1.00`~`+1.11`개의 사실을 더 충족했고(`p = 0.0250`, `0.0300`, `0.0280`, 보정 없음), 총 토큰은 `1.54×`~`1.71×`(비캐시 토큰 `1.27×`~`1.45×`)를 사용했습니다.
- **`CodeGraph 1.6.2`·`codebase-memory-mcp 0.12.1` 대비**: `codemap-search 0.14.2`가 세 환경 모두에서 답변당 `+1.00`~`+2.00`개를 더 충족하면서(여섯 비교 모두 `p < 0.05`, 보정 없음) 총 토큰은 `0.40×`~`0.73×`(비캐시 토큰 `0.68×`~`1.10×`; `pi direct`에서 `codebase-memory-mcp 0.12.1` 대비 비캐시 토큰은 `98,081` 대 `89,291`로 `1.10×`)였습니다.
- **`Graphify 0.9.95`·`zvec-grep 0.2.2` 대비**: `codemap-search 0.14.2`가 세 환경 모두에서 답변당 `+0.33`~`+1.22`개 높았지만 각 한 환경씩만 `p < 0.05`를 넘었습니다(`Graphify 0.9.95` 대비 `pi codemode` `p = 0.0180`, `zvec-grep 0.2.2` 대비 `Codex` `p = 0.0100`; `n = 9` 표본에서는 판정 보류). 인용 입증을 뺀 단순 `내용 맞음` 합계만 보면 `Graphify 0.9.95`는 `pi direct`에서 `96` 대 `codemap-search 0.14.2` `98`, `pi codemode`에서 `96` 대 `100`, `Codex code mode`에서 `95` 대 `99`였습니다.
- **자체 완결 탐색·비교 MCP 4종 대 `rg 15.2.0`**: `codemap-search 0.14.2`는 전체 답변 `27`개에서 기본·셸 도구 호출 `0`회(서버 안에 `read`, `grep`, `find`를 내장), 테스트·생성 파일 인용 `0`건이었습니다. 비교 MCP 4종 중 어느 환경에서도 `rg 15.2.0`보다 `p < 0.05` 수준으로 더 많은 사실을 충족한 도구는 없었으며, 총 토큰은 `rg 15.2.0` 대비 `1.00×`~`3.82×`(비캐시 `0.92×`~`1.94×`)를 사용했습니다.

## 세부 도구 호출·인용·출력 잘림

- **전달(Dispatched)·거절(Rejected)·오류(Errors)**: `총 호출 = 전달 호출 + 거절`입니다(`답변당 총 호출`·`답변당 전달 호출`은 답변당 평균, `거절 합계`·`오류 합계`는 해당 셀의 전체 합계). `거절`은 `.git` 대상 검색이나 소스 루트 밖 경로 등 읽기 전용 경로 샌드박스 규칙이 실행 전에 막은 호출 수입니다. `오류 ⊂ 전달`은 실제 전달된 호출 중 오류를 반환한 횟수입니다(없는 경로 지정이나 검색 실패 등).
- **보조 `read` (`Graphify 0.9.95`) 대 `zvec-grep 0.2.2`**: `Graphify` 자체 도구 7종이 원문 본문 없이 그래프 엔티티와 위치만 돌려주므로 하네스가 읽기 전용 MCP 보조 `read` 도구를 붙였습니다. 반면 `zvec-grep 0.2.2`는 `zvec_grep_search`가 제한된 원문 발췌를 함께 반환하므로 보조 `read`를 붙이지 않았고, 더 넓은 파일 확인에는 내장 도구나 셸을 사용했습니다.
- **클라이언트 출력 한도·스크립트 잘림·어댑터 잘림**: `기본·CLI 한도 도달 (답변 수)`는 클라이언트 출력 상한에 걸린 횟수입니다(`pi`에서는 내장 `read` `2,000`줄/`50 KiB`, `grep` `100`건, `find` `1,000`건, `ls` `500`건; `Codex code mode`에서는 셸 `exec_command`와 `// @exec: {"max_output_tokens": ...}` 지정이 없을 때 기본 `10,000`토큰 상한이 적용되는 `exec` 코드 모드 셀 양쪽에서 `Codex CLI 0.164.0`이 낸 `Warning: truncated output` 횟수). `스크립트 잘림`(`pi codemode`)은 `codemode` 확장이 기본 `10,000`토큰 상한으로 스크립트 출력을 자른 횟수이며, `어댑터 잘림`(`pi`)은 `@buyong/pi-mcp-adapter 0.1.2`가 직접 MCP 응답을 자른 횟수입니다(기본 `20 KiB`, `codemap-search 0.14.2`는 `_meta["pi/maxOutputBytes"]`로 `100,000`바이트 지정).
- **인용 집계 기준**: 정규화된 검토 인용 색인(검증 통과한 `160`개 답변 원문에서 일관된 규칙으로 추출한 인용 목록)에서 직접 재집계했습니다. `범위 인용`은 여러 줄 `path:시작-끝`(`end > start`) 인용, `한 줄 인용`은 1줄 인용(`path:행` 또는 `start == end`), `테스트·생성 인용`은 테스트 또는 생성 파일을 1건 이상 인용한 답변 수입니다.
