## 측정 조건

읽기 전용 [grafana/grafana](https://github.com/grafana/grafana) TypeScript·Go 저장소에서 `gpt-6.1-sol`(`medium`)으로 다단계 아키텍처 질문 `3`개를 세 클라이언트 환경마다 도구별로 `3`회씩 풀고, 블라인드 채점기가 답변당 필수 사실 `12`개(`Core` `7` + `Extended` `5`) 충족 여부를 채점했습니다.

### 평가 질문과 정답 범위

- **`git-sync-job-dispatch`**
  - **질문**: "메시지 버스 패턴 중 Git 저장소 동기화 작업이 그 작업을 실행하는 처리기까지 전달되는 구간 다 확인해줘."
  - **정답 범위 (`Core` `7` · `Extended` `5`)**: 화면·컨트롤러·웹훅의 동기화 요청이 메모리 큐가 아니라 API 서버의 작업 리소스 생성으로 저장되고, KV 백엔드 커밋 뒤 NATS 변경 알림이 발행되어 작업 인포머 큐 그룹 구독과 드라이버 큐를 거쳐 선점(claim) 후 동기화 처리기로 이어지는 경로입니다. 확장 항목은 구독 실패 시 재조회 단독 시작, 두 실행 호스트 조립, 갱신 알림 중복 적재 방지, 발행 실패 시 쓰기 유지, 선점 재시도·쿨다운을 확인합니다.
- **`alertmanager-config-autosync`**
  - **질문**: "Kubernetes 방식 API 중 외부 Alertmanager 설정을 가져오는 자동 동기화와 연결되는 구간 다 확인해줘."
  - **정답 범위 (`Core` `7` · `Extended` `5`)**: 설정 화면이 싱글턴 설정 리소스를 조회·패치하면 어드미션 검증기가 대상 데이터소스를 확인하고, 주기적 폴링 선처리가 데이터소스 프록시 HTTP로 외부 Alertmanager 설정을 가져와 저장한 뒤 리소스 상태에 동기화 결과를 기록해 화면에 반영하는 경로입니다. 확장 항목은 해시 비교를 통한 변경 시 저장, 해제 시 정리, 동기화 활성 중 수동 가져오기 차단(`409`), 관리 주체 분기, 실패 사유·응답(`404`) 구분을 확인합니다.
- **`scope-annotation-filter`**
  - **질문**: "스코프 필터 중 대시보드 주석 저장·조회와 연결되는 구간 다 확인해줘."
  - **정답 범위 (`Core` `7` · `Extended` `5`)**: 스코프 필터 토글과 대시보드 변수에서 추출한 스코프 이름 목록이 데이터소스 조회, 패널 컨텍스트 생성·수정, 주석 목록 패널 세 진입점을 거쳐 Kubernetes 방식 주석 클라이언트의 조회 쿼리와 요청 본문으로 전달되고, 주석 앱 검색 라우트와 저장소 백엔드별 스코프 필터링까지 이어지는 경로입니다. 확장 항목은 레거시 REST 경로 미전달과 백엔드별 미지원 거부·무시 처리를 확인합니다.

- **`·` 구분 순서**: 세 값은 `pi direct` · `pi codemode` · `Codex code mode` 순서입니다.
- **통계적 유의성 (`p < 0.05`, 문항 층화 순열 검정)**:
  - `codemap-search 0.14.2`는 `3`개 환경 모두에서 `rg 15.2.0`, `CodeGraph 1.6.2`, `codebase-memory-mcp 0.12.1`보다 충족 건수가 유의하게 높았습니다.
  - `Graphify 0.9.95` 대비로는 `pi codemode`에서, `zvec-grep 0.2.2` 대비로는 `Codex code mode`에서 유의하게 높았습니다.
  - 나머지 오픈소스 MCP 서버 `4`종은 어느 환경에서도 `rg 15.2.0`을 유의하게 앞서지 못했습니다(`p >= 0.05`).
- **실행 특이사항**:
  - `codemap-search 0.14.2`만 모든 환경에서 기본·보조 도구 호출(`0.0`)과 테스트·생성 파일 인용 답변(`0`) 없이 자체 MCP 도구만으로 응답했습니다.
  - `*` `pi codemode`의 `zvec-grep 0.2.2`는 한 문항에서 서버 `SIGSEGV` 중단이 두 번 발생해 `9`회 중 `7`회(`71/84`, `84.5%`)만 완료했습니다.

환경별 토큰 분포(중앙값·최소–최대), 쌍별 `p` 값, 문항·세부 항목별 채점표, 하위 도구 호출 상세는 [상세 결과](/ko/benchmarks/details/)에서 확인할 수 있습니다.
