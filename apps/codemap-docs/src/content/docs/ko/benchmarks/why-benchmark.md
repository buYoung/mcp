코딩 에이전트용 코드 탐색 도구는 흔히 특정 심볼 정의 한 개를 찾거나 알려진 식별자를 맞히는 단일 조회 마이크로 벤치마크로 점검합니다. 하지만 실제 에이전트가 처음 보는 저장소를 끝까지 탐색할 때 겪는 실패는 여러 파일·계층·언어를 건너가며 연결을 추적하는 과정에서 나타납니다.

## 왜 행 범위 인용을 요구하는 다단계 문항인가

대규모 코드베이스에서 아키텍처 질문에 답하려면 진입점을 찾고, 패키지나 언어 경계를 넘는 위임 흐름을 따라가며, 설정 조건이나 보조 분기를 확인하고, 이름이나 테스트에서 추측하지 않고 실제 구현 원문으로 근거를 확인해야 합니다.

단일 적중률이 아니라 종단간 탐색 동작을 보기 위해, 이번 측정에서는 모든 주장마다 `path:시작-끝` 행 범위 인용을 요구하는 다단계 아키텍처 문항을 사용했습니다. 채점은 도구나 저장소 접근 없이 동작하는 블라인드 채점 모델(`gpt-6-astra`, 추론 강도 `high`)이 맡았습니다. 설명 내용이 맞더라도 인용한 행 번호 범위가 그 설명을 입증하지 못하면 `충족`이 아니라 `내용 맞음·인용 부족`으로 집계합니다.

## 측정 대상 요약

고정된 읽기 전용 **Grafana** 체크아웃(`24,115`개 추적 파일, TypeScript + Go, 커밋 `c0a598f5a49abf2014f67e806075d8ad267c9efb`, `2026-10-26`)에서 `codemap-search 0.14.2`를 기본 도구 기준군(`rg 15.2.0`) 및 공개 MCP 코드 탐색 서버 4종(`Graphify 0.9.95`, `zvec-grep 0.2.2`, `codebase-memory-mcp 0.12.1`, `CodeGraph 1.6.2`)과 함께 측정했습니다(`Serena 2.1.0`은 전체 LSP 색인이 1회 약 34~70분 걸려 실행 전 제외했습니다).

- **풀이·채점 구성**: 풀이 모델 `gpt-6.1-sol`(추론 강도 `medium`)이 다단계 문항 `3`개를 각 `3`회씩 풀었습니다(도구·환경당 답변 `9`개·사실 `108`개, 단 `pi codemode`의 `zvec-grep 0.2.2`는 서버 중단 2건으로 답변 `7`개·사실 `84`개). 문항당 채점 사실 `12`개(`Core` 필수 종단간 연결 `7`개 + `Extended` 부가 분기·조건 `5`개)를 평가합니다.
- **전체 유효 표본**: 세 실행 환경(`pi direct`, `pi codemode`, `Codex code mode`)에 걸쳐 총 `160`개 유효 답변과 `1,920`개 채점 사실을 평가했으며, 세 환경은 나란히 보고하되 합산하지 않습니다.

## `codemap-search`가 벤치마크를 쓰는 방식

이 측정은 보편적인 성능 홍보가 아니라, 고정 조건에서 탐색·전달 병목을 찾고 수정 전후의 변화를 비교하기 위해 수행했습니다. 따라서 이 문서는 보편적인 속도 우위, 다른 저장소·모델 전반으로 일반화되는 정확도 우위, 또는 내장 파일 읽기·검색 도구보다 무조건 앞선다는 결론을 주장하지 않습니다. 모든 수치는 [측정 방법](/ko/benchmarks/methodology/)에 적은 저장소, 문항, 모델, 고정 도구 버전과 클라이언트 설정 기준에서 관측한 결과입니다.

## 벤치마크 문서 안내

- [측정 방법](/ko/benchmarks/methodology/) — 비교 도구, 고정 커밋, 세 가지 실행 환경, 샌드박스 격리 규칙, 사전 구축 Grafana 색인 규모를 다룹니다.
- [측정 지표](/ko/benchmarks/metrics/) — 충족 사실, 토큰 집계, 호출 결과, 인용 수, 클라이언트 출력 한도와 순열 검정의 정확한 정의를 설명합니다.
- [측정 결과](/ko/benchmarks/results/) — 환경별 요약, 상세 결과표, 문항별 점수, 36개 세부 항목 충족표(`A1–AE5`, `G1–GE5`, `B1–BE5`), 하위 도구 호출·잘림 기록을 제공합니다.
- [벤치마크로 바뀐 것](/ko/benchmarks/what-changed/) — 관측된 병목을 바탕으로 반영한 제품·지침 변경 사항과 남아 있는 GPT 토큰 트레이드오프를 정리합니다.
- [한계와 비주장 범위](/ko/benchmarks/limits/) — 표본 크기, 미보정 `p` 값, 단일 저장소 범위, 도구 조건 차이, 서버 중단과 비주장 범위를 밝힙니다.
- [재현 조건과 참고 사항](/ko/benchmarks/reproduction-notes/) — 고정 커밋, 같은 날 두 배치 실행, 재실행 내역, 하드웨어·캐시 민감도와 공개·비공개 자료 범위를 안내합니다.
