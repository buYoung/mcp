- 모든 저장소·모델에 걸친 보편적인 속도 우위나 비교 도구 대비 전반적인 우위를 주장하지 않습니다.
- 다른 저장소나 모델로 일반화되는 정확도 우위, 또는 내장 `Read`/`Grep`·`rg`보다 무조건 앞선다는 결론을 주장하지 않습니다.
- 호스트 하드웨어, 캐시 상태, 색인 상태, 클라이언트·어댑터 버전을 떠나 조건 없이 항상 그대로 재현된다고 주장하지 않습니다.
- 이번 실행에서 서버 지침만의 단독 인과 효과를 도구 설계의 효과와 분리해 결론 내리지 않습니다.

모든 수치는 **Grafana**(`24,115`개 추적 파일, TypeScript + Go), 다단계 문항 `3`개, `gpt-6.1-sol`(`medium`), `gpt-6-astra`(`high`), 그리고 [측정 방법](/ko/benchmarks/methodology/)에 적은 고정 도구·클라이언트 버전에서 관측한 결과입니다.
:::

## 표본 크기와 미보정 `p` 값

- **작은 표본 변별력(`n = 9`, `pi codemode`의 `zvec-grep 0.2.2`는 `n = 7`)**: 환경·도구당 답변 `9`개 표본에서는 문항 층화 정확 순열 검정이 대체로 답변당 `1`개 안팎 이상의 차이를 가려내며, `0.3–0.8`개 차이는 시행 간 변동 범위 안에 있어 판정을 유보합니다. 예를 들어 `codemap-search 0.14.2`는 `Graphify 0.9.95`·`zvec-grep 0.2.2`보다 `+0.33`~`+1.22`개 높았지만 각 한 환경씩만 `p < 0.05`를 넘었으므로(`Graphify 0.9.95` 대비 `pi codemode` `p = 0.0180`, `zvec-grep 0.2.2` 대비 `Codex code mode` `p = 0.0100`) `n = 9` 표본에서는 판정을 유보합니다.
- **인용 입증 대 단순 `내용 맞음`**: 인용 입증을 제외한 단순 `내용 맞음` 합계로 보면 `Graphify 0.9.95`는 `pi direct`에서 `96` 대 `codemap-search 0.14.2` `98`, `pi codemode`에서 `96` 대 `100`, `Codex code mode`에서 `95` 대 `99`였습니다.
- **미보정 다중 비교**: 보고된 `p` 값은 외부 MCP 비교 `24`개(세 환경 전체 쌍별 비교 `27`개 행)에 대해 다중 비교 보정을 적용하지 않은 값입니다.

## 단일 저장소와 `scope-annotation-filter` 중심 변별

단일 저장소(**Grafana**, `24,115`개 추적 파일, TypeScript + Go)의 문항 `3`개만 측정했습니다. 도구 간 차이 대부분은 `scope-annotation-filter` 문항에서 나왔으며, 이 문항에서 `codemap-search 0.14.2`는 세 환경에서 `33/36`, `32/36`, `33/36`을 기록했습니다(예: 핵심 연결 `B6`에서 `codemap-search 0.14.2`만 `9/9`, 다른 도구는 `0–3/9`, `zvec-grep 0.2.2`는 `1/7`). 반면 `alertmanager-config-autosync`에서는 거의 모든 도구·환경이 `28–30/36`으로 수렴했습니다(`pi direct`의 `CodeGraph 1.6.2`만 `24/36`).

## 단일 풀이 모델

풀이 모델은 `gpt-6.1-sol`(추론 강도 `medium`) 한 종만 측정했습니다. 다른 모델 계열이나 추론 강도에서는 토큰 비율, 프롬프트 캐시 적중률, 인용 습관, 충족 점수가 달라질 수 있습니다.

## 도구 조건 차이와 사전 제외

- **`Graphify 0.9.95` 보조 `read` 대 `zvec-grep 0.2.2` 기본 도구 fallback**: `Graphify` 자체 그래프 도구 7종이 원문 본문 없이 엔티티 메타데이터와 위치만 반환하므로 하네스가 읽기 전용 MCP `read` 보조 도구를 연결했습니다(답변당 `30.6–51.7`회 호출). 반면 `zvec-grep 0.2.2`는 `zvec_grep_search`가 제한된 원문 발췌를 함께 반환하므로 보조 `read`를 붙이지 않았고, 더 넓은 파일을 읽을 때는 내장 도구나 읽기 전용 셸(답변당 `15.7–48.4`회)을 사용했습니다.
- **내장 도구 경계와 클라이언트 출력 한도**: `codemap-search 0.14.2`는 `read`·`grep`·`find`를 MCP 서버 안에 내장하고 있어 기본·셸 호출이 `0.0`회이며(전체 호출의 약 95%가 내장 `grep`·`read`·`find`, `search`는 답변당 `1.0–1.8`회), `rg 15.2.0` 등과의 비교에는 클라이언트 기본 출력 한도 도달 차이도 함께 작용합니다(`zvec-grep 0.2.2` [`pi codemode` `7`개 답변에서 `15`회, 그 외 `17–24`회]·`Graphify 0.9.95` [`18–32`회]·`rg 15.2.0` [`25–36`회]의 기본·CLI 한도 도달 `15–36`회 대 `codemap-search 0.14.2` `0`회).
- **`Serena 2.1.0` 사전 제외**: `Serena 2.1.0`은 Grafana 전체 Go·TypeScript LSP 색인이 1회 약 34~70분 걸려 풀이 실행 전 비교 대상에서 제외했습니다.

## 서버 중단과 일시적인 동시 실행 정리 오류

- **`zvec-grep 0.2.2` 서버 중단 (`pi codemode`)**: `scope-annotation-filter` 2회 실행이 `zvec-grep` 서버 `SIGSEGV`로 종료되어 해당 셀은 유효 답변 `7`개(채점 사실 `84`개)로 집계했습니다.
- **`codebase-memory-mcp 0.12.1` 일시적 동시 실행 정리 오류**: `pi` 환경 `codebase-memory-mcp 0.12.1` 답변 2건(`pi direct` `9/12`, `pi codemode` `10/12`)은 다른 동시 실행의 공용 임시 상태 정리 작업 때문에 도구 호출이 1회씩 실패했습니다. 영향을 받은 두 슬롯(단일 `도구 × 실행 환경 × 문항 × 회차` 실행 단위)을 제외하고 `codemap-search 0.14.2` 대 `codebase-memory-mcp 0.12.1` 민감도를 다시 계산해도 `pi direct` `78/96`(`+0.92`, `p = 0.0350`), `pi codemode` `74/96`(`+1.53`, `p = 0.0025`)로 결론은 같습니다.

## 환경 분리와 실행 민감도

`pi direct`, `pi codemode`, `Codex code mode`는 보조 도구, 출력 상한, 프롬프트·토큰 집계가 달라 합산하지 않습니다. 또한 측정 결과는 당시 호스트 하드웨어, 캐시 상태, 사전 구축 색인 스냅샷, 고정 클라이언트·어댑터 버전(`pi 1.4.0`, `@buyong/pi-mcp-adapter 0.1.2`, `Codex CLI 0.164.0`)에 의존합니다. 자세한 내용은 [재현 조건과 참고 사항](/ko/benchmarks/reproduction-notes/)을 확인하세요.
