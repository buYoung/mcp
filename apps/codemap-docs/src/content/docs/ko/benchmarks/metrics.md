이 문서는 [측정 결과](/ko/benchmarks/results/)의 모든 열 이름, 세부 구분, 통계 검정 기준을 정의합니다.

## 정확도 및 사실 채점 지표

각 답변은 `gpt-6-astra`(`high`, 도구·저장소 접근 없음)가 문항당 필수 사실 `12`개(`9`개 답변 기준 `108`개, `pi codemode`의 `zvec-grep 0.2.2`는 `7`개 답변 기준 `84`개)와 대조해 채점합니다.

| 지표 / 열 | 정의 |
| --- | --- |
| `충족` (`Fulfilled`) | 주 정확도 지표입니다. 설명 내용이 맞고(`correct=true`) **동시에** 답변에 적힌 `path:시작-끝` 행 범위가 그 설명을 실제 입증(`supported=true`)할 때만 충족으로 인정합니다. `rg 15.2.0`을 포함한 모든 비교군에 같은 행 범위 인용 지시를 주었습니다. |
| `충족률` (`Fulfilled %`) | 전체 채점 사실 중 `충족`으로 인정된 비율입니다(`충족 / 전체 채점 사실 수`). |
| `Core` | 진입점부터 처리기·저장소까지 필수 종단간 연결을 묻는 사실입니다(문항당 `7`개, `9`개 답변 합계 `63`개, `7`개 답변 합계 `49`개). |
| `Extended` | 부가 분기, 설정 가드, 조건부 동작을 묻는 사실입니다(문항당 `5`개, `9`개 답변 합계 `45`개, `7`개 답변 합계 `35`개). |
| `Core 완결 (7/7)` | `Core` 사실 `7`개를 하나도 빠짐없이 모두 충족한 답변 수입니다(`9`개 중, `pi codemode`의 `zvec-grep 0.2.2`는 `7`개 중). |
| `내용 맞음` (`Factually correct`) | 인용 행 범위의 입증 여부와 무관하게 설명 내용 자체는 맞은 사실 수입니다(`correct=true`, 즉 `충족 + 내용 맞음·인용 부족`). |
| `내용 맞음·인용 부족` (`Correct, weak citation`) | 모델의 설명은 맞았지만 인용한 행 번호 범위가 그 주장을 입증하지 못한 건수입니다(`correct=true, supported=false`). |
| `오답·누락` (`Incorrect / missed`) | `전체 평가 사실 수 − 내용 맞음`(`108 − 내용 맞음`, `n = 7`에서는 `84 − 내용 맞음`)입니다. 따라서 `충족 + 내용 맞음·인용 부족 + 오답·누락 = 전체 평가 사실 수`가 됩니다(예: `96 + 2 + 10 = 108`). |
| `테스트·생성 인용` (`Cited test/gen`) | 테스트 파일이나 생성 파일을 1건 이상 인용한 답변 수입니다(`테스트·생성 파일 인용 답변`). |

## 토큰 및 턴 지표

다중 턴 에이전트는 매 턴 이전 대화 문맥을 다시 전달하므로 입력 토큰의 `~86–94%`(`85.9%–94.3%`)가 프롬프트 캐시에서 읽힙니다.

| 지표 / 열 | 정의 |
| --- | --- |
| `총 토큰` (`평균`, `중앙값`, `최소–최대`) | 답변당 전체 입력 토큰(캐시 + 비캐시)과 출력 토큰을 합한 값입니다. |
| `입력 토큰 (평균)` | 답변당 전체 입력 토큰 평균입니다(`캐시 입력 + 비캐시 입력`). |
| `캐시 입력 (평균, %)` | 답변당 프롬프트 캐시 적중 입력 토큰 평균과 셀 전체 비율(`sum(cached) / sum(input)`)입니다. |
| `비캐시 입력 (평균)` | 프롬프트 캐시에 적중하지 않은 신규 입력 토큰 평균입니다. |
| `출력 토큰 (평균)` | 풀이 모델이 생성한 출력 토큰 평균입니다. |
| `비캐시 합계 (평균)` | 답변당 `비캐시 입력 + 출력 토큰` 평균으로, 반복 전달된 캐시 접두사를 제외하고 새로 처리한 토큰량을 보여 줍니다. |
| `턴 수 (평균, 최소–최대)` | 답변 하나를 완성하는 데 거친 모델 턴 수의 평균·최솟값·최댓값입니다. |

`Codex code mode`의 총 토큰이 `pi`보다 `~1.4–1.9×` 높게 집계되는 주된 이유는 `Codex`가 매 턴 더 큰 개발자·도구·코드 모드 프롬프트(예: `codemap-search` 첫 턴 입력 토큰 `9,748` 대 `pi direct` `5,118`, `pi codemode` `4,338`)를 포함해 대부분 캐시 상태로 다시 전달하기 때문입니다.

## 도구 호출 결과 및 하위 도구 지표

| 지표 / 열 | 정의 |
| --- | --- |
| `답변당 총 호출` | 답변당 평균 호출 수이며 `총 호출 = 전달 호출 + 거절`입니다. |
| `답변당 전달 호출` (`Dispatched`) | MCP 도구, 내장 도구 또는 읽기 전용 셸에 실제로 전달되어 실행된 답변당 평균 호출 수입니다. |
| `거절 합계` (`Rejected`) | `.git` 대상 검색이나 소스 루트 밖 경로 등 읽기 전용 경로 샌드박스 규칙에 의해 실행 전 차단된 호출의 셀 전체 합계입니다. |
| `오류 합계` (`Errors`) | 실제 전달된 호출 중 오류를 반환한 횟수의 합계(`오류 ⊂ 전달 호출`)입니다(없는 경로 지정, 실패한 질의 등). |
| `답변당 기본·보조 도구` / `답변당 기본·셸` | 클라이언트 내장 도구(`pi`의 `read`, `grep`, `find`, `ls`) 또는 읽기 전용 셸(`Codex code mode`의 `exec_command`) 호출의 답변당 평균입니다. `0.0`은 내장 도구나 셸로 대체하지 않고 MCP 서버 자체 도구만으로 풀이를 마쳤음을 뜻합니다(`codemap-search 0.14.2`는 `read`, `grep`, `find`를 서버 안에 내장). MCP 서버가 없는 `rg 15.2.0` 기준군에서는 내장 파일·검색 도구 또는 읽기 전용 셸 호출 전체를 뜻합니다. |
| `하위 도구별 평균 호출` | 개별 MCP 도구, 내장 도구, 셸별 답변당 평균 호출 수입니다. |
| `보조 read` (`Graphify 0.9.95`) | `Graphify 0.9.95`의 자체 그래프 도구 7종이 원문 본문 없이 엔티티와 위치만 반환하므로 하네스가 전용으로 연결한 읽기 전용 MCP `read` 보조 도구입니다. 클라이언트 기본·셸 호출과는 별도로 집계합니다. `zvec-grep 0.2.2`는 `zvec_grep_search`가 제한된 원문 발췌를 함께 반환하므로 보조 `read`를 붙이지 않았습니다. |

## 인용 형식과 답변 길이

인용 통계는 유효한 `160`개 답변 원문에서 일관된 규칙으로 추출한 정규화 검토 인용 목록(normalized review citation index)에서 직접 재집계했습니다.

| 지표 / 열 | 정의 |
| --- | --- |
| `답변당 범위 인용 (합계)` | `end > start`인 여러 줄 `path:시작-끝` 인용의 답변당 평균과 셀 전체 합계입니다. |
| `인용당 평균 줄 수` | 여러 줄 범위 인용 1건당 평균 줄 수입니다. |
| `답변당 한 줄 인용 (합계)` | `path:행` 또는 `start == end`인 한 줄 인용의 답변당 평균과 셀 전체 합계입니다. |
| `평균 답변 길이(자)` | 해당 셀의 최종 풀이 답변 평균 글자 수입니다. |

## 문항별 표와 세부 항목 행렬 표기

- **회차별 표기 (`1·2·3회차 (Core+Ext)`)**: 세 회차 각각의 충족 사실 수와 괄호 안 `(Core+Extended)` 구성을 보여 줍니다(예: `10 (6+4)`는 충족 `10`개 = `Core` `6`개 + `Extended` `4`개).
- **세부 항목 행렬 (`A1–AE5`, `G1–GE5`, `B1–BE5`)**: 정답 경로·심볼·루브릭 원문은 비공개로 두고 불투명 ID(`1–7`은 `Core`, `E1–E5`는 `Extended`)로 표기합니다. 각 셀은 `pi direct · pi codemode · Codex code mode` 순서의 충족 횟수(기본 `3`회 기준이며, `pi codemode` 3회 중 2회가 중단된 `zvec-grep 0.2.2`의 `B*`/`BE*`는 `1/1`·`0/1`처럼 `충족/실행`으로 표기)와 전체 합계(`sum/9`, `zvec-grep 0.2.2`의 `B*`/`BE*`는 `sum/7`)를 나타냅니다.

## 통계 검정과 토큰 비율

- **문항 층화 정확 순열 검정**: 쌍별 `p` 값은 문항 층화 정확 순열 검정 결과입니다(`9 vs 9` 비교는 `8,000`개 순열, `7 vs 9` 비교는 `1,600`개 순열). 보고된 `p` 값은 외부 MCP 비교 `24`개(전체 쌍별 비교 행 `27`개)에 다중 비교 보정을 적용하지 않은 값이며, 미보정 기준 `p < 0.05`를 사용했습니다.
- **양측 `p` 대 단측 `p`**: **양측 `p`**는 두 도구가 어느 방향이든 다른지 검정합니다. **단측 `p`**는 앞 도구(`A − B`의 `A`)가 뒤 도구(`B`)보다 답변당 충족 사실이 더 많은지 검정하므로 음수 차이 행에서는 단측 `p`가 `1.0`에 가깝게 나옵니다.
- **`n = 9` 표본의 변별력**: 셀당 답변 `9`개(`pi codemode`의 `zvec-grep 0.2.2`는 `7`개) 표본에서는 답변당 약 `1.0`개 안팎의 차이부터 통계적으로 갈리며 `0.3–0.8` 차이는 시행 간 변동 범위로 봅니다.
- **총 토큰 비율·비캐시 토큰 비율**: 앞 도구의 평균 토큰(`A`)을 뒤 도구의 평균 토큰(`B`)으로 나눈 비율(`×1.71`, `×0.55` 등)입니다.
