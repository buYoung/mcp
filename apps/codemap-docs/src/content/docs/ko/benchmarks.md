## 측정 조건과 진행 방식

평가는 풀이 모델의 학습 기준일 이후 커밋이 포함된 [grafana/grafana](https://github.com/grafana/grafana) 읽기 전용 체크아웃(`24,115`개 TypeScript와 Go 추적 파일, 커밋 `c0a598f5a49abf2014f67e806075d8ad267c9efb`)에서 진행했습니다. `gpt-6.1-sol`(`medium`) 모델로 세 클라이언트 환경마다 다단계 아키텍처 질문 `3`개를 도구별로 `3`회씩 풀어 유효 답변 `160`개, 채점 사실 `1,920`개를 얻었습니다(`pi codemode`의 `zvec-grep 0.2.2`는 서버 중단 `2`건으로 `9`회 중 `7`회만 완료). 도구나 저장소 접근 권한이 없는 블라인드 채점 모델 `gpt-6-astra`(`high`)가 답변마다 필수 사실 `12`개를 대조하고, `path:시작-끝` 행 범위 인용으로 실제 입증된 항목만 인정했습니다. 모든 도구에 같은 인용 지침을, 모든 MCP 비교군에 같은 MCP 우선 지침을 주었으나 클라이언트마다 보조 도구와 출력 한도, 프롬프트 토큰 계산 방식이 달라 세 환경은 합산하지 않고 따로 집계했습니다.

### 표 읽는 법

- **충족 (`내용 맞음` + `인용 입증`)**: 답변당 `12`개 사실(`9`개 답변 `108`개, `7`개 답변 `84`개) 기준 주 정확도 지표입니다. 설명이 맞고(`correct=true`) 답변에 적은 `path:시작-끝` 행 범위가 그 내용을 입증해야(`supported=true`) 충족으로 인정합니다.
- **Core (`63`), Extended (`45`), Core 완결 (7/7)**: 문항마다 종단간 핵심 연결을 묻는 Core `7`개와 부가 분기와 설정 조건을 묻는 Extended `5`개가 있습니다. **Core 완결 (7/7)**은 Core `7`개를 빠짐없이 충족한 답변 수입니다.
- **내용 맞음, 인용 부족, 오답·누락**: **내용 맞음·인용 부족**은 설명은 맞았으나 인용한 행 범위가 주장을 입증하지 못한 건수입니다(`correct=true, supported=false`). **오답·누락**은 `전체 평가 사실 수 − 내용 맞음`이므로 `충족 + 내용 맞음·인용 부족 + 오답·누락 = 전체 평가 사실 수`가 됩니다.
- **총 토큰 vs 비캐시 토큰**: 다중 턴 에이전트는 이전 대화를 매 턴 다시 보내 입력의 `~86–94%`가 프롬프트 캐시에 적중합니다. **총 토큰**은 캐시 입력까지 포함한 전체 합계이고, **비캐시 토큰**은 캐시에 걸리지 않은 신규 입력과 출력의 합계입니다. `Codex` 총 토큰이 `pi`보다 `~1.4–1.9×` 높은 주된 이유는 매 턴 더 큰 시스템과 도구 프롬프트(`codemap-search` 첫 턴 입력 `9,748`토큰 vs `pi direct` `5,118`, `pi codemode` `4,338`)를 다시 보내기 때문입니다.
- **호출 수와 기본·보조 도구 호출**: `답변당 평균 호출`은 `답변당 총 호출`(`전달 호출 + 거절`)입니다. 기본·보조 도구 호출 `0.0`은 내장 도구나 셸 없이 MCP 도구만으로 풀이를 마쳤다는 뜻입니다(`codemap-search 0.14.2`는 `read`, `grep`, `find`를 내장). MCP 서버가 없는 `rg 15.2.0`은 모든 기본 도구와 셸 호출이 여기에 들어갑니다.
- **`·`로 구분된 세 값 순서**: 요약표와 행렬의 세 값은 항상 `pi direct` · `pi codemode` · `Codex code mode` 순서입니다.
- **순열 검정 `p` 값과 토큰 비율**: 쌍별 `p` 값은 문항 층화 정확 순열 검정 결과(`9 vs 9` `8,000`회, `7 vs 9` `1,600`회)로, 외부 MCP 비교 `24`건(전체 `27`개 행)에 대해 다중 비교 보정 없이 `p < 0.05`를 기준으로 봅니다. **양측 `p`**는 양방향 차이를, **단측 `p`**는 `A − B`에서 `A`가 `B`보다 앞섰는지를 검정합니다. `n = 9` 표본에서는 답변당 약 `1.0`개 이상 차이부터 통계적으로 구분되며, `0.3–0.8` 차이는 시행 간 오차 범위에 속합니다. 토큰 비율은 `A` 평균 토큰을 `B` 평균 토큰으로 나눈 값입니다.

## 하위 도구 호출, 인용 및 출력 잘림

- **전달, 거절, 오류**: `총 호출 = 전달 호출 + 거절`이며 호출 수는 답변당 평균, 거절과 오류는 해당 셀의 합계입니다. `거절`은 `.git`이나 저장소 밖 경로처럼 읽기 전용 샌드박스가 실행 전에 막은 호출이고, `오류`는 실제 전달된 호출 중 오류로 끝난 횟수입니다.
- **보조 `read` (`Graphify 0.9.95`) 대 `zvec-grep 0.2.2`**: `Graphify`의 그래프 도구 7종은 원문 없이 위치와 메타데이터만 반환하므로 읽기 전용 MCP `read` 보조 도구를 붙였습니다. 반면 `zvec-grep 0.2.2`는 검색 결과에 제한된 원문 발췌가 포함되어 보조 `read` 없이 넓은 파일 확인만 기본 도구나 셸로 처리했습니다.
- **클라이언트 출력 한도와 잘림**: `기본·CLI 한도 도달 (답변 수)`는 클라이언트 상한에 걸린 횟수입니다. `pi`에서는 기본 `read`(`2,000`줄 / `50 KiB`), `grep`(`100`건), `find`(`1,000`건), `ls`(`500`건)가 기준이고, `Codex code mode`에서는 셸 `exec_command`와 `// @exec: {"max_output_tokens": ...}` 지정 없는 기본 `10,000`토큰 `exec` 셀에서 출력된 `Warning: truncated output` 횟수입니다. `스크립트 잘림`은 `pi codemode`의 `10,000`토큰 상한에 걸린 횟수, `어댑터 잘림`은 `@buyong/pi-mcp-adapter 0.1.2`가 개별 MCP 응답을 자른 횟수입니다(기본 `20 KiB`, `codemap-search 0.14.2`는 `_meta["pi/maxOutputBytes"]`로 `100,000`바이트 지정).
- **인용 집계 기준**: 유효 답변 `160`개의 본문에서 정규화한 인용 목록을 다시 집계했습니다. `범위 인용`은 여러 줄(`end > start`) `path:시작-끝` 인용, `한 줄 인용`은 1줄(`path:행` 또는 `start == end`) 인용, `테스트·생성 인용`은 테스트나 생성 파일을 한 번 이상 인용한 답변 수입니다.
