## v1.1.0

<ReleaseMeta version="1.1.0" date="2026-11-28" />

### 개선

- Go, TypeScript, Java, Kotlin, C#, C++, Dart, PHP, Rust, Scala, Swift에서 매개변수가 저장소 선언 타입·import 타입·언어 표준 타입이어도 파일 간 선언과 구현을 연결합니다(와일드카드 import, 타입 별칭, C++ 템플릿 제외).
- C++에서 파생 클래스가 기반 헤더를 직접 include하면 include guard나 매크로 확장이 있는 파일에서도 파일 간 가상 메서드 재정의를 연결합니다.
- 매크로가 확장된 C/C++ 파일의 이벤트 입력 불가 안내를 선언마다 반복하지 않고 `read`·`search` 응답당 한 번만 표시합니다.
- 하위 타입에 같은 이름의 메서드가 있지만 연결을 증명하지 못한 경우 `read`·`search` 구현 후보 아래에 `not source-proven` 개수 행을 표시합니다(Go·Rust 제외).
- Java, Kotlin, C#, TypeScript, Dart, Swift의 호출·구현 탐색에 제네릭 타입을 지원해 `Codec<String>` 같은 타입 인자 수신자 호출과 제네릭 기반 상속을 연결합니다(타입 매개변수를 쓴 메서드 매개변수는 제외).
- Kotlin, Swift, C#, Dart, PHP, TypeScript, Python에서 null 가능 수신자(`Tool?`, `?Tool`, `Tool | null`, `Tool | undefined`, `Tool | None`, `Optional[Tool]`)와 `?.`, `!!.`, `!.` 호출을 대상 메서드에 연결합니다.
- Kotlin과 C#에서 타입을 명시한 지역 변수와 Kotlin 클래스 본문 프로퍼티의 호출을 해당 타입의 메서드에 연결합니다.
- 최초 색인과 전체 재색인이 끝날 때 검색 세그먼트를 하나로 정리합니다.

### 변경

- 파서를 tree-sitter 0.27과 새 문법(C#, Dart, PowerShell, Scala, Swift 등)으로 올려, 놓치던 Swift 최상위 함수와 PowerShell Pester `It` 블록 같은 명령을 인식합니다.
- C# 파서를 `tree-sitter-c-sharp` 0.24.0으로 올려 오류 없이 파싱되는 파일이 늘었습니다. 새로 생긴 회귀가 두 가지 있습니다. `&&` 조건 중간에 `typeof(...)`를 담은 `#if` 블록이 오고 뒤에 `!`로 시작하는 피연산자가 이어지면 파일 전체가 파싱 오류가 되어 선언 대부분이 빠지며, 역참조 포인터 캐스트 안의 호출도 놓칩니다.
- 업데이트 후 기존 색인을 한 번 자동으로 다시 만듭니다.

### 수정

- Swift에서 전위·이항 연산자 바로 뒤의 호출(`!flags.contains(x)`, `total / Double(count)` 등)이 올바른 호출 대상과 수신자를 유지하도록 고쳤습니다.
- Dart의 `=>` 함수 본문 호출과 null 안전 호출(`gauge?.level()`)이 올바른 호출 대상과 수신자를 기록하도록 고치고, 함수 타입 `typedef`를 필드나 호출이 아닌 타입으로 표시합니다.
- Dart에서 제네릭 기반 클래스(`extends Codec<String>`)가 구현 탐색에서 빠지던 문제와 `static` 메서드가 상위 타입 `static` 메서드의 구현으로 표시되던 문제를 고쳤습니다.
- 애너테이션으로 끝나고 줄바꿈이 없는 Kotlin 파일이 서버와 색인 작업을 멈추던 문제를 고쳤습니다.
- 주 생성자가 다음 줄에서 시작하는 Kotlin 클래스(중첩 클래스와 `constructor` 앞에 애너테이션·공개 범위 수식어가 함께 붙은 경우)가 깨지던 문제를 고치고, null 가능 매개변수(`String?`)를 가진 Kotlin 메서드를 기반 선언과 연결합니다.
- C#, PHP, Ruby, Lua에서 본문 안의 문장 하나를 파싱하지 못해도(예: C#에서 `#if`가 `else` 분기를 가르는 경우) 바깥 메서드·클래스·네임스페이스를 유지합니다.
- 외부 타입을 가리키는 호출(`String::from`, `std::max`, `\DateTimeImmutable::createFromFormat`과 자유 함수와 이름만 같은 외부 타입 수신자 호출)을 `unconfirmed callers`에서 제외하고, 외부 타입의 확장 메서드 호출은 유지하며 Kotlin 매개변수 타입도 검사합니다.
- 같은 `.csproj` 또는 폴더에 속한 C# `partial` 클래스의 멤버 호출을 연결하고(`.csproj`가 여럿인 폴더와 `#if` 조각 제외), 이름이 같은 제네릭·비제네릭 타입(`Outcome<T>` vs `Outcome`)을 구분합니다.
- Java의 패키지 비공개 메서드와 Dart의 밑줄(`_`) 시작 라이브러리 비공개 메서드가 다른 패키지·라이브러리의 같은 이름 메서드와 연결되지 않도록 고쳤습니다.
- Python에서 함수 안에 선언한 이름·모듈 별칭 import의 효력을 해당 함수 범위로 제한하고, `from ... import *` 뒤에 선언된 최상위 import를 연결합니다.
- Java, Kotlin, Scala, Groovy, Swift에서 부모 타입에 같은 매개변수 개수의 다른 오버로드가 있으면 수신자 타입 메서드로 단정하지 않고 미연결로 둡니다.
- C·C++·어셈블리 매크로 확장 안내에 절대 경로 대신 작업공간 기준 상대 경로를 표시합니다.
- C, C++, Java, Groovy에서 지역 변수 초기화 호출(`int total = sum();` 등)과 C·C++ 재귀 호출이 연결되도록 고쳤습니다.
- `if` 조건식과 본문 안의 수신자 타입 기반 호출을 해석합니다.
- 간략한 `search` 끝의 `Connected locations`에서 관계 줄 없이 메서드 제목만 남는 경우를 없애고, 모든 관계 줄에 제목을 함께 표시합니다.

## v1.0.0

<ReleaseMeta version="1.0.0" date="2026-11-17" />

### 추가

- `search`에 `workspace_scope`를 통한 다른 저장소 검색을 추가했습니다. 세션 `read` 권한 범위 안의 외부 폴더나 연결 worktree를 넘기면 해당 저장소를 색인·검색하며, `read`와 `grep`도 그 색인을 재사용합니다.
- `read view=source` 끝에 읽은 범위의 내보낸 값·클래스·상수를 import하는 다른 파일 목록 트레일러를 추가했습니다(`output.read.is_outside_callers_enabled = false`로 호출자 트레일러와 함께 끌 수 있음).

### 개선

- 색인이 없는 새 git worktree는 같은 저장소의 최신 호환 worktree 색인에서 시작해 변경된 파일과 네이티브 매크로 파일만 다시 추출하며, 내용 변화 없이 수정 시각만 바뀐 파일은 다시 읽지 않습니다.
- 색인 생성과 `search`를 멀티코어로 병렬화해 대형 저장소의 최초 색인과 기본 `search` 시간을 3배 이상(`caller_context: false`는 4배 이상) 단축했습니다.
- 저장 문서를 zstd로 압축하고 중복 메타데이터 저장을 없애 색인 디스크 크기를 절반 이하로 줄였습니다.
- 바뀐 문서만 디코딩하고 변경 없는 색인 데이터를 재사용해 시작 및 증분 갱신 시 최대 메모리 사용량을 낮췄습니다.
- `search` 남은 출력 예산 안에서 docstring이나 문자열 리터럴이 따옴표 구절·인접 단어와 정확히 일치하는 순위 밖 파일을 `Exact phrase matches outside the ranking`으로 추가 표시합니다.
- `search` 결과의 반복되는 본문 생략 안내와 callee 헤더를 공유하고, `grep` `view=source_grouped` 상단의 중복 안내 문구와 `initial_instructions`의 저장소 통계를 제거했습니다.
- Jev 필터가 `read`·`grep`의 잘린 함수와 함수 밖 코드 블록, `search`의 후속 호출 후보(최대 8개, `(Jev: related)` 표시)까지 판정하며, 생략된 정확한 위치나 단일 함수 범위를 다시 읽을 때는 재판정 없이 원문을 반환합니다.
- Jev 요청 형식을 제공자별로 맞췄으며(TypeSafe·`typesafe/*`는 일반 텍스트 배치, OpenRouter `openai/*`는 후보별 개별 요청, 기타 OpenRouter 모델은 JSON), Jev 활성화 시 기본 도구 설명을 교체하지 않고 생략 안내 문장 하나만 덧붙입니다.
- 서버 지침과 도구 설명을 보강해 저장소 전체 탐색 후 범위 축소, 공유 리터럴 기반 언어·클라이언트-서버 간 추적, `path:start-end`/`path:line` 인용 형식, 필요한 호출자·import만 추적, 요청 외 테스트·생성 파일 인용 회피를 안내합니다.

### 변경

- Jev 동시성 기본값과 범위를 변경했습니다(`output.jev.max_in_flight_requests` `1–8`, 기본값 `3` → `8`; `output.jev.request_spacing_ms` `>= 100`, 기본값 `300` → `100`).
- 업데이트 후 기존 색인을 한 번 자동으로 다시 만듭니다.

### 제거

- **호환성 변경:** `overview` 도구를 제거했습니다. 디렉터리 목록은 `find`, 파일 선언 목록은 `read`의 `view=definitions`, 모노레포 범위 목록은 `initial_instructions`를 사용하세요. `search`는 이전 호출의 `workspace_scope`를 유지하지 않으며, 설정 스키마 v33에서 `[output.overview]`, `tool_output.is_overview_stats_enabled`, `output.jev.overview_filter_enabled`와 `output.jev.scope`의 `"overview"`를 제거했습니다.
- **호환성 변경:** `register_task` 도구를 제거했습니다. Jev 필터를 켠 경우 `initial_instructions`의 필수 `task` 인자로 사용자 요청을 직접 전달합니다.
- Jev 판정 시 호출자·피호출자 소스, 관계 요약, 이벤트 근거 전송을 중단하고 각 단위의 소스와 경로·종류·이름만 보냅니다.

### 수정

- 작업공간 안에 체크아웃한 git 연결 worktree를 색인·감시·호출자 스캔에서 건너뛰어 `search` 중복 결과를 방지합니다(서브모듈과 중첩 저장소는 유지).
- 색인 갱신 시 압축 병합을 마무리하고 삭제된 항목을 회수해 반복 편집 중 색인 크기가 계속 커지던 문제를 고쳤습니다.
- TypeScript·JavaScript 재내보내기(`export { default as Name } from`, `export * as name from`), TypeScript `import { type Name }`, `.vue`·`.svelte`·`.astro` 컴포넌트 import, 본문에 private 멤버나 private 생성자가 있는 Groovy·Scala 선언의 import·내보내기 추적을 고쳤습니다.
- 어셈블리의 `#include`·`%include` import, Bash 함수의 전체 본문 범위, Bash·Zsh·PowerShell의 계산된 경로(`$(dirname "$0")`, `$PSScriptRoot`) 기반 스크립트 import 인식을 고쳤습니다.
- 대형 작업공간에서 `read view=source` 호출자 트레일러가 시간 제한에 자주 걸리던 문제를, 대상 이름을 쓰는 색인 파일만 조회하고 색인 추출 결과를 재사용하도록 고쳤습니다.
- 일치 결과가 없는 정확한 `event_key` 검색이 일반 순위 검색으로 자동 전환되지 않고 조회 범위와 순위 검색 방법을 안내하도록 고쳤습니다.
- `grep` 파일 목록·개수 모드에서 `view=source`와 `view=source_grouped`를 표시 전용 옵션으로 허용하고, `read view=definitions`가 색인된 Sass 파일을 미지원 형식으로 거부하던 문제를 고쳤습니다.

## v0.13.0

<ReleaseMeta version="0.13.0" date="2026-10-23" />

### 추가

- `read`·`grep`·`find`에 존재하지 않는 경로를 넘기면 비슷한 작업공간 경로를 최대 3개 제안합니다.
- `read view=source`에서 호출 인자로 쓴 문자열 키와 대문자 상수의 다른 파일 사용 위치를 함께 표시합니다.
- `auto`·`on`·`off` 색인 모드를 추가했습니다(`auto`는 필요 시 시작하며 비저장소 폴더나 설정된 파일 수 상한 초과 작업공간은 건너뜁니다).

### 개선

- C/C++ 헤더 선언을 고유 정의·호출자(간접 include 포함)와 연결하고, C++ `this`·타입 지정 변수·클래스명 기반 멤버 호출을 해석하며, 매크로 재처리를 입력이 바뀐 파일로 제한했습니다.
- 대형 저장소의 최초 색인에서 타입·의존 관계 분석 시간을 줄였습니다.
- `read` 호출자 요약이 생략될 때 색인·파일 상태나 시간 제한 사유를 안내하고, 백그라운드 색인 갱신 실패 시 재시도 간격을 최대 30초까지 늘리며 반복 경고를 줄였습니다.

### 변경

- 새 설정의 `read`·`grep`·`find` 기본 접근 범위를 `workspace`에서 `anywhere`로 변경했습니다(기존 설정값 유지).
- 모든 Jev 필터가 꺼져 있으면 도구 목록에서 `register_task`를 숨깁니다.
- 업데이트 후 기존 색인을 한 번 자동으로 다시 만듭니다.

### 수정

- 이전 클라이언트가 `initial_instructions`에 넘기는 구형 인자를 오류 없이 무시하고, `symbol:*` 같은 질의가 오류를 낼 때 일반 단어 검색으로 폴백합니다.
- 색인 갱신 후 오래된 세그먼트 파일이 누적되던 문제와, 다른 프로세스가 공유 색인에 쓰는 동안 호출자 요약이 빠지거나 오래된 결과 경고가 붙던 문제를 고쳤습니다.

- Linux(GNU·musl, Ubuntu 22.04+), macOS, Windows용 SHA-256 체크섬 포함 릴리스 아카이브와 POSIX 설치 스크립트, Homebrew, WinGet, crates.io 배포를 추가했습니다.

### 변경

- `get_codemap` 도구 이름을 `overview`로 변경하고, 기본 `grep` 출력을 `file:line:text` 형식으로 지정했으며, `register_git_exclude`·`respect_git_exclude`를 `use_git_ignore`로 통합하고 `.git/info/exclude` 자동 수정을 중단했습니다.

### 수정

- MCP `serverInfo.version`에 하드코딩된 값 대신 Cargo 패키지 버전을 반환하도록 고쳤습니다.

### 보안

- `find`·`grep`·`read`에 저장소 범위 기본 권한과 경로 경계 검증을 적용하고, POSIX 설치 스크립트에 원자적 설치·심볼릭 링크 거부를 적용했습니다.
