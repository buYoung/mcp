Register `codemap-search mcp` so your client launches it with the target repository as its working directory. Launching directly in your home directory (`~`) is refused; subdirectories such as `~/work/project` work normally.

If you have not installed the binary yet, see [Installation](/getting-started/installation/).

## Register with an MCP client

<Tabs>
    <TabItem label="Claude Code">
        Register `codemap-search` across projects for your user account:

        ```sh
        claude mcp add --scope user codemap-search -- codemap-search mcp
        ```

        For a team-shared `.mcp.json` entry, run inside that project directory:

        ```sh
        claude mcp add --scope project codemap-search -- codemap-search mcp
        ```

        Without `--scope`, Claude Code uses `local` (private to you for the current project in `~/.claude.json`), not the shared `project` scope. See [Claude Code's MCP docs](https://code.claude.com/docs/en/mcp).
    </TabItem>
    <TabItem label="Codex">
        Register with the Codex CLI:

        ```sh
        codex mcp add codemap-search -- codemap-search mcp
        ```

        Or add the server entry directly to `~/.codex/config.toml`:

        ```toml
        [mcp_servers.codemap-search]
        command = "codemap-search"
        args = ["mcp"]
        ```
    </TabItem>
    <TabItem label="pi">
        Install [@buyong/pi-mcp-adapter](https://www.npmjs.com/package/@buyong/pi-mcp-adapter) so `pi` respects `codemap-search`'s output limits instead of truncating MCP results at 20 KB (as `pi` 1.4.0's built-in MCP does):

        ```sh
        pi install npm:@buyong/pi-mcp-adapter
        ```

        Disable built-in MCP by adding `-builtin:mcp` to `extensions` in `~/.pi/agent/settings.json`, or turn off `mcp` under **Built-in** in `pi config`. Restart `pi` or run `/reload`.

        Add the server to `~/.pi/agent/mcp.json` or a trusted project's `.pi/mcp.json`:

        ```json
        {
          "mcpServers": {
            "codemap-search": { "command": "codemap-search", "args": ["mcp"] }
          }
        }
        ```

        Start `pi` inside the repository you want to inspect. The adapter applies `codemap-search`'s output limits automatically without `maxOutputBytes` in `mcp.json`; see [client delivery budgets](/configuration/#client-delivery-budgets).
    </TabItem>
    <TabItem label="OpenCode">
        Add the server to global `~/.config/opencode/opencode.json` or a project `opencode.json`:

        ```json
        {
          "$schema": "https://opencode.ai/config.json",
          "mcp": {
            "codemap-search": {
              "type": "local",
              "command": ["codemap-search", "mcp"],
              "enabled": true
            }
          }
        }
        ```

        See the [OpenCode MCP guide](https://opencode.ai/docs/mcp-servers/) for schema details.
    </TabItem>
</Tabs>

## Verify the first connection

1. Ask the client to call `initial_instructions` once. It returns navigation guidance and, in monorepos, available workspace scopes and languages. Leave arguments empty unless you enabled the optional [Jev relevance filter](/configuration/#optional-jev-decision-stages), in which case pass the user's request as `task`.
2. Confirm that the returned paths match your target repository. If you see a warming notice, wait for indexing to finish and retry.
3. Run `find`, `read`, and `search` against a known file and symbol to verify the index is working.

If the client cannot find the binary, check its `PATH`. If the wrong directory is indexed, fix the client's working directory. Startup and config errors are written to `stderr`.

## Optional global instructions

To keep a one-line navigation reminder in your client's global instruction file, add this to `~/.codemap/config.toml` (or `$CODEMAP_HOME/config.toml`):

```toml
[global_instructions]
enabled = true
```

This defaults to `false`. The server selects the global instruction file for Codex, Claude Code, pi, or OpenCode automatically and adds one managed line telling the agent to call `initial_instructions` first. Setting `enabled = false` removes only that managed line and leaves your own instructions intact. This option applies globally and cannot be overridden by repo configs.

Start a new agent session for the client to pick up the updated file. See [Global instructions](/configuration/#global-instructions) for per-client paths, file precedence, and removal limits.
