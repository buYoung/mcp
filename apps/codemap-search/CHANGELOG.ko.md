### 추가

- `read view=source`에 `[Other files importing this window's declarations (static analysis, approximate)]` 트레일러를 추가했습니다. 읽은 범위에서 내보낸 값·클래스·상수를 import하는 다른 파일과, 그 파일에서 이를 쓰는 함수나 행을 보여 줍니다. 호출자 트레일러는 함수를 이름으로 찾지만, 이런 선언은 import를 거쳐 쓰이기 때문입니다. 지원하는 프로그래밍 언어마다 그 언어의 import 규칙을 따릅니다. 스크립트 모듈과 그 재내보내기·이름을 바꾼 내보내기·넘겨 내보내는 기본값과 네임스페이스(`export { default as Name } from`, `export * as name from`), Python 모듈, Go 패키지, Rust 경로, JVM 패키지, C#·PHP 네임스페이스, Swift 모듈, Dart 라이브러리, Ruby·PowerShell의 상대 경로 로드, Lua 모듈, C·C++ include, 어셈블리 `.include`·`#include`·`%include`, 셸 `source`, Nix `import`, Starlark `load`를 따라갑니다. 같은 패키지·네임스페이스·모듈의 파일은 그 이름을 쓸 때 포함합니다. 기본 import와 Vue·Svelte·Astro 컴포넌트 import는 import한 파일의 이름으로 첫 행에 보여 줍니다. 가까운 디렉터리의 파일을 먼저 보여 주고, 트레일러는 1,536바이트와 100ms 안에서 만들며, 반복해서 읽으면 호출자 트레일러처럼 접습니다. 찾기가 import하는 파일을 하나도 찾기 전에 시간 한도에 닿으면 아무것도 보여 주지 않는 대신 그 사실을 알립니다. 같은 이름은 몇 번 대입되든 한 번만 보여 주며, 같은 이름을 스스로 묶는 함수(지역 선언, Python·PowerShell의 대입이나 매개변수, 셸의 `local`) 안에서 쓴 곳은 세지 않습니다. Zsh 위젯 함수처럼 하이픈이 든 셸 이름도 보여 줍니다. `output.read.is_outside_callers_enabled = false`로 설정하면 이 트레일러도 꺼집니다. 프롬프트 글자 수 변화(도구 설명 / 서버 안내 / 초기 안내): 0 / 0 / 0자.

### 개선

- 큰 저장소의 새 색인이 세 배 넘게 빨리 준비됩니다. 파일을 모든 프로세서 코어에서 읽고 추출하되, 색인에는 이전과 같은 순서로 넣습니다. 추출은 구문 노드를 감싼 노드들을 한 단계 올라갈 때마다 트리를 새로 내려가며 찾지 않고 한 번 내려가며 찾고, 자식 노드도 위치로 하나씩 찾지 않고 차례로 방문합니다. 게시할 때 저장 문서를 모든 프로세서 코어에서 디코딩하고, 모듈 조회는 경로마다 링크를 한 번만 풉니다. 초기 설정을 만들 때 각 디렉터리의 ignore 파일을 그 아래 디렉터리마다 다시 읽지 않고 한 번만 읽습니다. 파일 19,757개 저장소의 새 색인은 95.5–96.1초 대신 27.7–30.8초 만에, 파일 1,494개 저장소는 29.9초 대신 20.9초 만에 준비됩니다. 추출한 문서와 도구 출력은 바뀌지 않고, `search`와 `read`의 중앙값과 95백분위 시간은 이전과 4% 안쪽으로 같습니다. 프롬프트 글자 수 변화(도구 설명 / 서버 안내 / 초기 안내): 0 / 0 / 0자.
- 색인 크기가 이전의 절반 아래로 줄었습니다. 저장 문서를 zstd로 압축하고, 이벤트 소스·flow 요약·심볼 이름·docstring 사본을 더 이상 저장하지 않습니다. 이 값들은 그대로 검색되거나 파일에서 읽습니다. 경로·수정 시각·내용 해시를 fast field에도 두어, 갱신 때 파일을 비교하거나 게시 때 병합으로 자리를 옮긴 문서를 찾을 때 저장 문서를 읽지 않습니다. touch처럼 수정 시각만 바뀌고 내용은 그대로인 파일은 더 이상 다시 추출하지 않습니다. 이벤트 소스는 세대를 게시할 때 파일에서 읽고, 색인한 텍스트와 같을 때만 씁니다. 파일 19,757개 저장소의 새 색인은 429MB에서 161MB로, 파일 1,494개 저장소는 42MB에서 18MB로 줄었습니다. `search`와 `read`의 중앙값과 95백분위 시간은 이전과 5% 안쪽으로 같고, `caller_context: false`로 부른 `search`는 4–9% 빨라졌습니다. 업데이트 후 기존 색인을 한 번 다시 만듭니다. 프롬프트 글자 수 변화(도구 설명 / 서버 안내 / 초기 안내): 0 / 0 / 0자.
- 새 색인 세대를 게시할 때 바뀐 문서만 디코딩하고, 바뀌지 않은 파일은 이전 세대와 공유합니다. 시작 후 첫 게시는 시작할 때 읽은 문서를 다시 디코딩하지 않고 그대로 씁니다. 이벤트 경로 분석은 이벤트 소스도 Rust 파일도 아닌 파일만 바뀌면 캐시를 재사용하고, 분석 단계 사이에 바뀌지 않은 함수 요약을 공유합니다. 파일 19,757개 저장소에서 준비 완료 시점의 최대 메모리는 2.13–2.36GB에서 1.72–1.88GB로, 파일 200개를 고친 뒤의 최대 메모리는 3.38–3.65GB에서 2.22–2.63GB로 줄었습니다. 파일 1,494개 저장소에서 준비 완료 시점의 최대 메모리는 2.55GB에서 1.73GB로 줄었습니다. 도구 출력은 바뀌지 않습니다. 프롬프트 글자 수 변화(도구 설명 / 서버 안내 / 초기 안내): 0 / 0 / 0자.

### 제거

- **호환성 변경:** `overview` 도구를 제거했습니다. 디렉터리 목록은 `find`, 파일의 선언 목록은 `read`의 `view=definitions`, monorepo 범위 목록은 `initial_instructions`로 확인합니다. `search`는 이전 호출에서 고른 범위를 더 이상 유지하지 않으므로, 한 범위 안에서 찾을 때는 호출마다 `workspace_scope`를 넘깁니다. 설정 스키마 v33은 `[output.overview]`, `tool_output.is_overview_stats_enabled`, `output.jev.overview_filter_enabled`를 지우고 `output.jev.scope`에서 `"overview"`를 뺍니다. 설정 자동 갱신을 끈 경우 `output.jev.scope`의 `"overview"`는 무시하고 나머지 도구는 그대로 선택합니다. 프롬프트 글자 수 변화: −1,374(`overview` 설명과 매개변수 −1,336, `search` −26, `grep` −12) / +27 / −53자, monorepo 작업 공간은 −64자.

### 수정

- 색인 갱신이 시작한 세그먼트 병합을 끝낼 때까지 색인 writer를 놓지 않고, 지워진 문서가 10%를 넘는 세그먼트는 다시 씁니다. 이전에는 갱신할 때마다 병합이 취소되어, 다시 색인한 파일의 옛 복사본이 남고 색인이 계속 커졌습니다(어떤 색인은 세그먼트 43개, 지워진 문서 31%). 파일 200개를 고쳤다 되돌리기를 세 번 한 buyong-mcp 사본 색인은 이제 세그먼트 1개, 42MB를 유지합니다. 이전에는 세그먼트 5개, 49MB, 지워진 문서 199개였습니다. 프롬프트 글자 수 변화(도구 설명 / 서버 안내 / 초기 안내): 0 / 0 / 0자.
