search, 소스 read·grep, 루트 외 overview의 활성화된 Jev 필터를 쓰기 전에만 사용자 요청과 관련성 판정 질문을 등록하세요. Jev가 꺼져 있으면 이 도구를 호출하지 마세요. initial_instructions·find·루트 overview는 작업 등록이 필요하지 않습니다.

Jev는 각 후보와 제공된 소스 근거를 이 질문들에 대조해 무관한 코드나 선언을 걸러냅니다. 등록 자체는 Jev를 호출하지 않습니다.

task_query에는 사용자 요청 원문 전체를 넣으세요. 코드가 답변에 기여하는 서로 다른 방식을 질문으로 나누고, 예가 관련 있음을 뜻하게 하세요. 각 질문은 하나의 일관된 관계를 판정하게 하세요. 같은 의미의 질문과 이름·표기 변형은 묶되, 질문 수를 줄이려고 독립적으로 필요한 여러 역할을 긴 체크리스트로 합치지 마세요. 질문 1~8개는 허용 범위이며 채워야 할 목표가 아닙니다.

각 질문에 요청한 대상·관계·범위를 독립적으로 명시하세요. 후보는 작업의 해당 부분에 기여하면 되며 전체 흐름을 구현할 필요는 없습니다. 짧은 위임 함수나 초기화 함수도 소스로 연결이 확인되면 대상 이름 없이 기여할 수 있습니다.

when_true에는 관련된 분기·콜백·위임 등 그 기여를 확인할 수 있는 사실을 적으세요. when_false에는 무관한 동작임을 확인하는 사실을 적고, 이름이나 문맥이 없다는 이유만으로 아니오를 확정하지 마세요. 흐름을 설명해 달라는 요청을 각 후보가 모든 단계를 수행해야 한다는 조건으로 바꾸지 마세요.

이처럼 관련성을 나타내는 대안들을 묶을 때는 match="any"를 명시하세요. 각 후보가 모든 기준을 반드시 충족해야 할 때만 "all"을 쓰세요. 검색어와 도구 호출이 바뀌어도 같은 등록을 재사용하고, 사용자 작업이 바뀌면 교체하세요.

활성화된 search·read·grep·루트 외 overview는 같은 작업 기준을 사용합니다. 루트 overview는 필터링하지 않습니다. Jev 생략은 파일 부재가 아닌 분류 결과입니다. 정확한 read 위치, view=source, include_seen=true도 활성화된 Jev 필터를 우회하지 않습니다. include_seen은 중복 전달만 제어합니다.
