Use to orient in unfamiliar code or to choose a monorepo workspace scope before acting. In a ready monorepo, `initial_instructions` already returns this root overview, so do not immediately repeat a no-path call. No path returns workspace scopes with file/symbol counts and their leading languages. Confirm scope for broad changes; for read-only location discovery with no chosen scope, locate the implementation with a repo-wide search or filename/exact-text lookup, then narrow. Do not guess the implementation layer from a folder name alone. Every scope it lists is valid: conventional workspaces such as `apps/api` and top-level source roots such as `api`, `app`, or `sdk`; unique basenames are accepted unless ambiguous. Passing a workspace scope narrows overview and sets that active scope for following `search` calls. A folder path narrows to that folder and lists its files' significant symbol names and kinds, without line ranges. A file path lists that file's significant symbols with exact line ranges. To get a symbol range before reading, run `overview`, then `read` that window. Not for locating a named symbol or concept — use `search`; `overview` orients, so don't call it repeatedly as a search substitute.

A selected subdirectory remains the search scope instead of expanding to its owning workspace. A selected file sets its parent directory as the search scope. `all` resets repo-wide search.
