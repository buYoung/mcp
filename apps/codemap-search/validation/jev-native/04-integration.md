# 04 — Native MCP/config handoff

- Config schema v24: `[analysis.jev]` keys and effective defaults: `overview_enabled=false`, `search_filter_enabled=false`, `model="jev-1.13.0"` (pinned), `api_key_env="TYPESAFE_API_KEY"` (name only), `timeout_ms=45000`, `max_in_flight_requests=3`, `request_spacing_ms=300`, `max_batch_bytes=80000`, `pool_idle_timeout_ms=30000`, `search_filter_min_unrelated_probability=0.70` (finite, `0.5 < p <= 1.0`). Repo > global > built-in per key; invalid keys warn and delegate. Both localized templates, canonical layout normalization, additive commented migration, docs and README are updated. Credentials are resolved from the host environment only for selected requests, never stored in generated configs.
- MCP schemas add optional string `task_query` independently to `overview`/`search`; non-strings reject with `-32602` before tool lifecycle. Blank/absent intent or missing key bypasses evaluation. Search still requires its own `query`, and overview path/file/query remain path aliases; no task intent is borrowed from a prior request. Root only activates #1; #2 uses only actual selected search detail and never invokes #1 implicitly. With both modes off, `read`/`find`/`grep` and all old call arguments are unchanged.
- Sample calls after enabling the relevant mode and supplying the configured key in the MCP process environment:
  - `{"name":"overview","arguments":{"task_query":"Locate the request authorization flow"}}`
  - `{"name":"search","arguments":{"query":"authorize request","task_query":"Locate the request authorization flow"}}`
- The existing current-thread MCP loop still handles requests sequentially; config/redaction scopes remain pinned across awaits. A shared `JevEvaluator`/HTTPS client is reused while the credential and pool/concurrency settings match, recreated on changes. Public `McpServer::new` is unchanged; `set_jev_evaluator(Arc<dyn Evaluator>)` is an explicit in-process embedding/offline-test injection route, not remotely selectable. No notifications receive responses and no protocol-level cancellation behavior was added. The reusable module does accept caller-owned cancellation.
- `content` and JSON-RPC errors remain in their existing envelopes. When configured, `_meta.jev` reports `outcome=applied|bypassed|fallback`, a non-sensitive reason, input/output tokens and HTTP/whole-stage time; evaluated root calls also carry `recommendation_status=matched|no_match|insufficient_evidence`, question/policy versions, and search carries the effective threshold. Missing intent/key returns zero usage without network. MCP applies redaction and the existing final response cap; a cap error records no delivered source.

Isolated injected MCP request test passed for both enabled adapters, 0.70/0.90, in-flight config pinning, no-match and malformed-answer fallback. `cargo check --manifest-path apps/codemap-search/Cargo.toml` and `--all-targets` passed.
