# 01 — Rust Jev runtime handoff

- API: `codemap_search::jev::{Evaluator, JevEvaluator, EvaluationRequest, Evaluation, Question, Answer, Policy, Failure, Transport, HttpsTransport}` in `src/jev/mod.rs`. `Evaluator::evaluate` is async, takes an explicit `task_query`, JSON `state`, named `questions`, per-call `Policy` and optional caller-owned `tokio::sync::watch::Receiver<bool>` cancellation. No MCP, index, parser or global config dependency. `Transport` supplies an offline injection boundary; `set_jev_evaluator` is the embedding/MCP test route, not an MCP argument.
- Wire shape: `POST https://api.typesafe.ai/v1/systemone` with `model=jev-1.13.0`, structured `state={task_query,evidence}`, keyed `questions` (`score` ordered 2–10 criteria, `choice` keyed 2–255 criteria, `noul` optional true/false criteria). Structured instructions are supported. Typed answers retain Score value/legend/distribution/confidence, Choice key/distribution/confidence, or Noul probability **without** a confidence requirement. Model, exact ID set, types, probability keys/ranges/sum (±0.03), Score weighted result (±0.06), and usage are checked. Local `jev-batch-N` identities identify completed batches; they are not model instructions.
- Initial policy: 80,000 encoded bytes per request, at most 3 in-flight requests, 300ms start spacing, 45,000ms whole-call deadline including queue and HTTP, 30,000ms idle pool lifetime, no automatic POST retry or redirect. Per-call settings may shorten the deadline. Greedy batches share only named state, each candidate carries its own evidence, and failures do not return incomplete answers as a complete result. `Failure` has a non-sensitive kind, completed batch count, completed usage, whole elapsed and completed HTTP elapsed; in-progress failed HTTP time remains part of whole elapsed only.
- Token bound: Jev 1.13 documents **64k tokens** for state plus all questions and **32k tokens** for state plus longest question. No provider tokenizer is bundled. This implementation conservatively applies UTF-8 JSON byte ceilings of 64 KiB and 32 KiB in addition to the 80,000-byte envelope; these are not actual token counts and can reject valid larger inputs. Provider 422/context failures remain explicit; no silent truncation. Choice/Score confidence is concentration, not truth.
- Dependency: `reqwest 0.12.28`, default TLS disabled, `rustls-tls`/JSON enabled; builder uses `pool_idle_timeout`, `.retry(never())` and no redirects. Observed toolchain: `rustc 1.98.1`; release workflow uses stable Rust for Linux GNU/musl, macOS and Windows. `cargo tree -i openssl` did not find `openssl` in the current target tree. Cross-target build and real idle TCP/TLS reuse were **not run**.
- Verification from repository root: `cargo test --manifest-path apps/codemap-search/Cargo.toml --lib jev::tests` passed 9 runtime cases (mixed types, no Noul confidence, criteria boundaries, invalid/incomplete answers, provider error, 32 KiB and 64 KiB packing, spacing deadline, cancellation, mock transport reuse); `cargo check --manifest-path apps/codemap-search/Cargo.toml --example jev_decisions` passed; `cargo run --manifest-path apps/codemap-search/Cargo.toml --example jev_decisions -- --mock` passed with Score=2.0, Choice=keep, Noul=0.9, usage 42/8. No key or network was used. `--live` remains an explicit operator-only option, unrun.
- Historical PoC files under `apps/codemap-search/experiments/jev-playground/checkpoint-poc/` were **not present** in this checkout; contract was checked against the official TypeSafe API/model/state references and the provided briefs, not source-level PoC parity. No branch/worktree inspection was performed.
