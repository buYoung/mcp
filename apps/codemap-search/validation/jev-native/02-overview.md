# 02 — Root overview recommendation handoff

- `overview::run(ctx)` remains synchronous and returns its original text. `overview::prepare(ctx) -> PreparedOverview {text,files,snapshot_id,is_eligible}` captures the rendered base and every eligible indexed root file from **one** `published_snapshot`; folder/file/llms-txt, warming, stale/dead and empty paths do not evaluate. The preparation owns a copy across awaits; workspace aliases and active-scope updates remain in the MCP caller.
- `overview::jev::recommend(prepared, task_query, &dyn Evaluator, Policy, output_cap)` is an independently callable async adapter. It projects presentation-redacted path, docstrings, declarations, kinds, owners and inclusive ranges. Every file, including a symbol-free one, produces at least one fragment; symbols are chunked in groups of 20 without BM25 prefiltering. A single Score 0–3 per fragment uses described levels; a file qualifies only if **any** fragment has P(2)+P(3) > P(0)+P(1). Qualification precedes the maximum-fragment-score/path ordering and 24-file limit. An equal mass is uncertain. An all-tangential result returns `no_match`; a tie or no usable indexed evidence returns `insufficient_evidence`; neither claims source absence.
- A dependent Choice stage runs only for selected files, classifies each indexed declaration into one representative role (`implementation`, `support`, `caller`, `consumer`, `unrelated`), and shows at most two supported roles/file. Files without supported declarations remain visible. Output includes path, kind, exact inclusive range, bounded indexed doc and possible indexed call/caller hints, plus a JSON `read` window limited to 180 lines. Hints are not proof of execution. `QUESTION_VERSION=overview-fragment-v1/role-v1`; `POLICY_VERSION=overview-qualification-v1-experimental`.
- Result retains raw Score and Choice `Evaluation`s, usage, model via those evaluations, snapshot identity, status, fallback reason and separate completed HTTP/whole elapsed time. Input, incomplete score/role stage, deadline and insufficient addition space fall back to the base overview; zero-match retains it plus bounded search/read/grep/find guidance. MCP `_meta.jev` reports outcome and recommendation status; its normal `content` envelope and final response cap remain in place.
- Checks (repo root): `cargo test --manifest-path apps/codemap-search/Cargo.toml --lib tools::overview` passed 4 cases including 30 candidates with a qualifying file below the first 24, no-match/tie without a role call, path/range/read mapping, and small-budget fallback. `cargo check --manifest-path apps/codemap-search/Cargo.toml` passed. Isolated `mcp::jev_tests::test_jev_mcp_native_injected_paths` passed with a populated Rust/TypeScript snapshot, matched recommendation and zero-match outcome. A real refresh racing an API response was not exercised; owned preparation and snapshot identity prevent mixing within this adapter. Provider quality/calibration untested.
