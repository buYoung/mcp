# 03 — Structured search filtering handoff

- Preparation is in `search::run_inner_with_metadata`, `grouped::FileOutput::push_source_segment`, and `render::render_anchored_symbols`. Only when `search_filter_enabled` **and** a nonblank `task_query` are supplied, selected file/declaration/source blocks are recorded as `SearchEvidence` before MCP dispatch. Each has its file, exact indexed symbol identity, typed block and byte range, displayed/redacted body, bounded displayed context, complete/partial flag, and conservative protection. Search rank/order, path-only tail, event-key branch and source-reading window are unchanged. Normal default-off calls do not capture an extra evidence copy.
- `search::jev::filter(output, task_query, search_arguments, &dyn Evaluator, Policy, threshold, output_cap)` asks `QUESTION_VERSION=search-unrelated-noul-v1` per complete bounded displayed body. Named shared state contains `search_query` and selected search arguments; the instruction includes the declaration identity, exact displayed source and context. It asks whether the body is **unrelated** to `task_query`; false includes direct/supporting/contradicting evidence. No separate confidence is requested. Bodies over 8,000 bytes, partial/missing source, unknown kinds, containers/constants, nested declarations, and connected or ambiguous call sites are retained. Protection uses indexed relationships of the already selected files, including same-name cross-file calls, only to *keep* evidence; no additional source is fetched.
- `retention(evidence, raw_answers, threshold)` is replayable without inference. Finite `0.5 < threshold <= 1.0`, default 0.70; omit only unprotected complete bodies with Noul >= threshold, retain other/unknown evidence. `POLICY_VERSION=search-retention-v1-experimental`. Fake responses with missing/invalid IDs or types and runtime failures restore the complete base output. The 0.70 Noul policy has **not** been calibrated; the PoC's older Choice result is not evidence for it.
- Rendering/accounting: the Rust renderer records whole source segments and a typed per-file `FileOutput` render plan. The base Markdown is held separately for whole-call fallback. After Noul/policy, only exact original **per-file source blocks** are replaced in that plan; `FileOutput::write_primary` serializes the retained Markdown once, and only relationship blocks already selected by the base renderer are reinserted at recomputed typed section positions. No final Markdown heading parsing, fence regex, arbitrary text rewriting or source generation is used. All declaration headings/ranges and separate file headings remain. If the final output exceeds the search cap it restores the base text. Delivered-source observations are recomputed from retained source/literal segments after omission, and final MCP cap errors clear observations.
- Checks: `cargo test --manifest-path apps/codemap-search/Cargo.toml --lib tools::search` passed 3 policy/boundary cases: 0/0.50/0.69/0.70/0.71/1.00, threshold replay 0.80 at 0.70 vs 0.90, protected second file, typed relationship insertion and incomplete evidence. Isolated MCP test passed on selected real Rust callable, nested TypeScript method and Rust constant with 0.70/0.90 reload, fallback and post-filter source observation; default-off search e2e cases passed in the 199-case suite excluding branch-switch watcher tests. Per-line exact-source identity for every language/byte-cap configuration and in-flight post-mask byte accounting were not independently measured.
