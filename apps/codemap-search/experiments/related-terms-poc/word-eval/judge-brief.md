# 사전 응답이 코드베이스의 쓰임과 얼마나 맞는지 판정하기

gin(Go 웹 프레임워크) 코드에서 쓰는 단어마다, 개발 용어 사전에 그 단어를 넣었을 때 나온 응답을 받습니다.
사전 응답이 **gin에서 그 단어가 쓰인 뜻**과 얼마나 맞는지 판정해 주세요.

## 입력 항목
- `word`: gin 코드에서 나온 단어·문구
- `gin_meaning`: gin에서의 뜻(`fields` 분야, `senses` 뜻 설명, `expansions` 약어의 원래 말)
- `gin_usage`: 그 단어가 들어간 식별자와 코드 줄 예시
- `dictionary_output`: 사전 응답 원문
  - `# 관련어 N개`: 응답에 나온 관련어 수
  - `입력 해석`: 사전이 입력을 어떻게 읽었는지. `→ a + b`는 사전이 문구를 단어별로 나눠 찾았다는 뜻, `사전에 없음`은 못 찾았다는 뜻
  - `## 뜻 미배정 직접 관계어`: 뜻에 묶이지 않은 관련어(주로 같은 단어의 다른 표기)
  - `## <분야> — <주제>`: 사전이 가진 뜻 하나. 그 아래 `직접 관계어`, `가까운 연관어`, `같은 주제` 순으로 관련어가 나옴

## 판정할 것
1. `sense_result` — 사전 응답에 gin의 뜻과 맞는 뜻(`## <분야> — <주제>` 묶음)이 있는가
   - `match`: gin에서의 뜻과 같은 뜻의 묶음이 있음
   - `partial`: 같은 뜻의 묶음은 없지만, 가까운 뜻(더 넓거나 좁은 뜻, 인접 개념)의 묶음이 있거나 뜻 미배정 관계어에만 맞는 단어가 있음
   - `none`: 관련어는 나왔지만 gin의 뜻과 맞는 묶음이 없음
   - `no_result`: 관련어가 0개
2. `matched_headings`: `match`·`partial` 근거가 된 묶음 제목(`## ` 뒤 글자 그대로). 없으면 빈 배열
3. `helpful_words`: 응답에 나온 관련어 가운데, gin에서의 그 뜻을 이해하거나 gin 코드에서 관련 부분을 찾아갈 때 도움이 되는 단어.
   응답에 적힌 글자 그대로 모두 적습니다. 개수를 줄이려고 고르지 말고, 도움이 되는 것은 빠짐없이 넣습니다.
   gin의 뜻과 상관없는 다른 뜻의 단어는 넣지 않습니다.
4. `note`: 판단이 애매했으면 이유를 짧게

## 작업 규칙
- 배정된 입력 파일만 읽습니다. 다른 파일·디렉터리는 열지 않습니다.
- 판정은 직접 합니다. 스크립트로 단어를 자동 매칭하거나 걸러 내지 않습니다(결과 파일을 쓰고 형식을 확인하는 스크립트는 괜찮습니다).
- 입력 항목을 하나도 빠뜨리지 않습니다.

## 결과 형식
JSON 배열 하나를 결과 파일에 씁니다. 입력 항목 하나당 한 항목, 입력 순서대로:
`{"id": "w0006", "word": "err", "sense_result": "match", "matched_headings": ["..."], "helpful_words": ["...", "..."], "note": null}`
마지막 답변에는 항목 수와 특히 애매했던 경우만 짧게 적습니다.
