# 코드 탐색 벤치마크 결과

한국어 | [English](./benchmarks.md)

실제 대규모 저장소에서 코드 탐색 도구가 코딩 에이전트의 답변 정확도와 토큰 비용에 어떤 차이를 내는지 확인하기 위해, `codemap-search 0.14.2`를 기본 도구 기준군(`rg 15.2.0`) 및 공개 MCP 코드 탐색 서버 4종과 **Grafana**(`24,115`개 추적 파일, TypeScript + Go)에서 비교 측정했습니다. 풀이 모델 `gpt-6.1-sol`(`medium`)과 도구·저장소 접근 없이 채점하는 블라인드 채점 모델 `gpt-6-astra`(`high`)를 사용해, 3개 에이전트 실행 환경마다 다단계 아키텍처 질문 3개를 3회씩(`9`개 답변, 행 인용 사실 `108`개) 평가했습니다.

## 한눈에 보는 결과

세 에이전트 환경(`pi direct`, `pi codemode`, `Codex code mode`)은 기본 보조 도구, 출력 길이 제한, 프롬프트·토큰 집계 방식이 서로 다르므로 나란히 적되 합산하지 않습니다(예: Codex는 매 턴 더 큰 개발자·코드 모드 프롬프트가 포함되어 총 캐시 입력 토큰이 더 높게 집계되며, `pi codemode`의 `zvec-grep 0.2.2`는 서버 중단 2건으로 답변 `7`개·사실 `84`개입니다).

### 지표 읽는 법

1. **충족 (내용 맞음 + 인용 입증, 주 정확도 지표)**: 답변마다 `12`개 사실(9개 답변 합계 `108`개)을 평가합니다. 설명 내용이 맞고(`correct=true`) **동시에** 답변에 적힌 `path:시작-끝` 행 범위가 그 설명을 실제 입증(`supported=true`)해야만 **충족**으로 인정합니다. `rg 15.2.0`을 포함한 모든 비교군에 같은 행 범위 인용 지시를 주었습니다.
2. **Core (`63`) vs Extended (`45`) 및 Core 완결 (7/7)**: 문항마다 필수 종단간 연결을 묻는 **Core** 사실 `7`개와 부가 분기·설정 조건을 묻는 **Extended** 사실 `5`개가 있습니다. **Core 완결 (7/7)**은 핵심 사실 7개를 하나도 빠짐없이 모두 충족한 답변 수입니다.
3. **내용 맞음, 내용 맞음·인용 부족, 오답·누락**: **내용 맞음·인용 부족**은 모델의 설명 자체는 맞았지만 인용한 행 번호 범위가 그 주장을 뒷받침하지 못한 건수입니다(`correct=true, supported=false`). **오답·누락**은 `전체 평가 사실 수 − 내용 맞음`(`108 − 내용 맞음`, `n = 7`에서는 `84 − 내용 맞음`)이므로 `충족 + 내용 맞음·인용 부족 + 오답·누락 = 전체 평가 사실 수`가 됩니다(예: `96 + 2 + 10 = 108`).
4. **총 토큰 vs 비캐시 토큰**: 다중 턴 에이전트는 매 턴 이전 대화를 다시 전달하므로 입력의 `~86–94%`가 프롬프트 캐시에서 읽힙니다. **총 토큰**은 캐시 포함 전체 입력+출력 토큰 평균이며, **비캐시 토큰**은 캐시에 적중하지 않은 신규 입력+출력 토큰 평균입니다. `Codex` 총 토큰이 `pi`보다 `~1.4–1.9×` 높은 주된 이유는 `Codex`가 매 턴 더 큰 시스템·도구·코드 모드 프롬프트(예: `codemap-search` 첫 턴 입력 토큰 `9,748` 대 `pi direct` `5,118`, `pi codemode` `4,338`)를 포함해 매 턴 캐시로 다시 전달하기 때문입니다.
5. **기본·보조 도구 호출**: 모든 MCP 비교군은 같은 지시문으로 MCP 도구를 우선 쓰고 불가능한 작업만 내장 도구·셸을 쓰도록 안내했습니다. `0.0`은 에이전트가 내장 도구로 물러서지 않고 MCP 도구만으로 전체 풀이를 마쳤음을 뜻합니다(`codemap-search 0.14.2`는 `read`·`grep`·`find`를 MCP 서버 안에 내장). MCP 서버가 없는 `rg 15.2.0` 기준군에서는 내장 파일·검색 도구나 읽기 전용 셸 호출 전체를 뜻합니다.
6. **통계 검정(`p`)과 토큰 비율**: 쌍별 `p` 값은 문항 층화 정확 순열 검정 결과입니다(외부 MCP 24개 비교·전체 27개 행에 다중 비교 보정 없음, 기준 `p < 0.05`). **양측 `p`**는 두 도구가 어느 방향이든 다른지 검정하고, **단측 `p`**는 앞 도구(`A − B`의 `A`)가 뒤 도구(`B`)보다 답변당 충족 사실이 더 많은지 검정하므로 음수 차이 행에서는 `1.0`에 가깝게 나옵니다. 환경·도구당 답변 `9`개 표본에서는 답변당 약 `1.0`개 안팎의 차이부터 통계적으로 갈리며 `0.3–0.8` 차이는 시행 간 변동 범위로 봅니다. 토큰 비율(`×1.71`, `×0.55`)은 앞 도구의 평균 토큰을 뒤 도구의 평균 토큰으로 나눈 값입니다.

## 세부 도구 호출·인용·출력 잘림

- **전달(Dispatched)·거절(Rejected)·오류(Errors)**: `총 호출 = 전달 호출 + 거절`입니다(`답변당 총 호출`·`답변당 전달 호출`은 답변당 평균, `거절 합계`·`오류 합계`는 해당 셀의 전체 합계). `거절`은 `.git` 대상 검색이나 소스 루트 밖 경로 등 읽기 전용 경로 샌드박스 규칙이 실행 전에 막은 호출 수입니다. `오류 ⊂ 전달`은 실제 전달된 호출 중 오류를 반환한 횟수입니다(없는 경로 지정이나 검색 실패 등).
- **보조 `read` (`Graphify 0.9.95`) 대 `zvec-grep 0.2.2`**: `Graphify` 자체 도구 7종이 원문 본문 없이 그래프 엔티티와 위치만 돌려주므로 하네스가 읽기 전용 MCP 보조 `read` 도구를 붙였습니다. 반면 `zvec-grep 0.2.2`는 `zvec_grep_search`가 제한된 원문 발췌를 함께 반환하므로 보조 `read`를 붙이지 않았고, 더 넓은 파일 확인에는 내장 도구나 셸을 사용했습니다.
- **클라이언트 출력 한도·스크립트 잘림·어댑터 잘림**: `기본·CLI 한도 도달 (답변 수)`는 클라이언트 출력 상한에 걸린 횟수입니다(`pi`에서는 내장 `read` `2,000`줄/`50 KiB`, `grep` `100`건, `find` `1,000`건, `ls` `500`건; `Codex code mode`에서는 셸 `exec_command`와 `// @exec: {"max_output_tokens": ...}` 지정이 없을 때 기본 `10,000`토큰 상한이 적용되는 `exec` 코드 모드 셀 양쪽에서 `Codex CLI 0.164.0`이 낸 `Warning: truncated output` 횟수). `스크립트 잘림`(`pi codemode`)은 `codemode` 확장이 기본 `10,000`토큰 상한으로 스크립트 출력을 자른 횟수이며, `어댑터 잘림`(`pi`)은 `@buyong/pi-mcp-adapter 0.1.2`가 직접 MCP 응답을 자른 횟수입니다(기본 `20 KiB`, `codemap-search 0.14.2`는 `_meta["pi/maxOutputBytes"]`로 `100,000`바이트 지정).
- **인용 집계 기준**: 유효한 `160`개 슬롯 전체의 정규화된 검토 인용 색인에서 직접 재집계했습니다. `범위 인용`은 여러 줄 `path:시작-끝`(`end > start`) 인용, `한 줄 인용`은 1줄 인용(`path:행` 또는 `start == end`), `테스트·생성 인용`은 테스트 또는 생성 파일을 1건 이상 인용한 답변 수입니다.

## 벤치마크를 통해 반영된 변경

- **클라이언트 한도 부근의 압축된 순위 `search` 출력 (`e727d20c6`)**: 순위 `search` 결과가 파일별 요약과 일치 행 미리보기를 제공하고, 설정된 클라이언트 출력 한도 부근에서는 응답 중간을 자르는 대신 낮은 우선순위 함수 본문을 정확한 `read` 범위로 대체합니다(`codemap-search` 답변 `27`건 전체에서 클라이언트·기본·어댑터 출력 한도 도달 `0`회).
- **행 범위 인용 및 직접 구현 코드 우선 지침 (`87e36d849`, `f33203c88`, `a7c083ae6`)**: 서버 지침이 근거를 뒷받침 줄을 덮는 `path:시작-끝` 행 범위로 인용하고, 요청이 테스트·생성 코드에 관한 것이 아니면 테스트·생성 파일 대신 직접 작성된 구현을 추적·인용하도록 안내합니다(테스트·생성 파일 인용 답변 `0/27`건 대 비교 도구 `2–9/9`건; 이 지침만의 단독 인과 효과는 이번 측정에서 분리하지 않았습니다).
- **`_meta["pi/maxOutputBytes"]` 전달 메타데이터 (`0.14.2`)**: 모든 도구가 `tools/list`에 `output.client.pi_max_bytes`(기본 `100,000`바이트)를 `_meta["pi/maxOutputBytes"]`로 알리므로 `@buyong/pi-mcp-adapter`가 별도 `mcp.json` 설정 없이 기본 `20 KiB`보다 먼저 `codemap-search` 전달 한도를 적용합니다(어댑터 잘림 `0`회).

`gpt-6.1-sol`에서는 `rg 15.2.0` 대비 정확도 우위(`+1.00`~`+1.11`개)에도 총 토큰 `1.54×`~`1.71×`(비캐시 `1.27×`~`1.45×`)가 들었으며, `rg` 대비 GPT 토큰 오버헤드를 줄이는 문제는 미해결 트레이드오프로 남아 있습니다.

## 해석 범위와 재현 참고 사항

- **표본 크기와 미보정 `p` 값**: 환경·도구당 답변 `9`개(`pi codemode`의 `zvec-grep 0.2.2`는 `7`개)이므로 정확 순열 검정이 가려내는 차이는 대체로 답변당 `1`개 안팎이며, `0.3–0.8` 차이는 이 표본에서 판정을 유보합니다. 보고한 `p` 값은 외부 MCP 비교 `24`개(전체 쌍별 비교 `27`개)에 대해 다중 비교 보정을 하지 않았습니다.
- **단일 저장소·문항 3개 한계**: 단일 저장소(`Grafana`)의 문항 `3`개만 측정했으며, `alertmanager-config-autosync`에서는 거의 모든 도구가 `28–30/36`(`CodeGraph 1.6.2` `pi direct`만 `24/36`)으로 수렴해 도구 간 차이 대부분이 `scope-annotation-filter`에서 나왔습니다.
- **단일 풀이 모델**: 이번 측정은 `gpt-6.1-sol`(`medium`) 단일 모델 기준이며, 다른 모델 계열에서는 토큰 비율과 점수가 달라질 수 있습니다.
- **하드웨어·캐시·색인 상태·클라이언트 버전 의존성**: 수치는 측정 당시 호스트 하드웨어, 캐시 상태, 고정된 사전 색인 스냅샷, 고정 클라이언트/어댑터 버전(`pi 1.4.0`, `@buyong/pi-mcp-adapter 0.1.2`, `Codex CLI 0.164.0`) 기준이므로 조건이 바뀌면 토큰 수와 잘림 횟수가 달라질 수 있습니다.
- **같은 날 두 배치 실행**: `codemap-search 0.14.2`·`rg 15.2.0`과 비교 MCP 4종은 같은 호스트에서 같은 날 두 배치로 실행했으므로 wall-clock 소요 시간은 비교하지 않습니다.
- **재실행과 서버 중단**: 두 번째 배치의 `Codex` `scope-annotation-filter` 2회차 4슬롯은 호스트 시계 보정으로 하네스 시각 검사에 걸려 검사를 고친 뒤 재실행했습니다(`CodeGraph 1.6.2` `10/12`, `Graphify 0.9.95` `11/12`, `zvec-grep 0.2.2` `10/12`, `codebase-memory-mcp 0.12.1` `8/12`). `pi codemode` `zvec-grep 0.2.2` 2회는 서버 `SIGSEGV`로 종료되었습니다.
- **일시적인 동시 실행 정리 오류**: `pi` `codebase-memory-mcp 0.12.1` 답변 2건(`9/12`, `10/12`)은 다른 동시 실행의 공용 임시 상태 정리 작업 때문에 도구 호출이 1회씩 실패했습니다. 두 건을 빼고 계산해도 `pi direct` `78/96`(`+0.92`, `p = 0.0350`), `pi codemode` `74/96`(`+1.53`, `p = 0.0025`)로 결론은 같습니다.
