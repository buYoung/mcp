# 탐색 출력 계약

`read`, 내용 조회 방식의 `grep`, `search`가 제공하는 선언·관계·원문과 각 보기의 차이를 설명한다. 관계는 지원하는 정적 근거 범위 안에서만 표시하며 실제 실행이나 이벤트 전달을 증명하지 않는다.

## 제공하는 정보

| 항목 | 동작 |
| --- | --- |
| 선언과 소속 멤버 | 함수·타입·impl 등의 선언별 구획과 멤버 계층을 표시한다. |
| 직접 호출 관계 | 호출자·호출 대상과 정의 위치, 해소하지 못한 호출 대상을 표시한다. |
| 참조 상수 | 지원하는 소스 근거가 있는 상수 정의·값을 제공한다. |
| 구현 관계 | 지원하는 타입·메서드의 선언·구현 연결을 제공한다. |
| 이벤트 지도 | 이벤트 탐색 설정과 조회 근거에 따라 발행·구독·핸들러 후보를 제공한다. |
| 소스 경로 | 저장과 소비를 연결하는 조건부 `Source routes`를 제공한다. 콜백·인자 전달·데이터 소비의 구분과 한계는 [소스 경로 계약](source-routes.ko.md)을 따른다. |
| 검색의 정적 컬렉션 관계 | `Related write/read paths`로 관련 쓰기·읽기 위치를 제공한다. |
| 원문 | 지정한 줄 범위·문맥 행·함수 확장과 출력 상한에 맞춰 제공한다. |

실제 원문 잘림, 색인 제외·미지원 형식, 오래된 색인과 호출 대상 불확실성은 안내한다. 관계가 표시되지 않았다는 사실만으로 해당 동작이 없다고 판단하지 않는다.

## Read·grep 보기

| `view` | 반환 내용 |
| --- | --- |
| `full` (기본값) | 원문·선언·관계 |
| `source` | 줄 번호가 있는 실제 원문; 관계 조회 생략 |
| `definitions` | 선언 정보 |
| `relations` | 직접 호출·상수·구현·이벤트 관계와 소스 경로 |

`grep`의 `files_with_matches`와 `count`는 경로 목록과 개수 모드이며 선언·관계 보기를 사용하지 않는다. 인자 조합과 페이지 단위는 [요청별 출력 제어](configuration.ko.md#readgrep-요청별-출력-제어)를 따른다. `debug`는 호환 인수이며 분석이나 출력에 영향을 주지 않는다.

기본 상세 결과는 `# codemap-search` 아래에서 `## 1. src/user.ts`처럼 파일을 묶는다. 각 파일에는 `### fn active`처럼 선언 종류와 이름으로 제목을 만들고 마지막에 `### results`를 한 번 배치한다. 메서드는 소속 impl/class 아래에 둔다.

`grep` 본문은 파일 제목과 중복되는 경로 접두사를 생략한다. 원문에 들어 있는 경로 문자열과 다른 파일을 가리키는 관계 위치는 보존한다. `view=source`는 파일별 상세 문맥 없이 읽을 수 있는 원문 형식이다.

## 범위·최신성·필터

- `read`와 `grep`은 디스크의 현재 소스를 읽는다. 색인 문맥이 최근 편집을 반영하지 못하면 그 한계를 안내한다.
- `read`의 `expand=callable`과 `grep`의 기본 함수 확장은 포함된 함수 범위를 사용한다. 큰 함수는 안내된 범위에서 `expand=none`으로 나눠 읽는다.
- 폴더 `overview`는 파일 목록, 소스 기반 시그니처와 필드·메서드 계층을 제공한다. 파일 `overview`는 색인된 선언 위치를 제공한다.
- `search`는 순위가 있는 상세 결과와 제한된 나머지 목록을 제공한다. 부분 결과는 완전한 원문 근거가 아니다.
- [Jev 본문 필터](configuration.ko.md#선택적-jev-판단-단계)를 켜면 `source` 보기에서도 본문을 생략할 수 있다. 생략 안내의 범위를 필터 없이 읽으려면 `output.jev.scope`에서 `"read"`를 빼거나 `output.jev.enabled=false`로 끈다.

## MCP 조회 예시

다음은 이 앱을 작업공간으로 연결한 MCP 클라이언트의 요청이다. 먼저 grep으로 현재 선언 위치를 찾고, 반환된 행을 read의 `offset`으로 사용한다. Jev를 켰다면 [작업 등록 순서](configuration.ko.md#작업-등록과-도구-순서)를 먼저 따른다.

```json
{"name":"grep","arguments":{"path":"src/config.rs","pattern":"pub fn load","view":"source","head_limit":1}}
```

같은 `file_path`, `offset`, `limit`으로 `view`를 `full`, `source`, `definitions`, `relations`로 바꾸면 소스와 문맥을 구분할 수 있다. `unresolved=count`는 미해결 이름 목록 대신 개수만 표시한다.
