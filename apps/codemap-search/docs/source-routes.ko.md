# 소스 경로 탐색 계약

`codemap-search`는 저장 위치와 그 값을 소비하는 위치를 `Source routes`로 연결한다. 라이브러리 이름이나 이벤트 API 목록에 의존하지 않고, 색인에 포함된 소스의 객체·필드·컬렉션·키·함수 인자·반환값을 분석한다. 기존 규칙 기반 `Event relationships`는 함께 유지한다.

이 연결은 **조건부 소스 후보**다. 같은 실행 인스턴스인지, 등록 뒤 호출하는지, 실제 이벤트가 전달되는지는 증명하지 않는다. 콜백을 인자로 넘긴 사실만으로 최종 콜백 실행을 표시하지 않으며, 이벤트 여부도 자동 분류하지 않는다.

## 조회와 설정

별도 API나 설정 키를 추가하지 않는다. `[output.event_navigation].is_enabled`의 기본값은 `true`다.

| 요청·설정 | 소스 경로 동작 |
| --- | --- |
| `read`, content `grep`의 기본 `full` 또는 `relations` | 반환한 선언·줄에 저장, 소비, 중간 근거가 있으면 자동 표시한다. |
| 일반 `search` | 실제 상세 결과에 포함된 근거에 맞춰 표시한다. 순위 결과와 원문을 먼저 보존하고 남은 출력 공간을 쓴다. |
| `include_events=false` | 이번 요청의 이벤트 지도와 소스 경로를 함께 생략한다. |
| `view=source`, `view=definitions`, grep 파일·개수 모드 | 관계 조회를 생략한다. |
| `[output.event_navigation].is_enabled=false` | 이벤트와 소스 경로 분석·출력을 끈다. |
| `use_builtin_rules=false`, `rules=[]` | 규칙 기반 이벤트만 제어한다. 소스 경로는 계속 동작한다. |
| `search`의 `event_key` | 기존 규칙 기반 이벤트 키 조회다. 범용 소스 경로를 이벤트 키로 분류하지 않는다. |

`caller_context`, 작업공간 범위, 테스트·디렉터리·Git 제외 규칙과 기존 원문 출력 계약을 유지한다. `debug=true`로 분석 범위를 넓히지 않는다. 제거한 `Value relationships` 및 그 요청 시점 평가기는 다시 사용하지 않는다.

다음 TypeScript 코드는 `register`의 저장과 `dispatch`의 콜백 소비를 잇는 예다.

```typescript
const routes = new Map<string, () => void>();
export function register(handler: () => void) { routes.set('tick', handler); }
export function dispatch() { routes.get('tick')?.(); }
```

해당 파일의 2행이나 3행을 읽으면 저장 → 소비 위치와 조건을 볼 수 있다. 이 출력은 `register`와 `dispatch`가 실제 호출됐거나 같은 프로세스에서 그 순서대로 실행됐다는 뜻이 아니다. 객체에 메서드를 직접 선언하고 바로 호출하는 경우는 그 선언만으로 콜백 등록 경로를 만들지 않는다.

## 관계 종류

| 출력 종류 | 확인한 소스 관계 |
| --- | --- |
| `callback invocation candidate` | 저장 슬롯과 호출 대상이 조건부로 이어진다. |
| `stored object method candidate` | 저장된 객체의 메서드 소비 후보가 이어진다. |
| `argument transfer (consumer unproven)` | 저장한 값을 다른 호출의 인자로 넘겼다. 그 호출의 실제 소비는 미해결이다. |
| `stored value return` | 저장한 값을 반환한다. |
| `stored object write` / `stored object read` | 저장된 객체의 필드 쓰기·읽기로 이어진다. |
| `stored lookup key` | 저장한 값을 조회 키로 소비한다. |

내부 관계는 `certainty=conditional_source_relation`, `concrete_instance_proven=false`, `event_classification=not_inferred`를 유지한다. 출력에는 파일·줄 번호와 조건 이름, 제한된 중간 경로를 표시한다. 여러 쓰기나 제거 근거가 있으면 순서·제거에 대한 불확실성이 남는다. 출력에 경로가 없다는 사실만으로 관계가 없다고 결론 내릴 수 없다.

## 언어와 분석 범위

대상은 JavaScript, TypeScript, Go, Rust, Java, Kotlin, Groovy, Scala, C#, C, C++, Swift, Dart, PHP, Python, Ruby, Lua, Assembly의 18개 개발 언어다. 문서·마크업·셸·인프라 설정 언어를 이 목록에 포함하지 않는다. `Cargo.toml`, `package.json` 등은 기존에 색인된 모듈·패키지 근거로만 사용한다.

공통 저장·소비 모델에 언어별 구문 해석을 연결한다. 필드·컬렉션, 함수 참조·클로저, 지원하는 인자·반환·별칭·타입·import 경로를 분석한다. Assembly는 지원하는 레이블·테이블·레지스터 이동·간접 호출 패턴을 분석한다. 18개 언어 지원은 모든 문법과 라이브러리 동작을 완전히 해석한다는 뜻이 아니다.

Rust의 일부 소스 매크로 템플릿, Scala의 일부 소스 매크로·암시적 선택, 생성기·콜백 조합은 제한된 소스 해석이며 필요한 조건을 남긴다. 프로시저 매크로, 빌드 스크립트, 대상 컴파일러, 언어 서버, Python, 분석 대상 프로그램을 제품 실행 중 호출하지 않는다. 보이지 않는 의존성을 내려받거나 제외 규칙을 우회하지 않는다. 실제 의존 구현까지 필요하면 해당 소스가 허용된 색인 입력에 있어야 한다.

Bevy의 Observer, SystemId, glTF 등록부터 최종 콜백까지의 세 경로는 미해결로 유지한다. 보존한 인자·타입 변수·할당·`Option` 내부 값만으로 제네릭 ECS의 물리 저장소와 trait 호출까지 확정하지 않는다. 컴파일러 보조 입력은 제품의 전제 조건이 아니다.

## 색인, 신선도, 상한

분석은 색인 세대를 만드는 작업 스레드에서 실행한다. 요청 시점에는 저장한 후보를 선택하고 근거 파일이 현재 소스와 같은지 확인한다. 엔드포인트뿐 아니라 import·재내보내기 등 추적한 지원 파일이 변경·삭제·제외되면 갱신 전 연결을 숨긴다. 모든 의존 근거를 제한 안에서 확인할 수 없는 관계도 표시하지 않는다.

테스트 제외 영역은 분석 전에 가리고 조회 시에도 확인한다. 테스트 포함 설정, Rust 분석 대상 OS, 이벤트 설정·제외 정책이 바뀌면 새 세대를 요청한다. Rust 활성 조건을 확정할 수 없으면 조건을 남기며, 비활성으로 확인한 지점은 숨긴다.

| 경계 | 상한 |
| --- | --- |
| 소스 입력 | 파일당 512 KiB, 색인 세대당 64 MiB·4,096파일 |
| 이벤트와 소스 경로의 공유 끝점 | 파일당 256개, 세대당 8,192개 |
| 요청의 공유 후보·출력 | 후보 512개, 끝점 128개 |
| 요청의 현재 소스 확인 | 128파일·4 MiB |
| 소스 AST 보존 | 파일당 131,072노드, 세대당 1,048,576노드, 깊이 256 |
| 요약 분석 | 4회, 함수당 256사실, 전체 40,000사실, 분석 작업 2,000,000회 |

관계 연결·콜백 치환·중간 경로에도 별도 제한이 있다. 입력 누락, 구문 오류, 분석·근거 확인·출력 제한은 가능한 출력 공간 안에서 안내한다. 제한에 걸린 부재를 음성 사례의 성공으로 세지 않는다. 요청마다 전체 작업공간을 다시 분석하지 않으며 기존 도구의 바이트 상한을 늘리지 않는다.

Effect `Stream.ts`를 포함하는 **확장 입력 검증 실행에만** 파일당 1 MiB를 허용한다. 이는 테스트 실행기의 명시적 옵션이며 제품 기본값이나 설정 옵션이 아니다. 제품은 512 KiB 초과 입력을 누락 사유와 함께 처리한다.

18개 언어의 소스를 보존하기 위해 색인 형식을 `v34-native-source-routes`로 변경했다. 이전 형식은 기존 자동 재생성 경로를 사용한다. 재시작 시 저장된 입력으로 소스 경로 스냅샷을 다시 만든다.

## 검증 근거와 남은 한계

완료 범위와 실행 결과는 [브리프셋](../../../docs/briefs/2026-09-16-briefset-source-routes.md) 및 [검증 기록](../../../docs/briefs/evidence/source-routes/verification.json)에 보존한다. 원래 PoC의 기대값·입력 잠금 파일은 변경하지 않는다. 제품 Rust 분석기로 고정된 입력을 다시 분석한 결과와 실제 MCP 조회 결과를 구분한다.

공개 저장소 소스의 관계 검증은 대상 애플리케이션 실행 검증이 아니다. 공개 구문 시나리오 26개, 실제 이벤트 전달·순서·수명·동시성, 보류한 Bevy 세 최종 경로는 실행 성공으로 보고하지 않는다. 성능 수치도 기록된 소스 집합과 실행 환경에서 관측한 값이며 전체 저장소에 대한 성능 보장은 아니다.
